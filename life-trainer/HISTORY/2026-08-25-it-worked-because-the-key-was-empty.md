# 잘 돌고 있어서 배선이 맞는 줄 알았다 — 키가 비어서였다

- **발견**: 네이버 검색 API 가 NAVER API HUB 로 이관돼 신규 발급이 닫혔다는 것을
  확인하다가, **우리 코드가 지금 왜 멀쩡한지**를 되짚었다.

- **증상**: 없었다. 그게 문제다. 한국어 검색이 잘 되고 있었다.

- **원인**: `_pick_provider` 는 한국어면 **여전히 네이버를 먼저** 골랐다.
  `naver_client_id` 가 비어 있어서 Serper 로 폴백하고 있었을 뿐이다.

  **누가 그 키를 채우는 순간 한국어 질의만 은퇴한 엔드포인트로 가서 401 이 난다.**
  영어 질의는 멀쩡하니 "검색이 고장났다"로도 안 보인다. 설정 한 칸이 함정이었다.

  깨진 가정: **"동작하니까 배선이 맞다."** 동작은 배선이 맞아서가 아니라
  **다른 경로가 비어 있어서** 나온 결과였다.

- **수정**: 고치지 않고 **지웠다.**
  `websearch.py` 의 `NAVER_ENDPOINT`·`_naver()`·`_clean()`·`_pick_provider()`,
  `config.py` 의 설정 키 2개, `cli.py doctor` 분기 2개, example.toml 항목.

  HUB 방식으로 되살리는 길은 열어 두지 않았다 — **Serper 하나로 충분한 것이
  2026-08-21 에 이미 결정**됐기 때문이다. 언어 판정(`is_korean`)만 남겨
  `_serper` 가 `gl=kr&hl=ko` 를 붙일지 정하는 데 쓴다.

- **방어**: `test_the_dead_naver_path_is_gone` — 함수도 상수도 설정 필드도
  **없다는 것**을 검사한다.

- **교훈**: **결정이 끝난 분기를 코드에 남겨 두면 그것이 곧 함정이다.**

  "혹시 나중에 쓸지도" 로 남긴 경로는 아무도 시험하지 않는다. 그리고 그 경로를
  깨우는 것은 대개 **설정 한 칸을 채우는 사람**이지 코드를 읽는 사람이 아니다.

  → 폴백이 있는 구조에서는 **주 경로가 실제로 도는지**를 따로 확인하라.
    "결과가 나온다"는 주 경로가 돈다는 뜻이 아니다.
