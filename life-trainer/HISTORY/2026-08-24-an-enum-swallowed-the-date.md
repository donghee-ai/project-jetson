# 안전하려고 건 제약이 날짜를 삼켰다

- **발견**: [`[id]` 를 받아주는 수정](2026-08-24-fixing-the-model-cost-more-than-accepting-what-it-sent.md)
  뒤에도 채점 1건이 계속 틀렸다. "어제" 를 말했는데 오늘에 적용됐다.

- **증상**: 같은 턴 안에서 두 툴이 다르게 답했다.

  ```
  get_plans → {"day": "2026-08-23"}   ← 자유 문자열. 정확
  slash     → {"day": "오늘"}         ← enum. 낱말 중에서 고르다 기본값으로
  ```

- **원인**: `slash` 툴의 `day` 를 **enum 으로 묶은 것이 나였다.** 새벽 경계(06:00)에
  모델이 날짜를 계산하면 이틀 뒤가 나오는 것을 막으려고 넣었다.

  깨진 가정: **"고를 수 있는 것을 줄이면 안전해진다."** 줄여 놓으니 모델이
  후보 낱말 중에서 고르다 기본값으로 흘렀다. **자유 문자열일 때 정확했던 것이
  제약을 걸자 부정확해졌다.**

  그리고 **그 위험은 하루 6시간이고 대가는 하루 종일이었다.**

- **수정**: enum 을 풀고 두 툴의 `day` 를 같은 모양으로 되돌렸다. **3/3.**
  실기기 확인 — `"어제 미팅 계획도 완료처리 해줘"` → 08-23 미팅 done ✓

- **방어**: 두 툴의 `day` 스키마가 같은 모양인지 보는 테스트.

- **교훈**: **제약을 걸 때는 그것이 막는 시간과 무너뜨리는 시간을 비교하라.**

  새벽 6시간의 오류를 막으려고 하루 종일의 정확도를 내줬다. 그리고 같은 값을
  다루는 툴이 둘인데 **한쪽에만 제약을 걸면 그 둘이 어긋난다** — 어긋난 쪽이
  조용히 기본값으로 흐른다.
