# 압축 설정이 사라진 컨텍스트를 기준으로 남아 있었다

- **발견**: 사용자가 Slack 에서 "어제 계획은 뭐였어?" 를 묻자
  **`Context overflow: prompt too large for the model.`** 이 그대로 나왔다.
  한 시간쯤 대화한 뒤였다.

- **증상**: 대화가 길어지면 어느 순간부터 **모든 질문이 영어 오류 문장**으로 답한다.
  사용자가 할 수 있는 일이 없다 — 그 문장이 권하는 `/reset` 은 우리 Slack 경로에
  없는 명령이다.

- **원인**: **압축 설정이 ctx 40,960 시절 값이었다.**

  ```
  keepRecentTokens  8000   ← 08-15 에 정함 (그때 ctx 40,960)
  reserveTokens     6000
  maxHistoryShare   0.7
  ```

  08-23 에 ctx 를 20,480 으로 줄이면서 **재계산했다고 적었지만**, 그 계산은
  `14,336 + 6,000 = 20,336 < 20,480` 이었다. **시스템 프롬프트가 빠져 있다.**

  ```
  시스템 프롬프트 5,326 + keepRecent 8,000 + reserve 6,000 = 19,326
  ctx 20,480 → 여유 1,154 토큰   ← 한 턴이면 넘친다
  ```

  같은 누락이 `main` 에이전트를 이미 죽여 놨고 그건
  [known-issues §10](../docs/known-issues.md) 에 적어 뒀는데, **우리 에이전트도
  같은 배를 타고 있다는 것을 그때 못 봤다.** `main` 은 프롬프트가 커서 즉시
  죽었고 우리는 작아서 한 시간 뒤에 죽었을 뿐, 원인은 하나다.

- **수정**: 둘 다 했다.

  1. **설정** — `keepRecent 3000 · reserve 3000 · share 0.6`. 여유 1,154 → 9,154
  2. **구조** — `agent/delegate.py` 가 세션을 회전시킨다.
     `MAX_TURNS_PER_SESSION 24` · `SESSION_IDLE_SEC 1800` · **오버플로를 만나면
     세션을 갈고 한 번 재시도**한다. 설정은 한계를 미룰 뿐이고, 히스토리가 계속
     자라면 언젠가 같은 자리에 닿는다.

  실측: 고친 뒤 같은 질문이 **15.2초에 정답**.

- **방어**: 회전 4종을 테스트로 고정했다. 다만 **"설정이 ctx 와 맞는지"를 검사하는
  것은 아직 없다** — `lt doctor` 가 볼 자리다.

- **교훈**: **공유 자원의 설정을 바꿀 때는 그 위에 올라탄 것들을 전부 다시 계산한다.**
  ctx 는 두 프로젝트가 나눠 쓰는 llama-server 의 설정이다. 08-23 의 계산은
  "히스토리 몫 + 예비 < ctx" 만 봤고, **시스템 프롬프트가 그 히스토리 몫 안에서
  나간다는 것**을 안 봤다.

  그리고 **한 곳에서 발견한 원인을 옆으로 밀어 보지 않았다.** `main` 이 같은
  이유로 죽은 것을 그날 아침에 적어 놓고도, 우리 에이전트를 같은 눈으로 안 봤다.
  기록을 남기는 것과 그 기록을 자기에게 적용하는 것은 다른 일이다.
