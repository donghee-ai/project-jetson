# "내일 계획 뭐 있어?" 에 오늘 블록을 통째로 베껴 답했다

- **발견**: 사용자가 "플래너도 RAG 로 처리하냐" 고 물어서 경로를 보여 주려고
  세 질문을 돌려 보다가 나왔다. 2회 재현.

- **증상**:

  ```
  Q 내일 계획 뭐 있어?
  A [오늘 YYYY-MM-DD 계획 — 사람이 세운 의도] 예시 일정 (미분류, 완료, 낮은 달성률)
  ```

  내일 계획이 DB 에 있었는데 오늘 것을 읊었고, **프롬프트 내부 라벨까지 그대로**
  나갔다. `내일 일정 알려줘` 로 물으면 `get_plans` 를 부르고 정답을 준다.

- **원인**: **"스키마·프롬프트에 적으면 모델이 지킨다"** 를 사실이라고 믿었다.
  질문의 "**계획**" 이 시스템 프롬프트 라벨의 "오늘 … **계획**" 과 겹치는 순간,
  8B 가 툴을 부르는 대신 **눈앞에 있는 계획처럼 생긴 것을 복사**한다.
  "일정" 으로 물으면 겹치지 않아 툴을 부른다 — 낱말 하나 차이다.

  같은 부류를 이 저장소가 다섯 번째로 겪었다(`required` 는 보장이 아니다 /
  검색 폴백 / 반복 답변 / `search_docs` 의 `period` 남용 / 이번).

- **수정**: 툴을 강제하지 않았다(`tool_choice="required"` 는 이미 데인 방법이다).
  대신 **물어본 날의 계획을 눈앞에 놓는다** — `context.referenced_day()` 가
  "내일·모레·어제·8월 24일·2026-08-25" 를 날짜로 풀어 그 날 계획을 턴 배경에 싣는다.
  그러면 베껴도 **맞는 것을 베낀다.** 비용은 턴당 +22토큰, 그것도 다른 날을 물었을 때만.
  "오늘" 은 일부러 안 잡는다(이미 시스템 프롬프트에 있다).
  계획이 없는 날이면 "등록된 계획 없음" 을 명시한다 — 빈손을 말 안 하면 오늘 것으로 메운다.

  안전망으로 `_has_scaffolding()` 이 라벨 유출을 잡으면 한 번 다시 생성하고,
  그래도 남으면 **그 줄을 통째로** 걷어낸다 — 라벨만 떼면 오늘 계획이 내일 답으로 둔갑한다.

- **방어**: `tests/test_llm_tools.py` 11건 — 날짜 해석 / 그 날 계획이 배경에 실린다 /
  없으면 "없음" 이라고 싣는다 / 오늘만 물으면 안 붙는다 / 뼈대 감지 /
  출처 표기 `[1](url)` 오탐 없음 / 뼈대는 줄 통째로 제거.

- **교훈**: **주입 블록의 라벨이 질문의 낱말과 겹치면 그 블록이 답으로 새어 나온다.**
  프롬프트에 붙이는 라벨을 고를 때 "사용자가 이 낱말로 질문할까?" 를 본다.
  그리고 이 저장소의 결론은 매번 같다 — **프롬프트로 안 되는 것은 구조로 막는다.**
  여기서 "구조" 는 툴 강제가 아니라 **필요한 데이터를 미리 눈앞에 놓는 것**이었다.
