# 아무도 안 부르는 마이그레이션 러너

> 2026-09-01 · `lifetrainer/db.py` · 프라이빗 모드 006 을 붙이다 라이브를 깼다

## 깨진 가정

**"마이그레이션 파일을 만들었으니 적용된다."**

아니다. `migrate()` 에는 **프로덕션 호출자가 한 개도 없었다.**

## 무슨 일이 있었나

프라이빗 모드가 `slot.private_sec` 컬럼을 쓰려고 마이그레이션 006 을 더했다.
테스트는 전부 통과했다 — 테스트는 `migrate()` 를 **직접 부르기** 때문이다.
그리고 10분마다 도는 롤업이 죽기 시작했다.

```
sqlite3.OperationalError: table slot has no column named private_sec
```

`lt init-db` 를 돌렸다. 이렇게 답했다:

```
스키마 적용 완료: .../data/lifetrainer.db (schema v6)
```

**거짓말이었다.** `SCHEMA_VERSION` 상수를 문자열에 끼워 출력했을 뿐이고,
실제로는 `init_db()` 만 불렀다. 확인해 보니:

```
slot.private_sec: False
적용 표식: ['002_day_boundary', '003_breakdown_device', '004_doc_embedding']
```

005 도 없다. **한 달 전에 만든 마이그레이션이 이 기기에 한 번도 안 돌았다.**
아무도 몰랐던 이유는 005 가 이 DB 에서 대상 0행이라 아무 증상이 없어서다.

## 왜 안 걸렸나

`init_db()` 의 `CREATE TABLE IF NOT EXISTS` 가 **새 DB 에서는 충분하다.**
그래서 테스트는 전부 통과한다 — 테스트 DB 는 항상 새것이다.
`ALTER TABLE` 이 필요한 것은 **오래된 DB 하나뿐**이고, 그게 라이브였다.

> *만들었다 ≠ 그게 불린다* ([CLAUDE.md §2](../../CLAUDE.md)). 같은 부류를 또 밟았다.

## 고친 뒤에 두 번째로 깨진 것

`open_db()` 가 `migrate()` 를 부르게 했더니 **웹 테스트 5개가 빈 격자를 뱉었다.**

새 DB 는 `schema.sql` 로 이미 최신인데 **마이그레이션 표식이 없었다.**
그래서 다음 `open_db` 가 그걸 "오래된 DB"로 보고 002·003 을 돌렸고,
그 둘은 *하루 경계가 바뀌었으니 재계산하라*는 뜻으로 `slot` 을 **비운다.**

```
새 DB 만들기 → 슬롯 넣기 → 다시 열기 → 슬롯 0개.  오류 없이, 조용히.
```

첫 수정이 만든 새 실패였다. 검사가 잡아서 5분 만에 알았다.

## 무엇을 바꿨나

| | 전 | 후 |
|---|---|---|
| `open_db()` | `init_db` 만 | `init_db` + `migrate` |
| `init_db()` | 스키마만 | 빈 파일이면 **표식을 찍는다**(baseline) |
| `lt init-db` 출력 | 상수 `v6` | **적용된 표식을 세서** 말한다 |
| 마이그레이션 목록 | `migrate()` 안의 if 블록 | `_MIGRATIONS` **한 곳** |

baseline 은 Alembic `stamp head`, Rails `db:schema:load` 와 같은 관례다 —
*빈 파일에 최신 스키마를 부었으면 마이그레이션은 이미 끝난 것이다.*

## 그 관례가 성립하는 조건 — 그래서 검사를 붙였다

baseline 은 **`schema.sql` 이 마이그레이션 뒤의 모양일 때만** 안전하다.
007 을 만들면서 `schema.sql` 을 안 고치면:

- 기존 DB → 마이그레이션이 컬럼을 더해 준다 ✅
- 새 DB → baseline 이 그걸 건너뛴다 → **컬럼 없이 "최신"으로 표시된다** ❌

어긋남이 **새 기기에서만** 터진다. 그래서 `test_schema_sql_은_마이그레이션이_더할_것을_이미_갖고_있다` 를 붙였다:
표식을 떼고 다시 돌려도 `PRAGMA table_info` 가 그대로여야 한다.

**언제 안 우나** — schema.sql 과 마이그레이션이 같은 모양이면 마이그레이션은
구조를 바꿀 게 없다. 둘이 어긋나는 순간에만 운다.

## 남은 것

`lt doctor` 는 아직 "밀린 마이그레이션이 있나"를 안 본다.
지금은 `open_db` 가 매번 적용하므로 밀릴 수가 없지만, 그건 **코드가 그렇다는 것**이지
검사가 있는 것은 아니다.
