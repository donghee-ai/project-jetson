# 게이트가 판정한 문자열과 실제로 나간 문자열이 달랐다

원래 이슈: `docs/issues/0001`

- **발견**: 사용자가 Serper 대시보드를 열었다가. 같은 질의 `어제 했지 오늘은?` 이
  30번 넘게 찍혀 있었고 **그렇게 물은 적이 없었다.**

- **증상**: 개인 발화가 서드파티 검색 API 로 나갔다. `gl=kr&hl=ko` 까지 붙어서.
  이 저장소의 대표 문장이 *"데이터는 기기 밖으로 나가지 않는다"* 인데 정면으로 어긋난다.

- **원인**: **게이트는 `user_text` 하나를 보고 판정하는데, 나가는 값은 그 뒤에 다시
  조립된다.**

  ```
  1턴  "어제 뭐 했지?"  →  게이트: web 안 걸림 ✅ (개인 질문 제외가 정확히 작동)
  2턴  "오늘은?"        →  게이트: web 걸림 ❌
                           ↓ converse._search_query() — 15자 미만이면
                             직전 질문의 낱말을 앞에 붙인다
                        →  "어제 했지 오늘은?"  →  Serper
  ```

  깨진 가정이 셋이다.

  **① "게이트를 통과한 말이 그대로 나간다."** 안 그렇다. 게이트가 본 적 없는
  문자열이 만들어져서 나간다. 그리고 그 문자열은 **게이트에 물리면 막히는 것**이었다.

  **② "짧은 후속 발화는 판정할 거리가 없다."** `오늘은?` 이 `\S+\s*(은|는)\s*\?`
  에 걸렸다. `게임 tft는?` 같은 되묻기를 잡으려던 패턴인데, 조사 하나로 끝나는
  한국어 후속 질문을 전부 삼켰다.

  **③ "뺄 낱말 목록으로 개인 정보를 거른다."** `_NOT_A_TERM` 에 `오늘` 은 있는데
  **`어제` 가 없었다.** 뺄 것을 세는 방식은 빠뜨리면 그대로 샌다.

  ★ 모듈 docstring 은 이 위험을 **이미 알고 있었다** — *"질의어에 개인 정보가 섞이지
  않게 길이를 `MAX_QUERY_CHARS` 로 자른다"*. **방어를 길이 축에 걸었는데 유출은
  내용 축이었다.** 개인 낱말이 질의어 *앞*에 붙어서 잘라도 남았다.

- **수정**: 세 겹.
  - `trigger.is_personal()` 을 공개하고, 맨몸 시간낱말 되묻기(`오늘은?`)를 개인 패턴에 추가.
    `롤체는?`·`게임 tft는?`·`오늘자 뉴스 뭐 있어?` 는 그대로 통과한다
  - `converse._context_terms()` 가 **그 턴 자체가 web 으로 판정된 경우에만** 낱말을 준다.
    "이 말이 나가도 되는가"는 게이트가 이미 답하고 있다
  - `websearch.search()` 가 **나가기 직전에** `is_personal()` 로 한 번 더 막는다.
    선주입·모델의 툴 호출·MCP 가 전부 이 함수로 합류하므로 **새 호출자가 생겨도
    못 빠져나간다**

- **방어**: `tests/test_websearch.py` 회귀 5개. 유출 재현 그대로 + **정상 경로 보존**
  (`롤체 tft는 뭐야?` 가 계속 조립되는지, 바깥 질의 3종이 안 막히는지).
  막느라 기능을 죽이는 것이 이 부류의 흔한 2차 사고다.

- **교훈**: **판정한 것과 보낸 것이 같은지 확인하라.**

  게이트는 정확했다. `_PERSONAL_PATTERNS` 는 `어제 했지 오늘은?` 을 지금도 막는다.
  틀린 것은 게이트가 아니라 **게이트를 어디에 걸었는가** 였다. 입구에서 재고
  출구에서 다시 조립하면, 잰 것과 나간 것이 다르다.

  → 바깥으로 나가는 값이 **호출 직전에 가공된다면, 가공된 뒤에 다시 검사한다.**
    검사와 발송 사이에 코드가 있으면 그 코드가 검사를 무효로 만들 수 있다.

  그리고 **관측이 먼저다.** 이 건은 우리 로그에 한 줄도 없어서 남의 대시보드로
  발견됐다 ([`0002`](2026-08-27-what-went-out-left-no-trace-of-its-own.md)).
  그것을 먼저 고쳤기 때문에 이 수정이 고쳐졌다는 것도 우리 로그로 확인할 수 있었다.

## 남은 것

- **왜 30번 넘게 반복됐는지 — 2026-08-28 에 유력한 설명이 나왔다 (정황 추론)**

  그 구간 로컬 로그도 없다. 그런데 **운영 대화로 같은 문장을 30번 칠 이유가 없다.**
