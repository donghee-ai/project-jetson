# 08-23 에 고쳤다고 적은 것이 절반이었다 — 폰 URL 이 게이트 하나 앞에서 막혀 있었다

- **날짜**: 2026-09-04
- **깨진 가정**: **"증상이 사라졌으니 원인을 고친 것이다."**

## 무슨 일이 있었나

08-23 에 `bucket_type()` 에서 `web` 을 `android` 보다 앞으로 옮겼다. 기록은 이렇게 적혀 있다:

> **`android` 로 잡히면 URL 이 통째로 죽는다** — 롤업이 URL 을 `dev.buckets["web"]` 에서만
> 꺼내 슬롯에 붙이는데, 폰의 web 버킷이 영원히 비어 있어 `rules.yaml` 의 URL 규칙이 폰
> 브라우징에 하나도 걸리지 않았다. **폰 크롬 929분이 앱 이름만으로 `browsing`/`away` 로
> 뭉뚱그려져 있었다.**

09-04 에 같은 것을 다시 쟀다. **증상이 그대로였다.**

```
폰 웹 이벤트 1,228건 — 전부 url 이 있다
폰 크롬 슬롯 149개  → browsing 123 · away 26      ← 앱 이름만으로 뭉뚱그려진 그대로
```

## 왜

버킷 타입을 고친 것은 맞았다. 이벤트는 `dev.buckets["web"]` 까지 **왔다.**
그런데 그 다음에 게이트가 하나 더 있었다:

```python
url = None
if classifier.is_browser(app):          # ← 여기
    url = _best_web_url(web_hits, w_start, w_end)
```

`is_browser` 는 `config/rules.yaml` 의 `browser_apps` 를 본다. 그 목록은
**데스크톱 실행파일명뿐**이었다 — `chrome.exe`, `firefox`, `safari` …
`com.android.chrome` 은 없다. 그래서 폰 세션은 URL 을 받을 수 없었다.

## 가정이 깨진 지점

**두 지점을 고쳐야 하는데 하나만 고치고 증상이 사라졌는지 다시 안 쟀다.**

08-23 당시에는 폰 web 버킷이 통째로 비어 있었으므로, 버킷 타입을 고친 것만으로도
"이벤트가 들어오기 시작"하는 눈에 보이는 변화가 있었다. 그 변화를 **증상이 사라진
것으로 읽었다.** 실제로는 파이프의 앞쪽 막힘 하나를 뚫었을 뿐, 뒤쪽 게이트는 그대로였다.

원래 기록에 *"URL 규칙이 폰 브라우징에 하나도 걸리지 않았다"* 라는 **검증 가능한 문장**이
있었는데, 고친 뒤 그 문장을 다시 확인하지 않았다.

## 고친 것

`browser_apps` 에 안드로이드 패키지를 넣었다. 폰이 url 을 뽑을 수 있는 브라우저는
앱의 `WebWatcher.KNOWN_BROWSER_PACKAGES` 가 정하므로 **그 목록과 같게** 뒀고,
한쪽만 늘리면 조용히 다시 갈린다는 것을 주석에 적었다.

## ★ 고쳤는데도 화면은 거의 안 바뀐다 — 그것도 사실이다

재롤업 전후 카테고리별 합이 거의 같다 (엔터테인먼트 +0.2분, 브라우징 −0.3분).
**배관은 뚫렸지만 흘릴 것이 없다** — URL 규칙이 이 사람이 실제로 보는 사이트를
하나도 안 덮는다:

```
실제:  m.example-forum.com · m.example-board.com · m.example-portal.com · example-stream.com · example-blog.net · google.com/search
규칙:  arxiv · github · mail · op.gg/inven · youtube · 뉴스사이트
```

움직인 0.2분이 `youtube.com` 규칙이 걸린 것이고, **그게 배관이 뚫렸다는 증거**다.
규칙을 늘릴지는 "이 시간을 무엇으로 셀 것인가" 라는 사람의 결정이라 여기서 하지 않는다.

## 곁가지 — 폰이 주소창 힌트를 URL 로 보낸다

같이 재다가 나왔다. `"Google 검색 또는 URL 입력"` 이 URL 자리에 **128회 13.8분** 들어와
있다. 주소창이 비었을 때의 안내 문구다. 폰 `WebWatcher.extractUrl` 이 그것까지
읽는다 — 폰 쪽에서 걸러야 한다.
