# 주석이 코드보다 낙관적이었다

> 2026-09-01 · `migrate()` 사고 직후 같은 부류를 훑었다 · `llm/queue.py` · `plan/models.py`

## 깨진 가정

**"한 번 밟았으니 그 한 건을 고치면 된다."**

아니다. [마이그레이션 러너](2026-09-01-the-migration-runner-nobody-called.md)는
**부류의 첫 사례**였다.

## 무엇을 쟀나

프로덕션 코드에서 이름이 한 번도 안 나오는 공개 함수를 AST 로 셌다.
정규식이 아니라 AST 인 이유가 이 조사의 전부다 — **주석과 독스트링을 빼야** 한다.

13개가 나왔다. 그중 하나가 `purge_done` 이었고, 정규식이었으면 못 찾았을 것이다.

## `purge_done` — 주석이 없는 일을 있다고 말했다

`lt doctor` 의 큐 판정에 이렇게 적혀 있었다:

```
# ★ 그렇다고 **누적 실패율**도 아니다 (2026-08-28, issues/0016).
#   `purge_done` 이 종료 잡을 14일 뒤에 걷어가므로 done 은 회전하는데
#   failed 는 그 창이 지나야 사라진다.
```

**`purge_done` 에는 호출자가 없었다.** 회전한 적이 없다.

```
가장 오래된 done   2026-08-17 (17일 전)
failed             204건, 2026-08-20 부터 그대로
```

주석의 결론("누적 말고 최근을 보라")은 맞았다. 틀린 것은 **근거**다.
근거가 틀린 채로 맞는 결론은 다음 사람이 재사용할 수 없다.

★ 이 주석은 이미 한 번 실패에서 배운 자리다 —
[내려갈 수 없는 비율](2026-08-28-a-ratio-that-could-not-fall.md).
**교훈을 적으면서 그 교훈의 근거를 확인하지 않았다.**

## `unskip_plan` — 되돌릴 길이 아예 없었다

`skip_plan` 은 CLI(`lt plan skip`)와 웹(`POST /api/plan/<id>/skip`) 둘 다 있는데
`unskip_plan` 은 **어디서도 안 불렸다.** 그리고 건너뛴 계획은 목록에서 빠지므로
잘못 눌렀을 때 DB 를 직접 손대는 것 말고 길이 없었다.

붙이려고 테스트를 쓰다가 **더 큰 것이 나왔다** — 건너뛰기 자체가 동작하지 않는다.
`plan_skip` 은 전개(materialize) 후보 쿼리에서만 쓰이는데, 사람이 보고 있는 날은
**이미 전개된 뒤**다. 버튼은 200 을 돌려주고 아무 일도 안 한다
([issues/0026](../docs/issues/README.md#옛-번호-대응표)).

> 안 불리는 함수를 쫓다가 **불리는 함수의 버그**가 나왔다.
> 죽은 코드는 그 자체보다, 그 옆이 왜 그런지를 알려준다.

## 무엇을 만들었나

`tests/test_no_unused_exports.py` — 안 불리는 공개 함수를 잡는다.

**지우라는 검사가 아니다.** 셋 중 하나를 하면 꺼진다:

| | |
|---|---|
| 부른다 | `purge_done` 이 이렇게 꺼졌다 |
| 지운다 | |
| **이유를 적어 목록에 넣는다** | ← 이게 핵심이다 |

이유를 적게 하는 것이 요점이다. `verify_link_token` 의 이유는 이렇게 적혀 있다 —
*"함정이라 주의. `/auth/enter` 는 `consume_link_token` 을 쓴다. 이쪽은 1회용 검사를
안 한다. 실수로 이걸 쓰면 토큰 재사용이 열린다."* 다음 사람은 이걸 안 재도 된다.

### 언제 안 우나

| 안 세는 것 | 왜 |
|---|---|
| `_` 로 시작 | 비공개 |
| 데코레이터가 붙은 것 | `@app.get(...)` — **등록이 곧 호출자** |
| 기반 클래스가 있는 클래스의 메서드 | `HTMLParser.handle_data` — 부모가 부른다 |

이 셋을 안 뺐을 때 35개가 나왔고 그중 22개가 오탐이었다.

### 양방향으로 운다

목록이 한 방향으로만 자라면 결국 아무 말도 안 하게 된다. 그래서 반대도 잡는다 —
**고쳐 놓고 목록에서 안 뺀 것.** 일부러 넣어 확인했다:

```
① 안 불리는 함수를 심었을 때   → nobody_calls_this (timeutil.py:263)
② 고친 걸 목록에 남겨 뒀을 때  → 이제 불리는데 목록에 남아 있다 — 지워라: ['day_str']
```

그리고 검출기 자체의 자기 시험이 있다 — 오탐 넷(비공개·데코레이터·오버라이드·호출됨)을
각각 안 잡는지 본다.

## 판단이 필요했던 셋 (2026-09-03 에 정했다)

### `alert` — 지웠다. 그런데 진짜 구멍은 다른 데 있었다

물어보려고 조사하다가 **아무것도 "동기화가 멈췄다"를 안 잡는다**는 것을 알았다.
`lt doctor` 는 마지막 커서를 **찍기만** 하고 오래됐는지 안 봤고, `daily-check.sh` 는
타이머 결과를 안 보며, `host-status.sh` 가 보는 유닛 목록에 `lifetrainer-sync` 가 없다.

09-01 에 롤업이 10분마다 죽었을 때 doctor 는 *"롤업 08-12 ~ 09-01"* 이라고 OK 를 찍었다.
**범위는 맞았고, 그 범위가 멈춰 있다는 것만 몰랐다.**

★ 그런데 **커서로 재면 안 된다.** 커서는 PC 에 새 이벤트가 있을 때만 전진하므로
노트북을 꺼 두면 밤새 안 움직인다 — 그건 고장이 아니다. 매일 아침 헛경보가 났을 것이다.

`MAX(slot.updated_at)` 으로 잰다. 롤업은 이벤트가 없어도 오늘 144칸을 다시 쓰므로
**PC 가 꺼져 있어도 전진한다.** 멈췄다면 멈춘 것은 우리 쪽이다.

| | |
|---|---|
| 언제 꺼지나 | 롤업이 한 번 성공하면 즉시 (누적 아님) |
| 안 울려야 할 때 | PC 꺼짐 · 갓 만든 DB(*"아직 롤업한 적 없음"* — 실패가 아니라 미확인) |
| 두 번 세나 | AW 도달 불가는 위의 ActivityWatch 항목이 따로 말한다. **한 사건에 경보 하나** |

`alert` 은 지웠고, **그 기능을 지키던 테스트 4개는 지우지 않고 뒤집었다** — 이제
"그 경로가 없다"와 "대신 `daily-check.sh` 가 자기시험을 갖고 상태 변화만 알린다"를 지킨다.
지우기만 하면 다음 사람이 되살려도 아무도 안 막는다.

`alert_state` 테이블은 스키마에 남겼다(0행). 지우려면 마이그레이션이 필요한데,
빈 테이블 하나보다 **옛 DB 와 새 DB 가 갈리는 쪽이 더 나쁘다.**

### `carry_debt` — 일일 리포트에 붙였다. 0이면 안 보인다

슬랙 `/defer` 가 이월을 **실제로 만들고** `v_carry_debt` 뷰도 동작하는데
**읽는 쪽만 없었다.** 숫자만으로는 못 고치므로 제목을 붙였다
(`carry_debt_titles`) — *"↩️ 두 번 이상 미룬 것: 보고서 쓰기 (3번)"*.

★ 붙이자마자 **검사가 조용해졌다.** `DailyStats.carry_debt` 필드를 만들었더니
`stats.carry_debt` 가 `ast.Attribute(attr="carry_debt")` 로 잡혀 함수가 불리는 것처럼
보였다. 판정 단위가 이름이지 바인딩이 아니라서 생기는 한계다 —
필드를 `repeated_defers` 로 바꿔 충돌을 없애고, 한계를 검사 문서에 적었다.

### subject CRUD — 지우려다 되돌렸다

*"0행이고 만드는 길이 없다"* 를 근거로 삭제하기로 했는데, **지우기 전에 열어 보니**
(CLAUDE.md §5) 전용 테스트가 11개 있고 슬랙의 subject 목록 기능 테스트가
`create_subject` 를 픽스처로 쓴다. 지우면 그 테스트가 raw SQL 로 내려앉는다.

**없는 것은 모듈이 아니라 진입점이다.** 읽는 쪽은 이미 슬랙이 쓰고 있다.
검사가 이유를 묻게 만들어 뒀으므로 비용은 줄 네 개다.
