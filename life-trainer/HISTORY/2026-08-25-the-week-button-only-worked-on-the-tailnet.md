# 주간 버튼이 tailnet 에서만 동작했다

> 2026-08-25 · `web/templates/planner.html`·`week.html` · 발견: 사용자 ("웹 주간 부분 안 나와")

## 증상

웹 플래너에서 **주간** 버튼을 누르면 아무것도 안 나온다. 그런데 젯슨에서
`http://100.64.0.2:8770/w/…` 를 직접 열면 **멀쩡히 나온다.**

## 깨진 가정

> "라우트가 200 이면 화면도 뜬다."

아니다. **어느 주소로 들어왔느냐에 따라 같은 라우트가 다른 경로에 있다.**

앱은 두 얼굴로 서빙된다. tailnet 직결은 `/d/`, 터널(`lt.example.com`)은
`_PrefixMiddleware` 가 `SCRIPT_NAME=/planner` 를 붙여 `/planner/d/` 다.
그런데 템플릿의 내부 링크 4개가 **접두사를 무시하고 루트 절대경로로 박혀** 있었다.

```html
<a href="/w/{{ day }}">주간</a>          <!-- planner.html -->
<a href="/w/{{ prev_end_day }}">◀</a>    <!-- week.html · 이전/다음/일간 3개 -->
```

터널로 들어온 사용자가 `https://lt.example.com/planner/d/2026-08-25` 에서 주간을
누르면 `https://lt.example.com/w/2026-08-25` 로 간다. cloudflared 는
`^/ingest/` 와 `^/planner` **둘만** 열어 두고 나머지는 `http_status:404` 라,
**터널이 404 를 돌려준다.** 앱까지 오지도 않는다.

실측:

```
https://lt.example.com/planner/d/…   401   (세션 없음 — 정상)
https://lt.example.com/w/…           404   ★ 주간 버튼이 가는 곳
```

## 왜 안 잡혔나

**JS 는 이미 접두사를 쓰고 있었다.** `planner.js`·`week.js` 가
`#app-base` 의 `data-base` 를 읽어 `BASE + "/api/day/…"` 로 부른다.
그래서 **데이터는 잘 오는데 페이지 이동만 죽는** 모양이 됐다.

두 템플릿 모두 `url_prefix` 를 **이미 넘겨받고 있었고**(`request.script_root`),
`data-base` 에는 쓰고 있었다. `href` 에만 안 썼다. 값을 안 만든 게 아니라
**만들어 놓고 한 군데서 안 쓴 것**이다.

그리고 개발·확인은 전부 tailnet 직결로 했다. 거기서는 접두사가 빈 문자열이라
**틀린 링크와 맞는 링크가 같은 문자열이 된다.** 터널로 열어봐야만 갈린다.

## 고친 것

`href` 4개에 `{{ url_prefix }}` 를 붙였다. 접두사가 없으면 빈 문자열이라
tailnet 직결은 예전 그대로다.

테스트 3개를 추가했다 (`test_web.py`):

- 접두사가 있으면 일간·주간 페이지의 링크가 **전부** `/planner/…` 인가
- **접두사 없는 `href="/w/`·`href="/d/` 가 하나도 안 남았는가** — 하나만 남아도 터널에서 죽는다
- 접두사가 없을 때는 예전 그대로인가

## 남는 것

이 부류는 **라우트를 추가할 때마다 재발할 수 있다.** 링크를 손으로 쓰는 한
누군가 또 접두사를 빠뜨린다. `url_for` 를 쓰면 Flask 가 `SCRIPT_NAME` 을 알아서
붙이므로 구조적으로 막히는데, 지금은 템플릿이 문자열로 조립한다.
당장은 위의 "접두사 없는 href 가 없는가" 테스트가 그물 역할을 한다.
