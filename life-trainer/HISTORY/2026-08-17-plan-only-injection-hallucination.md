# 계획만 주입했더니 모델이 "다 했다"고 지어냈다

- **발견**: 대화 기능을 실데이터로 처음 E2E 돌린 첫 질문에서 바로.
- **증상**:

  ```
  Q: 오늘 뭐 했지?
  A: 오늘 계획 A·B·C를 모두 달성했다.
  ```

  계획들은 미달성으로 주입돼 있었다. 실제 일정·활동 수치·앱 이름은 공개본에서 제거했다.

- **원인**: 시스템 프롬프트에 **계획(`plan_instance`)만 넣고 실측(`slot`)을 안 넣었다.**

  계약서 §3 은 `slot`(기계 측정) / `plan_instance`(사람 의도) / `slot_override`(사람 정정)를
  **절대 섞지 말라**고 못박아 두었다. 나는 그 원칙을 DB 층에서만 지키면 되는 것으로
  읽었다. 그런데 프롬프트도 층이다. 의도만 주고 "오늘 뭐 했냐"를 물으면, 모델에게
  주어진 유일한 재료가 의도뿐이라 **그걸로 답을 만들 수밖에 없다.**

  깨진 가정: **"계획을 주입하면 모델이 계획을 계획으로 읽을 것이다."**
  실제로는 — 질문이 실측을 요구하는데 실측이 없으면, 모델은 되묻지 않고 있는 재료를
  변환해서 답한다. 그리고 **에러가 나지 않는다** (`docs/build/openclaw-agent.md §4-6` 과 같은 부류).

- **수정**: 두 가지.

  1. 실측 활동 요약을 **③층(user 메시지)** 에 함께 주입한다. ①층(시스템)이 아닌 이유는
     활동 집계가 10분마다 갱신되기 때문이다 — ①층에 넣으면 하루에도 몇십 번 프롬프트
     캐시가 깨진다. user 메시지는 어차피 매 턴 새것이라 손해가 0이다.
  2. 두 블록의 제목에 출처를 박았다. `[오늘 … 계획 — 사람이 세운 의도]` /
     `[오늘 실제 활동 — 기계 측정]`.

  덤으로 하나 더 나왔다. 고친 뒤 `"오늘 계획대로 잘 했어?"` 에 주입값과 다른 달성률을
  답했다. 계획과 실측을 함께 받아 **자기가
  나눗셈을 했다.** 소형 모델은 산술을 틀린다. 시스템 프롬프트에
  `숫자는 주어진 값을 그대로 인용한다. 비율·합계·차이를 새로 계산하지 마라` 를 넣어 막았다.

- **방어**:
  - `test_llm_tools.py::test_시스템층에는_실측이_들어가지_않는다` — ①층 오염 방지
  - `test_llm_tools.py::test_턴_컨텍스트에_실측이_들어간다` — ③층 누락 방지
  - `test_llm_converse.py::test_계획은_시스템에_실측은_user_에_들어간다` — 조립 결과 고정

  단, **셋 다 배치만 검증한다.** "모델이 지어내지 않는가"는 실호출로만 확인된다.
  자동 회귀 방어가 없는 영역이라는 것을 알고 있어야 한다.

- **교훈**: **프롬프트도 층이다. DB 에서 분리해 둔 개념은 프롬프트에서도 분리해서,
  둘 다 실어야 한다.** 한쪽만 실으면 모델이 그 한쪽으로 나머지를 지어낸다.

  일반화하면 — **"모델이 X 를 물어볼 텐데 X 가 프롬프트에 없다"** 는 조용한 환각의
  가장 흔한 입구다. 툴을 붙여 두는 것으로는 안 막힌다. 소형 모델은 툴을 안 부르고
  있는 재료로 답하는 쪽을 택한다.
