# master 소스에 있는 화면이 배포된 APK 에는 없었다

- **발견**: 사용자가 폰에서 API 키 설정 화면을 찾다가. "어디 넣어야 하는지 모르겠네"
- **증상**: 계획 문서가 "앱 설정의 **API key** 화면에서 값을 얻어라"라고 지시하는데,
  앱을 아무리 뒤져도 그 화면이 없다. 사용자가 자기가 못 찾는 줄 알고 헤맸다.
- **원인**: **`AuthSettingsActivity.kt` 를 master 소스에서 읽고 "앱에 있다"고 썼다.**
  실제로 폰에 깔린 것은 공개 릴리스 APK(`v0.14.0dev20260723`)이고,
  그 화면은 **그 태그 이후 master 에 추가된 것**이었다. 릴리스와 master 사이가
  18커밋 벌어져 있었고(master 는 이미 `0.14.0b1`/versionCode 39), APK 로는 안 나왔다.

  ```
  adb shell dumpsys package net.activitywatch.android | grep Activity
    → .MainActivity 하나뿐. AuthSettingsActivity 없음
  ```

  **"더 최신 APK 로 갈아타면 되지 않나"도 아니다** — 공개된 최신 APK 가 그것이다.

- **수정**: 코드 수정 아님. 문서를 고쳤다.
  - `android/docs/runbook.md` §③ — "앱 설정에서 키를 얻어라" 를 지우고
    **막다른 길이라는 것과 시도해서 실패한 6가지**를 남겼다
    (`run-as`·외부 저장소·logcat·헤더 위장·WebView 디버깅·앱 내 Export)
  - 게이트 a·b·c 는 **master 소스에서 확정**했다. 우리가 빌드할 것이 그 소스이므로
    릴리스 APK 를 재는 것보다 정확하다 — 다만 **그 사실을 명시**해 뒀다

- **방어**: 없음(문서 규칙으로만).
  기계적으로 막을 방법이 마땅치 않다. 대신 runbook 에 **"앱에서 API 키 화면을 찾지
  마라. 없다."** 를 첫 줄에 박아 다음 사람이 같은 데서 시간을 쓰지 않게 했다.

- **교훈**: 이 프로젝트 반복 실패 1번의 **세 번째** 사례다.

  | 회차 | 읽은 것 | 붙인 것 |
  |---|---|---|
  | 1 | aw-server-**rust** 소스 ("이벤트는 겹치지 않는다") | 파이썬 aw-server |
  | 2 | arXiv **공식 API 문서** | robots.txt 로 전 경로 차단된 실물 |
  | 3 | aw-android **master** 소스 | 배포된 **릴리스 APK** |

  앞의 두 번은 "**구현체**가 다른 것"이었고, 이번은 "**시점**이 다른 것"이다.
  같은 저장소·같은 파일이어도 **HEAD 와 배포물은 다른 물건이다.**

  → **버전을 확인하라는 것으로는 부족하다.** 버전은 맞았다(`v0.14.0dev20260723` 이
  최신 APK 가 맞다). **"내가 읽은 코드가 그 버전에 들어 있는가"** 를 따로 확인해야 한다.
  릴리스 태그로 체크아웃해서 읽거나, 실물에서 존재를 먼저 확인하고 계획에 쓴다.

## 덤으로 나온 것 — 진짜 버그 하나

게이트 c 를 master 소스에서 확인하다가, 우리 코드의 실제 문제를 찾았다.

```json
"data": {"app": "카카오톡", "package": "com.kakao.talk", "classname": "…"}
```

`data.app` 이 **패키지명이 아니라 사람이 읽는 앱 이름**(`getApplicationLabel`)이었다.
`upsert_events` 가 `data.app` 을 그대로 `app` 컬럼에 넣으므로, **분류 규칙이
`"카카오톡"` 같은 로케일 의존 라벨에 걸린다** — 폰 언어를 바꾸거나 앱이 이름을 바꾸면
조용히 안 맞는다. 실데이터가 들어온 뒤에 발견했으면 원인 찾기가 훨씬 어려웠을 것이다.

데스크톱과 같은 배치로 맞췄다: **`app` = 패키지명(규칙용), `title` = 앱 이름(표시용)**.
`app=Code.exe / title=창 제목` 과 같은 구조다 (`collect/ingest.py`, 테스트 2개).

**막다른 길에서도 얻은 게 있었다** — 표본을 못 뽑은 대신 소스를 읽었고, 그 과정에서
실데이터가 들어오기 전에 이걸 잡았다.
