# 하이브리드 검색이 키워드 단독보다 나빴다 — 질의에 지시문을 안 붙였다

- **발견**: 사용자가 "rag가 여기서 정확하게 뭘 하고 있는거야?" 라고 물어서 경로를
  훑다가, `jetson` 검색 결과에 `Introducing Google Antigravity` 가 2번으로 올라온 것을
  봤다. `docs/rag-plan.md §5` 가 요구했던 20질의 비교를 그제서야 돌렸다.

- **증상**: 고유명사 질의가 무관한 문서를 물어온다. `jetson` → Google Antigravity /
  Reachy Mini / LeRobot. `jetson 추론 최적화` → Intel CPU Stable Diffusion.
  키워드로는 잘 찾히는 것들이었다.

- **원인**: **"하이브리드니까 둘의 장점을 합친다"** 를 사실이라고 믿었다.

  ```
                    kw     vec   vec+i     rrf   rrf+i
  hit@5            96%     44%     86%     76%     98%
                                            ↑
                        하이브리드가 키워드 단독보다 20%p 낮았다
  ```

  진짜 원인은 Qwen3-Embedding 계열이 질의를 `Instruct: {task}\nQuery:{q}` 로 받는
  전제로 학습됐는데 **맨 질의를 보내고 있었다**는 것. 질의 벡터가 문서 벡터와
  어긋난 자리에 놓이니, 벡터 쪽 상위 20건이 사실상 무작위였다.

  RRF 는 두 목록이 **겹칠 때** 이득이 난다(양쪽에서 발견된 문서가 점수를 두 번 받는다).
  겹침이 1% 라 융합이 재순위가 아니라 **1:1 교대**로 퇴화했고, 모델에게 주는 3칸 중
  1칸이 무관한 문서로 고정 배정됐다.

- **수정**: `embed.query_instruct` 를 추가해 **질의에만** 접두를 붙인다.
  문서 쪽에는 안 붙이는 것이 이 모델의 규약이라 **재색인이 필요 없었다**(4,270건 그대로).
  `vector_weight` 는 0.5 유지(접두 후 0.3 과 동률), 코사인 컷오프는 안 넣었다 —
  질의별 1위 점수가 0.50~0.65 로 흩어져 절대 컷오프가 성립하지 않는다.

- **방어**: `scripts/eval_search.py` — 엔티티 10질의는 기계 판정(찾는 낱말이
  제목·초록에 있으면 관련), 개념 10질의는 점수 분포만 찍고 판정은 사람이 한다.
  `--weight` 로 가중치를 쓸어볼 수 있다. `tests/test_embed.py` 5건으로
  "질의에는 붙고 문서에는 안 붙는다" 를 고정.

- **교훈**: **모델이 요구하는 입력 형식을 확인하지 않으면 임베딩은 조용히 틀린다.**
  차원도 맞고 정규화도 맞고 에러도 안 나는데 결과만 무작위다 — 잴 방법을 안 만들면
  영영 모른다. 그리고 **rag-plan §5 가 "20질의 비교 없이 붙이지 마라" 고 적어 둔 것이
  정확히 이걸 막으려던 것이었다.** 진입 조건을 건너뛴 대가를 두 달 뒤에 치렀다.
