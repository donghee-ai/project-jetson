# 하루 경계를 06:00 으로 옮기자 세 곳이 조용히 어긋났다

- **발견**: 마이그레이션 자체는 깨끗했다(테스트 466개 통과, 불변식 위반 0).
  **여파는 그 뒤에 하나씩** — CLI 를 직접 돌려서, 스크린샷을 DB 와 대조해서, 다른 담당이 코드를 읽다가.
- **증상**: 셋 다 **에러가 안 났다.** 조용히 틀린 값을 만들었다.

## 배경

자정 기준이던 논리적 하루를 **KST 06:00 → 다음날 06:00** 으로 옮겼다
(레퍼런스 흡수, `slot 0 = 06:00~06:10`). 종이 플래너 격자가 06시에 시작하는데
데이터 경계는 자정이라 둘이 어긋나 있었기 때문이다.

경계를 바꾸는 것 자체는 `timeutil` 한 곳에서 처리했다. **문제는 그 값을 각자 계산하던 곳들이었다.**

---

## ① `lt log --at 09:00` 이 15:00 으로 기록됐다

```python
day_start, _ = timeutil.day_bounds(day, cfg.tz)   # 이제 06:00 을 돌려준다
end_ts = day_start + hh * 3600 + mm * 60          # 06:00 + 9h = 15:00  ✗
```

자정 기준일 때는 `day_start` 가 00:00 이라 맞았다. 경계가 바뀌자 6시간씩 밀렸다.

**수정** — 벽시계 시각을 경계 기준 오프셋으로 환산한다:

```python
offset_min = ((hh * 60 + mm) - boundary * 60) % 1440
end_ts = day_start + offset_min * 60
```

`% 1440` 덕분에 경계보다 이른 시각(01:00 등)이 자동으로 다음 날 새벽에 배치된다.
확인: `--at 09:00` → 08:00~09:00, `--at 01:00` → 다음날 00:30~01:00(논리적 하루는 동일).

**발견 경로**: CLI 를 임시 DB 로 직접 돌려보고 기록된 시각을 눈으로 확인.

---

## ② 웹 격자가 6시간 이중 회전했다

```python
hour = (grid_start_hour + r) % 24
base = hour * cols          # ✗ 벽시계 시각으로 슬롯을 찾는다
```

`hour` 는 화면에 찍는 **라벨**인데 그걸로 슬롯 인덱스를 계산했다.
경계 전에는 slot 0 이 자정이라 맞았지만, 이제 slot 0 이 곧 06:00 이라 36슬롯이 밀린다.

**증상**: 18~24시가 통째로 비고 01~05시에 활동이 몰려 보였다.
DB 를 조회해보니 슬롯 11~107(07:50~23:50)로 **데이터는 정확**했다 — UI 만 틀렸다.

**수정**: `base = r * cols`. `hour` 는 라벨 표시용으로만 남긴다.

**발견 경로**: 스크린샷을 보고 "저녁이 왜 비지?" → DB 원본과 대조.
별개로 UI 담당 에이전트도 픽셀 분석으로 독립적으로 같은 결론에 도달했다.

---

## ③ 계획 오버레이가 격자와 어긋났다

`plan/achieve.py` 가 `plan.start_min // slot_minutes` 로 슬롯을 구하고 있었다.
자정 기준 계산이라 경계 도입 후 `slot_breakdown`(경계 보정됨)과 어긋났다.

**수정**: `timeutil.wallclock_min_to_slot(..., boundary_hour=...)` 로 교체.

**발견 경로**: 계획 계층 담당이 코드를 읽다가. **픽셀 비교를 안 하는 테스트라 안 잡혔다.**

## 교훈

**셋 다 원인이 하나다: 같은 값을 여러 곳에서 각자 계산하고 있었다.**
평소에는 기본값이 우연히 일치해서 아무 문제가 없다가, 그 값이 바뀌는 날 전부 조용히 어긋난다.

파생값(격자 시작, 슬롯 인덱스, 하루 시작 timestamp)은 **한 곳에서만 계산하고 나머지는
받아 써야 한다.** 인자에 기본값을 주는 것은 호환을 위해 편하지만, 동시에
"안 넘겨도 돌아간다"는 뜻이라 이런 어긋남을 숨긴다 —
경계 전환을 맡은 담당이 이 위험을 정확히 지적했고, 실제로 다음 파일에서 현실이 됐다.

그리고 **파괴적 변경은 실데이터가 쌓이기 전에 하라.** 이번엔 합성 데이터뿐이라
`slot`/`slot_breakdown` 을 통째로 지우고 재롤업하는 게 공짜였다.
몇 주 뒤였으면 훨씬 비쌌다.
