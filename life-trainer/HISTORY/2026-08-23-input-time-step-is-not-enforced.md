# `<input type="time" step="600">` 이 제출을 조용히 막고 있었다

- **발견**: 사용자가 "계획 수정이 안 된다" 고 보고. 서버 API 는 네 가지 본문으로
  직접 쳐 봐도 전부 200 이었고, JS 도 URL 접두사를 제대로 붙이고 있었다.
  실제 브라우저(모바일 뷰포트)를 붙이고서야 클라이언트 검증 단계라는 것이 보였다.

- **증상**: 저장 버튼을 눌러도 아무 일도 안 일어난다. 오류 메시지도 없고 네트워크
  요청도 안 나간다. 폰 로케일이 12시간제면 시간 선택기에 오전/오후가 붙고,
  분은 1분 단위로 고를 수 있어 09:13 같은 값이 들어간다.

- **원인**: **"`step` 을 주면 그 단위로만 고를 수 있다"** 를 사실이라고 믿었다.

  안드로이드 네이티브 시간 피커는 `step` 을 **무시한다.** 그래서 09:13 이 들어가고,
  그 값은 `step="600"` 기준으로 `stepMismatch` 가 된다. `required` 와 겹치면
  브라우저의 기본 검증이 **submit 이벤트 자체를 발생시키지 않는다** —
  JS 의 `addEventListener("submit", ...)` 는 검증을 통과한 뒤에 불리므로,
  코드 입장에서는 사용자가 버튼을 누른 적이 없는 것과 같다.

- **수정**: `<input type="time">` 을 버리고 셀렉트 두 개로 바꿨다.
  시 `00~23`(24개) · 분 `00 10 20 30 40 50`(6개). **고를 수 없게** 만든 것이라
  기기·브라우저·로케일에 기대지 않는다.
  옛 데이터가 09:13 이어도 열리도록 `snapMinute()` 로 가장 가까운 10분에 맞춘다 —
  없으면 셀렉트가 첫 항목으로 되돌려 놓아 **조용히 시각이 바뀐다.**

- **방어**: `tests/test_web_ui.py` 3건 — `type="time"` 이 없다 / 시가 00~23 24개 /
  분이 10분 단위 6개.

- **교훈**: **"지켜 주기를 바라는 제약" 과 "지킬 수밖에 없는 구조" 를 구분한다.**
  `step`·`maxlength`·`pattern` 은 전자다. 기기가 무시할 수 있고, 무시된 값이
  다시 그 제약에 걸려 **아무 말 없이 막히는** 조합이 최악이다.
  그리고 **네이티브 폼 검증은 JS 앞에 있다** — "핸들러에 로그를 넣었는데 안 찍힌다"
  면 코드가 아니라 검증을 의심한다.
