# 템플릿이 코드보다 뒤처지는 것을 사람 눈으로 막고 있었다

> 2026-09-03 · `config/lifetrainer.example.toml` · 옛 [`issues/0004`](../docs/issues/README.md) (고쳐서 여기로 옮겼다)

## 깨진 가정

**"전수 대조로 찾아 적어 두면 다음에 안 벌어진다."**

벌어진다. **찾은 것은 그때의 목록이지 규칙이 아니다.**

## 무슨 일이 있었나

2026-08-23 에 전수 대조로 찾았다. 08-27 에 재확인하고 *"지금도 그대로다"* 라고 적었다.
**09-03 까지 열려 있었고, 그 사이 빠진 키가 6개에서 18개로 늘었다.**

```
❌ rollup.day_boundary_hour
❌ web.external_host · url_prefix · external_mask
❌ embed.*        9개  ← [embed] 섹션 자체가 없었다
❌ private.*      5개  ← 2026-09-01 에 내가 넣은 것
```

★ **그중 5개는 이 검사를 붙이기 직전에 내가 벌린 것이다.** 프라이빗 모드를 만들면서
`_DEFAULTS` 에 다섯 줄을 더하고 템플릿에는 안 더했다. 이슈를 읽은 적도 있는데 그랬다.
규칙만 있고 검사가 없으면 규칙을 아는 사람도 어긴다.

## 무엇이 아까운가

동작은 안 깨진다 — `config.py` 에 기본값이 있다. 잃는 것은 **알 기회**다.

```
embed.batch_size    4    ~3 doc/s   → 재색인 24.6분
                   16     9.0 doc/s →       8.2분
                   64    25.8 doc/s →       2.9분
```

청킹 전략을 바꿔가며 재색인하는 실험이 그 값 하나에 달려 있는데, 템플릿에 없으면
**있는 줄도 모른다.**

## 무엇을 만들었나

키 집합을 비교하는 테스트를 **양방향으로** 붙였다.

| | 잡는 것 | 왜 |
|---|---|---|
| → | 코드는 읽는데 template 에 없는 키 | 설치하는 사람이 그 설정을 모른다 |
| ← | template 에만 있고 코드가 안 읽는 키 | **더 나쁘다.** 적어 놨는데 아무 효과가 없으니 적용된 줄 안다 |

한쪽만 만들면 목록이 한 방향으로만 자란다. 일부러 깨뜨려 둘 다 우는 것을 확인했다.

★ **값은 안 본다, 키만 본다.** example 이 코드 기본값을 담고 주석이 이 기기 운영값을
말하는 것이 이 저장소의 관례다(`[nightly]` 의 `summary_limit` 600 vs 30 참고).
값까지 묶으면 그 관례가 깨진다.

### 곁다리 — 내 시험이 먼저 틀렸다

"example 에만 있는 키" 쪽을 확인하려고 `[private]` 섹션을 파일 끝에 덧붙였다.
그런데 그 섹션은 이미 있었고, **TOML 중복 섹션 파싱 에러**가 났다.
테스트는 실패했지만 **내 단언이 운 게 아니었다.** 기존 섹션 안에 키를 넣어 다시 했다.

> 검사를 깨뜨려 확인할 때도 **깨뜨린 이유가 내가 의도한 것인지** 봐야 한다.
> 빨간불은 여러 이유로 켜진다.

## 같이 적어 둔 것

`web.external_mask` 는 코드 기본값이 `true` 인데 **이 기기 운영값은 `false`** 다.
플래너를 아직 공개 인터넷에 안 열어서(`/ingest/` 만 열려 있다) 꺼 둔 것이고,
템플릿 주석에 **"플래너를 여는 순간 반드시 true 로 되돌릴 것"** 이라고 적었다.
