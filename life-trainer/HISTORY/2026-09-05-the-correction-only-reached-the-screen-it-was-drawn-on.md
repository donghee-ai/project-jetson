# 사람이 칠한 것이 **그 화면에만** 반영됐다 — 원천이 둘이라서

- **날짜**: 2026-09-05
- **깨진 가정**: **"실측 원본을 안 건드리기로 했으면, 보정은 표시층에서 해결된다."**

## 무슨 일이 있었나

사람이 짚었다 — *"우클릭이나 드래그로 바꾼 수면이 오늘의 수면에 안 합쳐진다."*
그리고 이어서: *"모든 카테고리에 문제일 수도 있으니 검수해봐라."*

**검수해 보니 그랬다.** 3시간을 '학습' 으로 보정하고 재 봤다:

| 화면 | 원천 | 보정 반영 |
|---|---|---|
| 격자 칸 | `slot.category` 위에 보정을 겹쳐 그림 | ✅ 즉시 |
| 오늘의 수면 · 커버리지 · 최장 집중 | `slot.category` | ❌ 다음 롤업까지 |
| **차트 · 원그래프** | `slot_breakdown` | ❌ **영원히** |
| 상위 앱 · 기기별 | `slot_breakdown` | ❌ (원리적으로 불가) |

차트에는 **학습이 아예 안 나타났다.** 수면만의 문제가 아니었다.

## 원인 — 보정이 갈 곳이 없었다

층이 셋인데 단위가 다르다:

```
slot_override(day, slot, category)                     ← 슬롯 단위 (10분 통째)
slot(day, slot, category, …)                           ← 슬롯의 승자 하나
slot_breakdown(day, slot, category, app, device, sec)  ← 슬롯 **안**을 쪼갠 초
```

`plan/override.py` 는 *"실측 원본(`slot_breakdown`)은 절대 건드리지 않는다"* 고 정했고
그건 옳다. 그런데 **각 화면이 원본을 직접 SELECT** 했다 — `slot_breakdown` 을 읽는 곳이
11곳, `slot` 을 읽는 곳이 16곳이다. 보정은 원본에 안 들어가므로, 원본을 직접 읽는 화면은
**보정을 영원히 못 본다.**

즉 표시층에서 해결한 것은 **격자 하나뿐**이었고, 나머지 화면은 각자 틀려 있었다.

## 사람이 먼저 구조를 짚었다

> *"모든 카테고리에 문제라면 설계가 잘못된 것이다. 테이블을 카테고리 쪽을 직접
> 외래키로 참조하면 될 듯하다."*

진단은 맞았다 — 화면마다 따로 고치고 있었다는 것 자체가 설계 신호다.
**다만 외래키는 이 문제를 안 푼다.** FK 는 *"이 카테고리가 존재하는가"* 를 보장하고,
여기서 깨진 것은 *"어느 표를 세느냐"* 다. `slot_override.category` 에 FK 를 걸어도
`SUM(seconds) FROM slot_breakdown` 은 여전히 보정을 못 본다.

★ 그리고 **DB 에는 카테고리 표가 없다.** 정본은 `config/rules.yaml`·`palette.yaml` 이다.
FK 를 걸려면 표를 새로 만들어야 하고, 그러면 정본이 둘이 된다 — 반복 실패 2번을
스키마에 새기는 셈이다.

## 수정 — (B) 읽는 함수를 하나로 + (C) 검사로 막는다

**(B)** 카테고리별 초는 `report/stats.category_seconds` **하나**가 낸다.
원본은 그대로 두고 **읽을 때** 보정을 얹는다. 계획 겹침도 같은 함수의 `overlay` 인자다 —
계획 보기 합계를 따로 세던 코드를 지웠다.

| 층 | 이기는 순서 | 그 칸이 싣는 값 |
|---|---|---|
| 계획(`overlay`) | 1 | 칸 길이 전부 |
| 보정(`slot_override`) | 2 | 칸 길이 전부 |
| 실측(`slot_breakdown`) | 3 | 잰 초 그대로 |

★ 보정 칸이 **칸 길이 전부**인 이유: 실측 초만 쓰면 `off` 였던 칸(측정 0초)을 보정해도
여전히 0이라 화면에 안 나타난다 — *"그때 이걸 했다"* 는 말을 무시하는 셈이다.

**(C)** `tests/test_no_direct_breakdown.py` 가 **새 직접 조회를 막는다.** 허용 목록에는
*왜* 허용인지를 같이 적고, 이유가 짧으면 그것도 실패한다(실제로 내 첫 항목이 걸렸다).
반대 방향도 막는다 — 목록에 죽은 항목이 남으면 그 자리가 조용히 다시 열린다.

**보정 즉시 반영**도 같이 고쳤다. `/api/slot` 이 `slot_override` 만 쓰고 끝나서
`slot.category` 는 다음 롤업까지 옛 값이었다. 지정은 `apply_overrides` 로 즉시(가볍다),
해제는 원래 값을 되계산해야 해서 그 하루만 다시 롤업한다(실측 1.35초).

### FK 대신 — 파일끼리 맞춰 본다

`tests/test_categories.py`. FK 가 막아 줄 것(오타·없는 카테고리)을 **정본을 늘리지 않고**
얻는다. 마침 이번에 그 함정을 실제로 밟았다 — `private` 이 2026-09-01 부터
`rules.yaml` 예약 카테고리에 빠져 있었고, **프라이빗이 있는 날의 일일 PNG 를 그렸으면
`classifier.label()` 이 KeyError 로 죽었을 것이다.**

## 방어

- 보정한 칸이 카테고리 합계에 들어가는가 (합성 회귀 데이터로 확인)
- 수면 보정이 "오늘의 수면" 에 들어가는가 (합성 회귀 데이터로 확인)
- **검사가 진짜 잡는가를 시험했다** — rules.yaml 에서 `sleep` 을 빼 보고, 새 파일이
  원본을 직접 읽게 해 보고, 둘 다 잡히는 것을 확인한 뒤 되돌렸다
