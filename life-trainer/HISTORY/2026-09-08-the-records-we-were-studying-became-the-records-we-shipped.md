# 재료로 쓴 실기록이 **저장소에 실려 나갔다**

- **날짜**: 2026-09-08
- **깨진 가정**: **"측정값이니 그대로 적는 것이 정확하다."**
  정확했다. 다만 그 정확함이 필요한 곳은 **동작을 재현하는 데**지 사이트 이름에 있지 않았다.

## 무엇이 올라가 있었나

사용자가 물었다 — *"개인 방문기록 같은 거 혹시 남아있어?"* 추적하니 세 갈래였다.

| 어디 | 무엇 |
|---|---|
| `docs/design/mockups/data.js` | 2026-08-19 실기록. 고유 창 제목 11개 — 학교 포털·신청 작업, 비공개 프로젝트 이름 셋, SSH 호스트 셋 |
| `docs/design/shots/redesign-v2-{desktop,dark}.png` | 다른 날의 "오늘의 기록" 패널. 대화 제목·소모임 이름·게임 |
| 문서·테스트 픽스처 여러 곳 | 실제 방문 사이트·게시글 제목·**게임 계정명**, 그리고 사용자가 실제로 던진 검색 질의 |

전부 **비공개 저장소에 push 된 상태**였다. 유출은 아니지만 남길 이유가 없었다.

## 왜 이렇게 됐나 — 재료와 산출물이 같은 것이었다

이 프로젝트는 **사람의 실생활이 유일한 데이터셋**이다. 그래서 디버깅할 때 본 값이
곧 문서에 적을 값이고, 시안을 만들 때 쓴 데이터가 곧 실기록이었다.
합성 데이터(`collect/synthetic.py`)가 **있었는데도** 쓰지 않았다 —
"진짜 데이터라야 시안이 진짜 같다" 는 생각이 그 자리를 이겼다.

## 수정

- 목업 데이터의 창 제목·앱을 `collect/synthetic.py` 어휘로 교체.
  **가명을 새로 짓지 않았다** — 같은 결정을 두 곳에서 하면 한쪽만 낡는다.
  카테고리·시각·슬롯은 그대로라 시안 색과 배치는 한 픽셀도 안 변한다
- 스크린샷 2장은 편집이 아니라 **다시 찍었다.** 실 DB 가 아니라 `lt synth` 로 만든
  임시 DB 에 웹을 띄워 원본과 같은 1440×1600 으로 촬영
- 이력을 다시 썼다 (`git filter-repo`) — 옛 블롭 3개를 들어내고, 문서에 박힌
  문자열은 예시값으로 치환. **force push 후 새로 clone 해서 확인**했다

## ★ 지운 것으로는 재발을 못 막는다

그래서 `operate/tools/check-privacy.sh` 를 만들어 `check-fast`(=pre-push)와 CI 에 걸었다.

**이 검사기의 제일 어려운 제약은 "검사기 안에 개인정보를 적지 않는 것"이었다.**
막을 값을 목록으로 적으면 그 목록이 곧 개인정보이고, 그게 저장소에 올라간다.
그래서 값이 아니라 **모양**으로 잡는다 — 실제 기록에만 나타나고 예시값에는 없는 형태:

```
[SSH: <호스트>]              예시는 [SSH: host]
op.gg/summoners/kr/<계정>    예시는 .../example
youtube.com/watch?v=<id>     예시는 %08d · x
m.<도메인>                    예시는 m.example-forum.com
```

꼭 막아야 하는 낱말은 `private-terms.local.txt` 에 적는다 — `.gitignore` 대상이다.

### 규칙 하나를 넣었다 뺐다

*"URL 경로의 8자리 이상 숫자 = 실제 글 id"* 를 넣었더니 공공데이터 API 데이터셋 id,
GPU 장치 경로(`17000000.gpu`), 1GiB 상수(`1073741824`)까지 **9건이 울었다.**
정상 내용에 우는 규칙은 검사기 전체를 꺼지게 만든다 (저장소 규칙 §1) — 걷어냈고,
그 오탐 예제들을 `must-pass.md` 에 넣었다. 이 규칙이 잡던 진짜 사건은 `m.<도메인>` 이
이미 잡는다.

## 곁가지 — 측정이 조용히 틀렸다

규칙을 정하기 전에 *"현재 트리 적중 0건"* 을 재고 도입했는데, 그 측정이 **무효였다.**
`grep -P` 와 `-E` 를 같이 줘서 `conflicting matchers` 로 죽었고, 죽은 출력을 0건으로
읽었다. 자기시험(`--self-test`)이 *"must-fail 을 못 잡는다"* 로 그걸 잡았다 —
**검사기에 시험지를 붙인 것이 검사기 자신의 버그를 잡았다.**

## 교훈

**합성 데이터를 만들어 두는 것과 그것을 쓰는 것은 다르다.** `synthetic.py` 는
처음부터 있었고 어휘도 충분했다. 없어서 못 쓴 게 아니라, 실기록이 눈앞에 있어서 안 썼다.

같은 부류를 어디서 의심하나 — **디버깅하며 본 값을 그대로 문서에 옮기는 순간.**
그 순간에는 "정확히 적는 것" 처럼 보인다.

## 두 번째 공개 전 감사

첫 정리 뒤 범위를 넓혀 다시 보니 비밀키는 없었지만, 서로 조합하면 생활 패턴을
재구성할 수 있는 기록이 더 있었다.

- 재생 곡·아티스트 메타데이터와 날짜별 미디어 이용량
- 게임·브라우징·수면·잠금해제의 시각, 지속 시간, 횟수, 순위
- 가족 일정과 학업 계획을 그대로 옮긴 프롬프트·테스트 설명
- 로컬 사용자명, 홈 경로, 사설망 주소 같은 개발 환경 식별값

공개본에서는 이런 값들을 제거하거나 `예시 일정`, `작업 A`, 상대적인 회귀 조건으로
바꿨다. 동작을 지키는 데 필요한 테스트 숫자는 합성값으로 남겼고, 실제 사용자에게
귀속되는 설명은 없앴다. 개인정보 검사는 재생 메타데이터·실측 행동량·시각 결합·홈
경로·사설망 주소 형태까지 검사하도록 넓혔다.

이 변경도 현재 파일만 고친 것으로 끝내지 않았다. 과거 커밋의 해당 문서·문자열을
함께 정리하고, 작성자와 커미터 메일은 GitHub noreply 주소로 통일한다. 재작성 전 묶음은
저장소 밖의 권한 제한 파일로만 보관하며 공개 원격에는 올리지 않는다.
