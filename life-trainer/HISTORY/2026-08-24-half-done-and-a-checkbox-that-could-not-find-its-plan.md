# 절반만 완료 처리하고 성공했다고 답했다 (+ 웹 체크박스가 자기 계획을 못 찾았다)

한 화면에서 두 버그가 같이 드러났다. 원인은 다르지만 **둘 다 "에이전트가 만든 계획"
이 기존 가정 밖에 있어서** 나왔다.

## ① `/done 2 3` 이 2번만 바꾸고 성공했다고 답했다

- **발견**: 사용자가 어제 목록을 보고 "2번 3번 완료처리해줘" 라고 했다.
  답변은 완료됐다고 나왔는데, 실제로는 하나만 바뀌었다. 게다가 **엉뚱한 날짜**였다.

- **증상**: 없다. 성공 메시지가 나온다. 사용자는 둘 다 됐다고 믿는다.

- **원인**: `_pick_instance` 가 `text.split()[0]` 으로 **첫 토큰만** 봤다.
  `/del` 은 `parse_index_list` 로 `3,5` 를 받는데 `/done` 은 하나만 받았고,
  **거부하지도 않았다.**

  ★ 이건 내가 이번 세션에 만든 코드다. **"조용히 다르게 동작하는 것"을 하루 종일
  잡아 놓고 정작 내가 만든 코드에 같은 것을 넣었다.**

- **수정**: `/del` 과 **같은 파서**(`commands_mod.parse_index_list`)를 쓴다.
  복수를 받고, **하나라도 없으면 아무것도 안 바꾼다** — 절반만 바꾸고 성공하는 것이
  최악이라서다. 제목에 숫자가 섞인 경우(`실습 3-1`)와 구분하려고
  `^\d+([,\s]+\d+)*$` 인 것만 번호 목록으로 본다.

- **방어**: 테스트 4개 (복수·쉼표·일부 누락·숫자 섞인 제목).

## ② 웹 체크박스가 `계획을 찾을 수 없습니다: id=133` 을 냈다

- **발견**: 위 ①로 잘못 완료된 계획을 사용자가 **웹에서 직접 해제하려다** 막혔다.

- **원인**: 웹 API 3개(`check`·`skip`·`delete`)가 `get_plan()` — **`plan`(반복
  템플릿) 테이블**에서 찾는다. 그런데 **슬래시·에이전트가 만드는 계획은 템플릿이
  없다** (`plan_id IS NULL`). 그 계획의 id 는 `plan_instance.id` 다.

  손으로 웹에서 만든 계획만 쓰던 동안에는 안 드러났다. **에이전트가 계획을 만들기
  시작하자 나왔다.**

- **수정**: 세 엔드포인트가 **양쪽을 다 본다.** 템플릿이 있으면 기존 경로,
  없으면 그날 인스턴스를 직접 조작한다. 없는 id 는 여전히 404.

- **방어**: 실기기 확인 (인스턴스 id 체크/해제 · 템플릿 id 체크 · 없는 id 404).
  단위 테스트는 아직 없다 — `tests/test_web.py` 에 넣을 자리다.

## 교훈

**새 입력원을 붙이면 기존 가정이 드러난다.** 웹 API 는 "계획은 템플릿에서 온다"를
전제로 만들어졌고, 그 전제는 사람이 웹으로만 만들 때는 참이었다. 에이전트가 계획을
만들자 거짓이 됐다. 코드는 한 줄도 안 바뀌었는데 **주변이 바뀌어서** 버그가 됐다.

그리고 ①은 더 부끄럽다 — **자기가 방금 배운 교훈을 자기 코드에 적용하지 않았다.**
오늘만 "조용히 절반만/다르게 동작하는 것"을 세 번 잡았는데(엉뚱한 계획 완료,
위임 강등, 날짜 누락), 네 번째를 내가 만들었다.
