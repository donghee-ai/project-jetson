# "오늘만 건너뛰기" 는 **아무도 안 연 날에만** 들었다

- **날짜**: 2026-09-07 (발견 2026-09-01, `docs/issues/0026`)
- **깨진 가정**: **"전개 후보에서 빼면 그 계획은 그날 안 뜬다."**
  이미 전개된 날에는 아무 일도 안 일어난다 — 그리고 **사람이 보는 날은 언제나 그쪽이다.**

## 증상

버튼을 누르면 `200 {"skipped": true}` 가 오고 **계획은 그대로 있었다.** 오류도, 경고도 없다.

## 원인 — 두 체계의 경계

`skip_plan` 은 `plan_skip` 행 하나를 넣는다. 그건 `materialize_day` 의 **후보 쿼리**에서
템플릿을 빼는 장치다. 그런데 `materialize_day` 는 **멱등**이라 이미 만들어진 인스턴스를
지우지 않는다 (그건 옳다 — 안 그러면 사람이 지운 계획이 10분마다 되살아난다).

```
아직 전개 안 된 날에 skip  →  인스턴스가 안 만들어진다   ✅
이미 전개된 날에 skip      →  plan_skip 행만 생기고 끝    ❌
```

**화면을 열었다는 것이 곧 전개다.** 그러니 사람이 누르는 순간은 항상 아래쪽이었다.

웹의 두 번째 갈래(`canceled` 로 바꾸는 길)도 못 탔다. 웹이 넘기는 `id` 는 **템플릿 id** 라
`get_plan()` 이 언제나 찾고, 그래서 `elif` 에 닿지 못한다.

## 수정 — 미래와 오늘을 같이 다룬다

`skip_plan` 이 두 가지를 한다:

1. `plan_skip` 행 — **미래**를 막는다 (원래 하던 일)
2. 그날 이미 있는 인스턴스를 **보관**한다 — `archived_at` + `skipped_at`

`skipped_at` 이 따로 있는 이유는 되돌릴 때다. `archived_at` 하나로는
*"건너뛰어서 보관된 것"* 과 *"사람이 지워서 보관된 것"* 이 구분되지 않아,
건너뛰기 해제가 **삭제 취소로 번진다.** 마이그레이션 011 이 그 열을 더한다.

> 감사 로그(`plan_instance_event.actor`)로 추론할 수도 있었다. 안 했다 —
> 추론은 마지막 이벤트가 무엇이냐에 따라 흔들리고, 읽는 쪽마다 규칙을 다시 써야 한다.
> **열이 하나 있으면 질의가 사실을 그대로 묻는다.**

## 방어

이슈에 적혀 있던 재현 절차가 그대로 테스트가 됐다. 다섯 개다:

| 지키는 것 | |
|---|---|
| 이미 전개된 날을 건너뛰면 화면에서 사라진다 | ← **이게 이 버그다** |
| 풀면 그대로 돌아온다 | |
| 해제가 **사람이 지운 것까지 되살리지는 않는다** | 반대쪽 경계 |
| 건너뛴 날이 다음 롤업에 **되살아나지 않는다** | 고치면서 깨기 쉬운 쪽 |
| 다른 날에는 영향이 없다 | |

## 왜 일주일을 살아남았나

테스트가 `skip_plan` 을 **함수 단위로** 검증하고 있었다.
*전개 → 건너뛰기 → 다시 조회* 라는 **사람이 실제로 하는 순서**를 밟는 것이 하나도 없었다.

## 교훈

**"막는 장치" 와 "지우는 장치" 는 다르다.** `plan_skip` 은 전자였는데 버튼 이름은
후자를 약속했다. 같은 부류를 어디서 의심하나 — **멱등하게 만든 생성기 옆의 취소 버튼.**
멱등성은 "다시 만들지 않는다" 는 뜻이지 "만든 것을 되돌린다" 가 아니다.
그 둘 사이에 취소가 떨어진다.
