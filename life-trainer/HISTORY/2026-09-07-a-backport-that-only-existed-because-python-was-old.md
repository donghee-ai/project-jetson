# 파이썬을 올리자 **옛 파이썬 때문에만 있던 것**이 없어져서 죽었다

- **날짜**: 2026-09-07 — 3.10.12 → 3.14.6 으로 올리다
- **깨진 가정**: **"백포트는 그냥 깔려 있다."**
  백포트는 *옛 파이썬이라서* 깔린 것이라, **올리면 사라진다.**

## 무슨 일이 있었나

올린 직후 `lt doctor` 가 22항목 → 17항목이 됐다.

```
[WARN] 에이전트   확인 실패: No module named 'tomli'
```

`tomli` 는 TOML 파서의 **백포트**다. 파이썬 3.11 부터는 표준 `tomllib` 이 있어서
`pyproject.toml` 이 이렇게 적어 뒀다:

```toml
"tomli>=2.0; python_version < '3.11'"
```

즉 **3.14 에서는 일부러 안 깐다.** 그런데 `agent/config.py` 가 이렇게 부르고 있었다:

```python
import tomli                      # ← 조건이 없다
...
return dict(tomli.load(fh).get("agent") or {})
```

`lifetrainer/config.py` 는 제대로 하고 있었다 — `tomllib` 을 먼저 보고 없으면 `tomli`.
**같은 판단을 두 곳에서 각자 하고 있었고, 한 곳만 맞았다** (이 저장소의 반복 실패 2번).

## 증상이 나쁜 쪽이었다

doctor 는 노란불로 알려 줬지만, 실제 경로에서는 `[agent]` 설정이 통째로 안 읽힌다.
그 아래 `except Exception` 이 *"설정이 깨졌다고 에이전트가 못 뜨면 안 된다"* 며
`{}` 를 돌려주게 돼 있어서, **조금 더 안쪽에서 터졌으면 조용히 기본값으로 돌았을 것**이다.

## 수정

정한 곳에서 받아 쓴다:

```python
from lifetrainer.config import tomllib
```

## 방어

`tests/test_config.py` — **백포트를 조건 없이 import 하는 곳이 없다.**
`lifetrainer/config.py` 하나만 예외다(파서를 정하는 당사자).

★ 이 검사는 파이썬을 올릴 때만 값을 하는 게 아니다. 백포트는 **언젠가 사라지는
의존성**이라, 조건 없이 부르는 자리는 그때마다 같은 방식으로 터진다.

## 교훈

**올리는 작업의 위험은 "새것이 안 된다" 가 아니라 "옛것이 사라진다" 쪽에 있었다.**
41개 의존성이 전부 같은 판으로 깔렸고 테스트도 전부 통과했다 —
문제는 **설치 목록에서 빠진 3개**(`tomli`·`exceptiongroup`·`tzdata`)였다.

같은 부류를 어디서 의심하나 — **`python_version <` 마커가 붙은 의존성.**
그 마커는 *"올리면 이게 없어진다"* 는 예고다.
