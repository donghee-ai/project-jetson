# HISTORY — 버그 기록

**버그를 고쳤으면 여기에 남긴다.** 기능 추가는 [../docs/progress/](../docs/progress/) 로 간다.

## 왜 따로 관리하나

이 프로젝트에서 나온 버그는 **거의 전부 테스트가 초록불인 상태에서 나왔다.**
렌더링해서 눈으로 보거나, 실기기를 붙이거나, 계산기에 넣어봐야 나오는 것들이었다.
그런 버그는 "고쳤다"로 끝내면 **같은 종류가 반복된다** — 원인의 층위가 코드가 아니라
가정에 있기 때문이다.

그래서 고친 코드가 아니라 **깨진 가정**을 기록한다.

## 규칙

- 파일명: `YYYY-MM-DD-짧은-슬러그.md`
- 사소한 오타·리팩터는 쓰지 않는다. **가정이 깨진 것**만 쓴다
- 아래 항목을 반드시 채운다:

```markdown
# 제목

- **발견**: 어떻게 드러났나 (테스트? 눈으로? 실데이터?)
- **증상**: 사용자가 보는 것
- **원인**: 무엇을 사실이라고 잘못 믿었나
- **수정**: 무엇을 어떻게
- **방어**: 재발을 막는 테스트/구조 (없으면 "없음"이라고 쓴다)
- **교훈**: 다음에 같은 부류를 어디서 의심할 것인가
```

## 반복되는 패턴 (읽을 것)

색인을 세로로 보면 같은 부류가 계속 나온다.

**1. 상류 문서를 사실로 믿었다.** — **세 번 나왔다.**

| 회차 | 읽은 것 | 붙인 것 |
|---|---|---|
| 1 | aw-server-**rust** 소스 ("이벤트는 겹치지 않는다") | 파이썬 aw-server |
| 2 | arXiv **공식 API 문서** | robots.txt 로 전 경로 차단된 실물 |
| 3 | aw-android **master** 소스 (API 키 설정 화면) | 배포된 **릴리스 APK** (그 화면이 없다) |

앞의 둘은 **구현체**가 달랐고, 셋째는 **시점**이 달랐다.
→ **문서는 구현이 아니다. 그리고 HEAD 는 배포물이 아니다.**
버전을 확인하는 것으로는 부족하다 — 3번은 버전이 맞았는데도 틀렸다.
**"내가 읽은 코드가 그 버전에 들어 있는가"** 를 따로 확인해야 한다.

**2. 같은 값을 여러 곳에서 각자 계산했다.**
하루 경계 하나를 바꾸자 세 곳이 조용히 어긋났다.
→ **파생값은 한 곳에서만 계산하고 나머지는 받아 쓴다.**

**3. 눈으로 확인할 수 있는 것을 계산하지 않았다.**
색각 분리는 계산 가능한데 눈대중으로 골랐다.
→ **계산 가능하면 계산한다.**

**4. 테스트가 통과하는 것과 동작하는 것은 다르다.**
그리기 순서, 격자 정렬, 하루 길이 — 전부 테스트 초록불이었다.
→ **산출물을 실제로 열어봐라.**

**5. 우리 사본을 원본 대신 읽고 진단했다.**
노트북 활동이 사라진 것을 보고 "afk 워처가 침묵했다"고 결론 내렸다.
근거는 **우리 DB** 였다. AW 서버에 직접 물어보니 침묵한 적이 없었고, 우리가 같은
이벤트의 짧은 판본을 저장하고 있었다. 하마터면 **창 이벤트 밀도로 가르는
휴리스틱**을 넣어 데이터 결함을 영구히 덮을 뻔했다.
→ **상류가 무엇을 말하는지 먼저 물어라.** 우리 저장소는 상류의 해석이지 원본이 아니다.
1번이 "문서 대 구현"이라면 이건 **"우리 사본 대 상류 실물"** 이고, 같은 부류다.

**6. 원본의 큰 숫자를 "영향"이라고 불렀다.**
`aw_event` 가 12배 부풀어 있고 정규화가 490분을 36분으로 줄이는 것을 보고
이슈 우선순위를 올렸다. **파이프라인 끝에서 재 보니 격자는 한 칸도 안 바뀌었다** —
그 아래에 흡수하는 층이 몇 개나 있었다.
→ **물을 것은 "원본이 몇 배냐"가 아니라 "사람이 보는 것이 뭐가 달라지나"다.**
같은 날 급조한 측정이 다섯 번 틀렸는데(쌍으로 세기·부동소수점 인접·동어반복 검사·
좌표 착각), **전부 자기 시험이 없는 일회용 질의였다.** 4번이 "테스트가 통과하는 것과
동작하는 것은 다르다"라면, 이건 **"내가 잰 것과 사람이 겪는 것은 다르다"** 이다.
