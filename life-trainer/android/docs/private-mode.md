# 프라이빗 모드 — 폰 구현 명세

> 2026-09-01 · 구현은 포크 저장소 [`donghee-ai/LT-Phone`](https://github.com/donghee-ai/LT-Phone), **윈도우에서** 진행
> 젯슨 쪽(테이블·API·롤업·웹 토글)은 **이미 들어가 있다.** 이 문서는 폰이 할 일만 적는다.

## 0. 먼저 5분만 재 보라 — 안 만들어도 되는 부류가 있다

**삼성 Secure Folder / 안드로이드 15 Private Space 는 별도의 안드로이드 프로필이다.**
[source.android.com](https://source.android.com/docs/security/features/private-space) 이
*"The sandboxed space is a separate Android profile"* 라고 적는다. 사용 통계는
**프로필별로** 저장되므로 메인 프로필의 워처는 그 안을 원리적으로 못 본다 —
**코드가 필요 없다.**

```
Secure Folder 안에서 앱을 5분 쓴다
  → 젯슨: sqlite3 data/lifetrainer.db \
      "SELECT app, title FROM aw_event WHERE ts > strftime('%s','now')-600"
  → 그 앱이 안 나오면: 그 부류는 끝났다. 타일은 다른 목적에만 필요하다
```

★ **공식 문서가 UsageStats 를 콕 집어 말하지는 않는다.** 그래서 재 본다.
결과를 이 문서 아래 "실측" 절에 적는다.

**타일과 대체 관계가 아니다.**
Secure Folder 는 *"이 부류는 아예 안 보이게"*, 타일은 *"지금 이 시간대를 통째로"*.
그리고 어느 쪽이든 **폰을 쓰고 있었다는 사실은 남는다** (unlock·AFK 워처가 화면
켜짐을 계속 기록한다). 가려지는 것은 *무엇을* 했는지다.

## 1. 왜 "워처를 멈춘다"로는 부족한가

**워처 넷의 수집 방식이 다르다. 그래서 필요한 장치도 다르다.**

| 워처 | 수집 방식 | 프라이빗에 필요한 것 |
|---|---|---|
| **앱 사용**(`UsageStatsWatcher`) | OS 로그를 **커서로 따라잡는다** ([plan.md](plan.md) §수집 주기) | **커서 건너뛰기.** 프로세스 정지는 선택 |
| **웹 URL**(`WebWatcher`) | 접근성 서비스 — **실시간** | **진짜로 정지.** 안 멈추면 그 자리에서 잡힌다 |
| **미디어 · unlock** | 실시간 | 〃 |

★ **앱이 OS 에게 "기록 멈춰"라고 할 수는 없다.** `UsageStatsManager` 는 읽기 전용이고
OS 는 시스템 전역으로 계속 적는다. 그래서 워처를 멈추기만 하면 **다시 켰을 때
커서가 그 구간을 통째로 따라잡는다.**

```
❌ queryEvents(옛날커서, now)          → 프라이빗 구간이 딸려 들어온다
✅ cursor = max(cursor, 프라이빗_끝)    ← 먼저 민다
   queryEvents(cursor, now)           → 그 구간은 아예 조회하지 않는다
```

**읽고 버리는 게 아니라 처음부터 안 읽는다** (skip, not backfill).
읽고 버리면 그 사이 폰 메모리·로그에 제목이 스친다.

★ 정직하게: **OS 로그 자체는 폰에 남는다.** 우리가 안 읽기로 하는 것뿐이라, 사용 통계
권한을 가진 다른 앱은 볼 수 있다. PC 의 AW 로컬 DB 와 같은 부류다.

## 2. 타일 (Quick Settings)

삼성 원 UI 기준 **상단 빠른 설정 패널**에 타일을 추가한다.

### 매니페스트

```xml
<service android:name=".privacy.PrivateTileService"
         android:icon="@drawable/ic_private"
         android:label="@string/private_tile_label"
         android:exported="true"
         android:permission="android.permission.BIND_QUICK_SETTINGS_TILE">
    <intent-filter>
        <action android:name="android.service.quicksettings.action.QS_TILE" />
    </intent-filter>
</service>
```

### 규칙 — 이걸 지켜야 타일이 안 죽는다

| | 무엇 | 왜 |
|---|---|---|
| `onStartListening()` | **로컬 상태만** 읽어 타일을 칠한다. 네트워크 금지 | 패널을 내릴 때마다 불린다. 여기서 HTTP 를 하면 패널이 버벅이고 Doze 에서 실패한다 |
| `onClick()` | **로컬을 먼저 뒤집고** 타일을 갱신한 뒤, WorkManager 로 젯슨에 통지 | 비행기 모드에서도 켜져야 한다. 서버 왕복을 기다리면 "눌렀는데 안 켜졌다"가 된다 |
| 상태 저장 | `SharedPreferences` 에 **`until_ts`(절대 시각, epoch 초)** | "남은 분"으로 저장하면 앱이 죽은 동안 시간이 안 흐른다 |
| 타일 라벨 | 켜짐이면 `프라이빗 12분` | 남은 시간을 안 보여주면 켠 것을 잊는다 — **조용한 손실이 이 기능의 유일한 실패 모드다** |

### 자동 만료

`until_ts` 를 **미리 박는다.** 열린 구간을 두면 앱이 죽었을 때 영원히 켜진 채가 된다.
`AlarmManager.setExactAndAllowWhileIdle` 로 `until_ts` 에 깨어나 워처를 되살린다.
알람이 안 울려도 워처가 **매 수집 때 `until_ts` 를 스스로 확인**하게 한다 (이중 방어).

## 3. 젯슨과 맞추기

### 엔드포인트

| | |
|---|---|
| 조회 | `GET /ingest/private` |
| 토글 | `POST /ingest/private` — `{"minutes": 60}` 또는 **`{"off": true}`** |

> ★ **키는 `off` 다. 예전에 이 표가 `end` 라고 적어 둔 채로 나갔다.**
> 서버는 `off` 만 봤고 나머지는 전부 "켜기"로 떨어졌으므로, 명세대로 만든 폰 타일이
> **끌 때마다 60분을 새로 켰다** (2026-09-03 실기기). 지금은 서버가 `end` 도 받고
> 모르는 본문은 400 을 돌려준다.

인증은 **기존 `LT1` HMAC 그대로**다 (`/ingest/aw` 와 같은 방식).
★ GET 은 본문이 없으므로 **`sha256("")` 을 서명한다.**

```
Authorization: LT1 <device>:<unix_ts>:<nonce>:<hex_hmac>
```

응답:

```json
{"active": true, "until_ts": 1788249600.0, "server_ts": 1788246000.0,
 "poll_sec": 15, "spans": [{"start_ts": ..., "end_ts": ...}]}
```

★ `until_ts` 는 **절대 시각**이다. "남은 초"가 아니다 — 폰이 젯슨을 못 만나도
자기 시계로 언제 워처를 되살릴지 알아야 한다.
`server_ts` 로 시계 차이를 보정한다 (`skew = server_ts − now`).

### 충돌 규칙 — **더 사적인 쪽이 이긴다**

```
until = max(로컬 until, 서버 until)
```

★ "최신이 이긴다"로 하면 **늦게 도착한 서버 응답이 방금 켠 프라이빗을 조용히 푼다.**
방향이 반대인 실패이고, 조용해서 더 나쁘다.

끄기는 예외다 — 사람이 명시적으로 끈 것이므로 `end` 통지는 즉시 반영한다.

## 4. 지연분 정리 — 앱이 자기 DB 에서 지운다

폰의 aw-server 는 **127.0.0.1 바인딩**이라 젯슨이 못 닿는다. PC 처럼
`DELETE /api/0/buckets/{b}/events/{id}` 를 젯슨이 대신 호출할 수 없다.

그래서 **앱이 한다.** 타일을 켠 시점과 워처가 실제로 멈춘 시점 사이(≤1주기)에
들어간 이벤트를 로컬에서 지운다.

- 구간에 **완전히 들어간 것만** 지운다. 걸친 이벤트를 통째로 지우면 프라이빗 밖의
  정상 시간까지 날아간다
- 걸친 이벤트의 제목은 **프라이빗을 켜기 전에 이미 보이던 것**이라 새로 새는 정보가 없다

## 6. 실측 — 만들기 전에 채운다

| 확인할 것 | 어떻게 | 결과 |
|---|---|---|
| Secure Folder 안이 `aw_event` 에 들어오나 | 5분 쓰고 젯슨에서 조회 | ✅ **안 들어온다** (2026-09-04) — 아래 |
| 워처를 멈췄다 켜면 그 구간이 딸려오나 | 워처 정지 → 5분 → 재개 → sync | ⬜ 미측정 |
| aw-android 의 aw-server 바인딩 (127.0.0.1 / 0.0.0.0) | `adb shell ss -lptn` | ⬜ 미측정 ([plan.md](plan.md) 도 미확인으로 적어 뒀다) |

★ 세 번째가 `0.0.0.0` 이면 젯슨이 폰 AW 도 직접 정리할 수 있다 — §4 가 필요 없어진다.
**그런데 그건 폰이 로컬 네트워크에 열려 있다는 뜻이기도 하다.** 확인 결과에 따라
정리 경로가 갈리므로 먼저 잰다.

### Secure Folder — 안 들어온다 (2026-09-04 실측)

**Secure Folder 안에서 쓴 앱은 `aw_event` 에 하나도 안 나온다.** 그 시간은
**자리비움으로 찍힌다.** §0 이 문서를 근거로 예상한 그대로다 — 별도 프로필의
사용 통계는 메인 프로필 워처가 원리적으로 못 본다.

**그래서 이 부류는 앱 작업 없이 끝난다.** "특정 앱을 아예 안 보이게" 하려고 코드를
쓸 이유가 없다. Secure Folder 에 넣으면 된다.

| | 뜻 |
|---|---|
| 가려지는 것 | **무엇을 했는지** — 앱 이름·제목·URL 이 통째로 안 온다 |
| 남는 것 | **폰을 만졌다는 사실**… 이 아니라 지금은 **자리비움**이다 (아래) |

> ★ **§0 이 적어 둔 *"어느 쪽이든 폰을 쓰고 있었다는 사실은 남는다"* 는 지금 안 맞는다.**
> 그 문장은 unlock·AFK 워처가 화면 켜짐을 계속 적는다는 전제였는데, 실제로는
> **자리비움과 구분이 안 된다.** 화면을 안 켠 것과 Secure Folder 를 쓴 것이 같은 모양이다.
>
> 그리고 이 측정 구간에 **unlock 워처가 죽어 있었다** (`lt doctor`
> 워처 침묵이 잡았다). 그러니 *"unlock 은 그래도 켜짐을 적었을 것"* 은 **아직 확인 못 한
> 상태다** — 워처가 살아난 뒤 다시 재야 갈린다. 실패와 미확인은 다르다.

**타일(§2)은 그대로 필요하다.** 대체 관계가 아니다 — Secure Folder 는 *"이 앱들은 아예"*,
타일은 *"지금 이 시간대를 통째로"* 다.
