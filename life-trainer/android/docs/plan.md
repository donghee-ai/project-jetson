## 0. 이번에 소스로 확인한 것 (조사 문서 갱신분)

조사 문서는 저장소 이슈와 공식 문서만 읽은 것이었다. 이번에는 **aw-android 소스를
직접 읽었다.** 그 결과 §6 의 미확인 3건 중 하나가 풀리고, 새 사실이 나왔다.

| 조사 문서 | 소스 확인 결과 |
|---|---|
| §6-3 버킷 타입 판별 "실물 확인 필요" | ✅ **그대로 동작한다.** 버킷 ID 는 `aw-watcher-android` (문자열 `window` 없음) 지만 타입이 **`"currentwindow"`** 라서 `bucket_type()` 의 메타 폴백이 `window` 로 잡는다 |
| §6-2 "안드로이드엔 AFK 워처가 없다" | ✅ **맞다.** `watcher/` 8개 파일 어디에도 afk 없음. 대신 **`aw-watcher-android-unlock`** (타입 `os.lockscreen.unlocks`) 이 있다 — 잠금해제 *시점*이지 활동 *구간*이 아니다 |
| §6-1 `base_url` 단일값 | ⚠️ **당장은 안 건드려도 된다.** Syncthing 은 파일 경로라 REST 를 안 쓴다. 폰의 5600 을 직접 폴링할 때만 필요 |

### 새로 안 것

| | |
|---|---|
| **워커 구조가 이미 있다** | `workers/` 에 `EventParsingWorker`·`NotifyWorker`·`SyncWorker`. 우리 익스포터도 여기 한 파일로 들어간다 |
| **FileProvider 선언돼 있다** | `${applicationId}.provider`, `exported=false`, `grantUriPermissions=true` |
| ★ **`allowBackup="true"`** | 앱 데이터가 **구글/삼성 백업으로 클라우드에 올라간다.** 이 프로젝트 전제("데이터는 기기 밖으로 안 나간다")와 정면으로 충돌한다 |
| ★ **수집 주기가 1시간** | `UsageStatsWatcher` 가 `AlarmManager.INTERVAL_HOUR` + **`setInexactRepeating`**. `EventParsingWorker`(PeriodicWork 24시간, 자정 시작)는 **놓친 것을 메우는 백스톱**이지 유일한 경로가 아니다 |
| **접근성 기반 URL 추출이 있다** | `WebWatcher`(AccessibilityService) + `UrlExtraction` + `BrowserSessionTracker`. 브라우저 주소를 읽는다 |
| **포트 5600** | `RustInterface` 가 `ServerSocket(5600)` 로 가용성만 검사. **바인딩 호스트(127.0.0.1 vs 0.0.0.0)는 Rust 쪽이라 미확인** |
| **빌드가 무겁다** | Rust nightly + Android NDK + node/npm + 서브모듈 재귀 초기화 |
| **CLA 없어 보임** | CONTRIBUTING·CLA 언급을 못 찾았다. **없다고 단정하진 않는다** |

**★ 수집 주기의 의미**: 폰 데이터는 **한 시간 남짓 늦게 도착한다.**

정확도는 주기와 무관하다 — 안드로이드 OS 가 사용 통계를 **자체적으로 계속 기록**하고
있고, 워처는 `queryEvents(마지막으로_읽은_시점, MAX)` 로 **커서를 들고 따라잡는다**.
하루에 한 번 읽어도 그 안에 초 단위 타임스탬프가 전부 들어 있다. 우리 노트북
`collect/aw_sync` 도 같은 구조(커서 + 겹쳐 읽기)다. **그래서 "계속 주고받는" 설계가
필요 없다.**

늦는 것은 **도착**이다. `setInexactRepeating` 이라 Doze 에서 더 밀리고, 그동안
**"지금 뭐 하고 있나" 실시간 답변에는 폰이 안 뜬다.** 5분으로 내리는 것은 정확도가
아니라 이 지연을 줄이는 작업이다. 그리고 늦게 도착하는 이상 **재롤업은 어차피 필요하다**
(우리 하루 경계가 06:00 이라 하루 후반부가 다음 날 들어올 수 있다).

## 1. 포크를 뜰 것인가 — 먼저 확인, 나중에 결정

**확인 전에 포크를 뜨지 않는다.** 이 프로젝트 실패 1번이 "조사 문서를 사실로 믿었다"이고,
포크는 되돌리기 비싼 쪽이다. 아래 게이트로 갈린다.

### ★ 2026-08-19 실측 — 두 갈래 다 막혔다. **포크가 필요하다**

v0.14.0dev20260723(공개된 최신 APK)로 실제로 해본 결과:

| 확인 | 결과 |
|---|---|
| `localhost:5600` 이 열리는가 | ✅ 열린다 (adb 포워딩으로 붙었다) |
| REST 로 버킷·export 를 받는가 | ❌ **API 키를 요구한다.** 키 설정 화면(`AuthSettingsActivity`)은 **master 에만 있고 공개 APK 엔 없다** (설치본 액티비티는 `.MainActivity` 하나뿐) — 더 최신 APK 로 갈아타서 풀 수 있는 문제가 아니다 |
| 앱 내 Export 가 파일을 만드는가 | ❌ **앱이 죽는다.** `ActivityNotFoundException: No Activity found to handle Intent { act=VIEW dat=blob: }`. WebView 에 `DownloadListener` 가 없어 `blob:` 다운로드가 외부 인텐트로 새고 받을 앱이 없다. **#228 이 "조용한 실패"에서 "크래시"로 악화됐다.** blob 자체는 정상 생성되므로 **전달만 실패**한다 |

키를 얻으려 시도한 것과 결과: `run-as`(릴리스 빌드라 불가) · 외부 저장소 설정 파일(없음) ·
logcat(안 찍힘) · `Origin`/`Referer`/`X-Requested-With`/User-Agent 위장(전부 401) ·
WebView 원격 디버깅(소켓 없음). **앱이 `Authorization` 헤더를 직접 주입한다.**

인증 없이 되는 것은 `/api/0/info` 와 정적 파일뿐. 거기서 얻은 것:
`hostname="localhost"` · `version=v0.14.0 (rust)` · `device_id`.
★ hostname 이 기기명이 아니라 `localhost` 이므로 **`lt import` 에 `--device` 를 반드시 명시**한다.

**결론: Termux 우회도 REST 도 못 쓴다.** 포크의 **첫 작업이 Export 크래시 수정**이 되고,
그게 고쳐지면 API 키 없이도 표본이 나온다.

**F2(활동 판정)와 `allowBackup=false` 는 어느 쪽이든 남는다.** 다만 F2 는 앱이 아니라
우리 쪽에서 푸는 선택지가 있다(§3).

## 2. 확장 항목

### F0. ★ Export 크래시 수정 (**첫 작업, 몇 줄**)

`MainActivity` 의 WebView 에 `setDownloadListener` 를 붙여 `blob:` 를 앱이 직접 파일로
저장하게 한다. 이슈 #228 이 지목한 지점이다. **이게 고쳐지면 API 키 없이도 표본이 나오므로,
막힌 Phase 0 이 풀린다.** 기존 파일 수정이지만 몇 줄이고, **업스트림 PR 감**이다
(실측으로 크래시 스택트레이스까지 확보했다).

### F1. 자동 내보내기 — `workers/ExportWorker.kt` (**새 파일**)

수동 버튼은 사람 손이 매일 간다. 조사 문서 §4-2 의 미확인 항목이 이것이다.

- `RustInterface.getEventsJSON(bucket_id, limit)` 로 버킷별 이벤트를 뽑아
  SAF 로 고른 폴더(= Syncthing 폴더)에 하루 한 파일로 쓴다
- 파일명 `aw-export-{device}-{YYYY-MM-DD}.json`, **지난 날짜는 불변, 오늘 것만 갱신**
- ★ **원자적 쓰기**: `.tmp` 로 쓰고 rename. 안 그러면 **Syncthing 이 반쯤 쓰인 파일을 옮긴다**
- 주기: WorkManager 최소 15분. Doze 에서 더 늦어져도 **문제 없다** — 데이터는 폰에 쌓여
  있고 타임스탬프는 정확하다

**기존 파일 수정은 `BackgroundService` 에 워커 등록 한 줄뿐.**

### F2. 폰의 "활동" 판정 — ★ **실데이터를 보고 결정한다**

폰엔 afk 가 없어서 그대로 두면 폰 활동이 전부 `away` 로 분류된다. 두 갈래인데
**지금 정하지 않는다.**

| | 방법 | 값 | 비용 |
|---|---|---|---|
| **(a) 앱에서** | 화면 on/off 리시버로 `aw-watcher-android-afk` (타입 `afk`, `data.status ∈ afk/not-afk`) 를 합성 | 우리 파이프라인 **무변경** — 폰이 노트북과 같은 언어를 쓴다 | 포크 필수. 화면 켬 ≠ 사용 중(거치·영상) |
| **(b) 우리 쪽에서** | `device.kind='phone'` 이면 afk 없이 **window 이벤트 존재 = active** | 포크 불필요 | 롤업에 기기별 분기가 생긴다 |

판단 근거는 **실데이터에만 있다**: 세션 이벤트가 없는데 화면은 켜져 있는 구간(홈 화면·
잠금화면)이 얼마나 되는지, 세션 duration 이 백그라운드 전환까지 늘어나는지. Phase 1 에서 잰다.

> (a) 를 택하면 화면 리시버는 **매니페스트로 선언할 수 없다**(`SCREEN_ON/OFF` 는 런타임
> 등록 전용). 이미 있는 `BackgroundService` 에 붙인다.

### F4·F5. 제목 채우기 → [phone-titles.md](phone-titles.md)

폰이 주는 `title` 은 **앱 이름**이라 유튜브를 두 시간 봐도 `"YouTube"` 뿐이다.
미디어 워처는 08-22 에 붙어 **45%** 를 채우고 있고(전환만 보고해서 나머지가 빈다),
웹 워처는 `title` 을 **한 번도** 안 채운다. 실측·원인·고칠 지점은 별도 문서에 있다.

### F3. 프라이버시 수정 (**포크 시 무조건**)

| | |
|---|---|
| `allowBackup="true"` → **`false`** | 데이터 원칙. 매니페스트 한 줄 |
| `WebWatcher`(접근성) | **켜지 않는다.** 브라우저 URL 을 읽는다. 기본 꺼짐(수동 권한)이지만 명시적으로 결정하고 기록한다 |
| `MediaWatcher`(알림 리스너) | 같음 |

### 우리 쪽 (Life Trainer, MPL 무관)

1. **`lt import --from <dir>`** — Syncthing 수신 폴더의 JSON 을 읽어 넣는다.
   `raw_event` PK 가 `(bucket_id, ts)` 라 **재실행이 안전하다**(중복 삽입 없음)
2. **device 등록** — `kind='phone'`, 버킷을 `device_id` 에 연결
3. **재롤업** — 폰 데이터가 늦게 도착하므로 **과거 날짜 롤업을 다시 돌려야 한다**
4. **중재 로직** — 폰과 노트북이 동시에 활동일 때 누가 이기는가. **아직 설계 없음**

## 3. ★ MPL-2.0 주의사항

### 확인한 것

- 저장소 LICENSE = **Mozilla Public License 2.0** (GitHub 표시도 MPL-2.0)
- **소스 파일에 라이선스 헤더가 없다** (`BackgroundService.kt` 상단은 곧바로 `package`).
  LICENSE 전문에 Exhibit B 문구가 있지만 그건 **MPL 표준 전문에 항상 들어있는 템플릿**이고,
  파일에 부착되지 않았으므로 **"Incompatible With Secondary Licenses" 는 적용 안 된 상태**다

### 지켜야 할 것

| # | 규칙 | 우리의 대응 |
|---|---|---|
| 1 | **의무는 "배포" 시점에 생긴다.** MPL 엔 AGPL 같은 네트워크 조항이 없다 | 내 폰에만 설치하면 공개 의무 없음. 단 [opensource-plan.md](../../../docs/plans/opensource-plan.md) 가 공개를 계획하므로 **결국 발생한다** — 처음부터 준수해서 만든다 |
| 2 | **파일 단위 카피레프트.** 고친 파일만 MPL 로 남으면 된다 | ★ **"기존 파일 수정 최소화, 기능은 새 파일로."** 라이선스 경계·업스트림 리베이스·리뷰가 동시에 쉬워지는 유일한 규칙이다 |
| 3 | **§3.2** 실행형(APK)을 배포하면 소스 제공 방법을 알려야 한다 | GitHub 포크를 공개로 두고 README 에 명시 |
| 4 | **§3.3** 다른 라이선스와 결합 가능(Larger Work), MPL 파일만 MPL 유지 | ★ **포크를 이 저장소에 넣지 않는다.** 별도 저장소 + **JSON 파일 교환**만 하므로 파생저작물 논쟁 자체가 안 생긴다 — Syncthing 경로의 부수 효과다 |
| 5 | **§3.4** 저작권·라이선스 고지를 제거하지 않는다 | LICENSE 파일 유지. 우리가 **추가하는 새 파일에는 Exhibit A 헤더를 넣는다**(경계를 명시적으로) |
| 6 | **§2.3 상표는 라이선스에 포함되지 않는다** | 배포한다면 **"ActivityWatch" 이름·로고 사용 불가.** 포크명·앱 아이콘 교체 |
| 7 | applicationId `net.activitywatch.android` | **변경 필수** — 라이선스 때문만이 아니라 원본과 **공존 설치**하려면 필요하다 |
| 8 | **§5** 위반 시 권리 종료(치유 기간 있음) | 위 1~7 을 체크리스트로 커밋에 남긴다 |

### 아직 확인 안 한 것 (포크 전에 볼 것)

- `aw-server-rust` 서브모듈 · `aw-webui` 의 **각각의** 라이선스 (MPL 일 가능성이 높지만 **확인 전엔 모른다**)
- 번들되는 서드파티(cargo crates, npm 패키지)의 라이선스 — 배포 시 고지 대상
- **CLA 유무** — 업스트림 PR 을 낼 거라면 먼저 확인

### 포크 vs 업스트림 기여

F0(Export 크래시)·F1(자동 내보내기)은 **업스트림에도 가치가 있다** — #228 에 대해 **크래시 재현 절차와 스택트레이스를 붙일 수 있다**. #221(Sync 접근성)도 관련.
다만 순서는 **포크에서 먼저 동작시키고, 쓸 만하면 PR** 이다. 리뷰를 기다리며 막히지 않기
위해서다. F2 는 우리 슬롯 스키마에 맞춘 것이라 업스트림 취향과 다를 수 있다.

## 4. 기술 주의사항

| | 위험 | 대응 |
|---|---|---|
| ★ **빌드 환경** | 젯슨은 arm64 + **가용 4.5GB**(llama-server 6.7GB + 임베딩 1.8GB). 08-23 ctx 축소로 늘었지만 Gradle·NDK·Rust·npm 3스택 동시 빌드는 여전히 무리다 | **Windows PC 에서 빌드한다** (`config/lifetrainer.toml` 의 그 PC) |
| **서명 키** | 자체 키로 서명 → 원본 위에 덮어쓰기 불가. **키를 잃으면 재설치(=폰 데이터 삭제)** | 키를 만들자마자 백업. 원본과 다른 applicationId 로 공존 설치 |
| **배터리 관리** | 삼성 스킨은 백그라운드 앱을 공격적으로 죽인다. 워처가 죽으면 **데이터가 조용히 빈다** | 배터리 최적화 예외 등록. **빈 구간을 감지하는 점검을 `lt doctor` 에 넣는다** |
| **권한** | `PACKAGE_USAGE_STATS` 는 설정에서 수동 허용하는 특별 권한. 재설치하면 다시 꺼진다 | 설치 절차에 명시 |
| **Syncthing 방향** | 양방향이면 젯슨에서 지운 파일이 **폰에서도 지워진다** | 폰 = **Send Only**, 젯슨 = **Receive Only** |
| ★ **겹침 재발** | 폰+노트북 동시 활동으로 **하루 합이 24시간을 넘을 수 있다.** [08-17 사고](../../HISTORY/2026-08-17-aw-overlap-inflation.md)와 **같은 부류**이고 합성 데이터로는 원리적으로 못 잡는다 | 실기기 데이터로만 검증. **하루 합 ≤ 24h 를 assert** |
| **늦게 오는 데이터** | 수집이 1시간 주기(Doze 에서 더 밀림) + 06:00 하루 경계 → 하루 후반부가 다음 날 도착 | import 후 **해당 날짜 재롤업**. 롤업이 멱등인지 확인 |
| **테스트 통과 ≠ 동작** | 이 프로젝트 실패 4번 | 마지막 검증은 **타임라인 PNG 를 눈으로 본다** |

## 5. 순서

| Phase | 무엇 | 코드 | 게이트 |
|---|---|---|---|
| **0** | 앱 설치 → 권한 → 배터리 예외 → **하루 대기** | 0줄 | 데이터가 쌓이는가 |
| **0.5** | Termux 로 `localhost:5600` 확인 + 내보내기 버튼 확인 | 0줄 | **포크 여부가 여기서 갈린다** |
| **1** | 실데이터를 젯슨으로 한 번 옮겨 `lt import` + 롤업 | 우리 쪽만 | 화면 켬 vs 세션 공백 실측 → **F2 (a)/(b) 결정** |
| **2** | (필요 시) 포크 — `ExportWorker` 추가, `allowBackup=false`, 이름·appId 변경 | MPL 준수 | 3일 무인 동작 |
| **3** | Syncthing 상시 연결 + `lt import` 자동화 | 우리 쪽 | 빈 구간 없이 들어오는가 |
| **4** | 폰↔노트북 **중재 로직** | 우리 쪽 | 하루 합 ≤ 24h |

**Phase 1 이 끝나면 폰 데이터의 가치를 다시 판단한다.** 조사 문서 §7 대로, 5분 미만 전환은
[`absorb_short_switches`](../../lifetrainer/rollup/rollup.py) 가 이미 처리한다. 폰 데이터는
**5분 이상 공백의 *이유*** 를 구분하는 데만 쓰인다. 그 값이 Phase 2~4 의 비용을 넘는지는
실데이터를 본 뒤에 정한다.
