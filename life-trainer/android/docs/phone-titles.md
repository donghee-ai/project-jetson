# 폰에서 **무엇을** 했는지 — 제목을 채우는 길

> 2026-08-25 작성. 공개본에서는 개인 재생 기록과 집계값을 제거했다. 아래 수치는
> 동작을 설명하기 위한 **익명 회귀 예시**이며, 실제 값은 §6의 쿼리로 로컬에서 다시 뽑는다.
> **안드로이드 API 쪽 제안은 소스로 확인하지 않았다** — 어느
> 것이 확인된 사실이고 어느 것이 가설인지 각 항목에 표시했다.

폰은 "어떤 앱을 켰나"는 알려주지만 "무엇을 했나"는 잘 안 알려준다. 노트북은
창 제목이 그대로 오는데(`Code.exe — rollup.py`), 안드로이드 앱 세션이 주는
`title` 은 **앱 이름**이다. 유튜브를 두 시간 봐도 전부 `"YouTube"` 다.

지금 두 갈래가 서로 다른 상태에 있다.

| | 워처 | 지금 | 막는 것 |
|---|---|---|---|
| **재생 중인 것** (영상·곡) | `aw-watcher-android-media` | **45%** 붙는다 | 워처가 *구간*이 아니라 *전환*을 보낸다 |
| **웹 페이지** | `aw-watcher-android-web` | URL ✅ / **제목 0%** | 워처가 `title` 을 안 채운다 (권한은 08-25 해결) |

---

## 1. 재생 중인 것 — 일부가 빈다

미디어 워처가 붙은 뒤에도 일부 유튜브 앱 세션에는 제목이 붙지 않고 앱 이름만 남았다.
개인별 세션 수·비율은 공개본에 싣지 않는다.

**"짧아서 아무것도 안 틀었다"가 아니다.** 세션 길이를 비교하면 오히려 안 붙는 쪽이
더 길다:

길이 분포를 비교해 보니 제목 없는 세션이 특별히 짧지 않았다. 따라서 짧은 재생을
버린 결과로 설명할 수 없었다.

### 무엇이 오고 있나 (확인됨)

```json
{"album":"예시 앨범","app":"com.google.android.apps.youtube.music",
 "artist":"예시 아티스트","package":"...","state":"playing","title":"예시 곡"}
```

메타데이터는 완전하다. 문제는 **언제 보내느냐**다. 공개용 축약 분포:

```
0초(상태 전환)  다수
1분 미만        다수
1분 이상        소수
```

**워처는 재생 구간이 아니라 상태 전환을 보고한다.** 그래서 앱 세션 중간에
`playing`/`paused` 전환이 한 번도 없으면 — 이미 재생 중이던 것을 계속 보거나,
Doze 에서 깨어나 이어보거나 — 얹을 후보가 없다.

### 우리 쪽에서 먼저 해 봤다 — **더 나빠졌다**

전환 이벤트를 상태 기계로 읽어 `playing` → 다음 전환까지를 재생 구간으로 복원해
봤다. 젯슨 쪽만 고치면 되니 제일 싸다.

```
현재 규칙 (겹침 + 세션 안 전환)   기준
상태 기계로 구간 복원              더 낮음     ← 내려갔다
```

내려간 이유는 `paused` 전환을 버리기 때문이다. 지금 규칙은 "세션 안에서 일어난
전환이면 그 곡이 재생된 것"으로 보는데(`rollup._title_from_media`), 그게 실제로는
더 많이 맞는다. **재 보고 나빠서 접었다** — 붙여 보고 좋아졌다가 아니다.

**결론: 젯슨 쪽에는 남은 수가 없다. 워처를 고쳐야 한다.**

### F4. 미디어 워처가 **구간**을 보내게 한다 (포크, 가설)

지금은 알림 리스너가 이벤트를 받을 때만 기록하는 것으로 보인다(★ 소스 확인 필요).
`MediaSessionManager.getActiveSessions()` 로 **현재 살아 있는 세션을 주기적으로
훑으면** 전환을 놓쳐도 상태가 남는다.

- `MediaController.Callback` 등록 + 워처 시작 시 **이미 열려 있는 세션을 한 번 훑는다**
  (지금 놓치는 "이미 재생 중이던 것"이 여기서 잡힌다)
- `state == PLAYING` 인 동안을 **하나의 이벤트로** 보낸다 (duration > 0)
- 곡이 바뀌면 끊고 새로 연다

### F4-b. 버킷 타입 — ~~바로잡는다~~ **그대로 둔다** (2026-09-04 재판정)

```
aw-watcher-android-media   type='android'    ← 앱 세션과 같은 타입
```

타입이 같아서 롤업이 **버킷 이름의 `-media` 접미사로** 가른다
([`rollup._bucket_kind`](../../lifetrainer/rollup/rollup.py)).

> ⚠️ **이 절은 원래 "워처 등록을 `type='media'` 로 바꾸면 된다"고 적혀 있었다. 틀렸다.**
>
> 1. **폰은 이미 그렇게 보내고 있다.** 앱은 `type="media.playback"` 으로 버킷을 만든다.
>    젯슨 `bucket_type()` 은 **메타 타입을 안 보고 버킷 ID 문자열로만** 가르므로
>    폰을 고쳐도 아무것도 안 바뀐다 — 고칠 곳이 폰이 아니었다.
> 2. **젯슨에서 `media` 분기를 더하면 깨진다.** `device_kind_for()` 의
>    `_PHONE_BUCKET_TYPES = {"android","unlock"}` 에 `media` 가 없어 **폰이 `laptop` 으로
>    등록될 수 있다.** 그리고 그 부재를 지키는 테스트가 이미 둘 있다
>    (`test_bucket_type_android_media_is_android` — 이중 계산이 없음을 실측으로 확인해 뒀다).
>
> → **`docs/issues/w-0028` 로 내렸다.** 고칠 수 있지만 재 보니 지금이 낫다.

## 2. 웹 페이지 제목 — **URL 은 살아났고, 제목만 안 온다**

### 08-25 에 두 번 고쳐 쓴 절이다

처음엔 "3일 동안 9건, `title` 이 비어 있다"고 적었다. 다시 재 보니 9건은 **08-22 에
20초 동안** 튀고 끝난 것이었고, 진단이 "품질이 낮다"에서 "멈췄다"로 바뀌었다.
그리고 **사용자가 접근성 권한을 켜자 즉시 들어오기 시작했다** — 멈춘 원인은
워처 코드가 아니라 **꺼진 권한**이었다.

```
14:22:43 ~ 14:23:32   폰 설정 앱 (권한 ON)
14:23:34              첫 이벤트. 이미 열려 있던 페이지를 346초짜리로 잡았다
14:29:20 ~ 14:30:46   네이버 → FM코리아. 11건
```

### 그런데 제목은 **여전히 0%**

새로 들어온 12건의 내역:

| | |
|---|---|
| `url` 채워짐 | **12 / 12** ✅ |
| `title` 채워짐 | **0 / 12** ❌ |

```
url='example-blog.net/제품-후기-매장-위치-연락처/'   title=''
url='m.example-forum.com/best/1234567'                                title=''
url='m.example-portal.com'                                                   title=''
url='Google 검색 또는 URL 입력'                                      title=''   ← 주소창 문구
```

**권한은 URL 을 살렸지 제목을 살리지 못했다.** 이것으로 두 문제가 깨끗이 갈렸다:

1. ~~워처가 멈췄다~~ → **권한. 2026-08-25 해결. 포크 불필요**
2. **`title` 이 안 채워진다** → 워처 코드. **F5 는 이것만 남는다**

주소창 문구(`"Google 검색 또는 URL 입력"`)가 URL 자리로 오는 것도 그대로다 —
9건 중 3건. 접근성 서비스가 주소창 노드의 표시 텍스트를 읽기 때문이고, 제목을
읽는 것과 같은 뿌리다.

### ★ URL 분류 규칙 6개가 이제 재료를 받는다

`config/rules.yaml` 에는 `match: {url: ...}` 규칙이 6개 있는데 — coding(github·
stackoverflow), entertainment(youtube·netflix), gaming(op.gg·인벤), research(arxiv),
communication(gmail), browsing(뉴스) — **08-25 이전까지 매칭될 대상이 9건뿐이었다.**
노트북에는 웹 버킷 자체가 없다(`aw-watcher-window` + `afk` 둘뿐).

권한이 켜진 지금부터는 폰 브라우징에 대해 **실제로 동작한다.** 다만 이번에 방문한
곳(`m.example-forum.com`·`m.example-portal.com`)은 6개 패턴 어디에도 안 걸린다 — 규칙을 손볼지는
데이터가 며칠 쌓인 뒤에 본다.

> ⚠️ **확인이 남은 것.** 웹 이벤트(14:29~14:30)는 도착했는데 그 시간의 **앱 세션은
> 아직 안 왔다**(앱 버킷은 14:23:07 에서 멈춰 있다). 폰이 버킷마다 다른 주기로 미는
> 것으로 보인다. 롤업은 멱등이라 다음 회차에 맞춰지겠지만, **앱 세션 없이 웹
> 이벤트만 있는 순간에 중재가 그 구간을 노트북에 주면 URL 이 잘려 나간다**
> (`_clip_events_excluding`). 며칠 뒤 폰 브라우징 칸에 URL 분류가 실제로 붙는지
> 확인할 것.

### F5. 웹 워처 (포크, 가설)

- **제목**: 주소창 노드가 아니라 **창 제목**을 읽는다.
  `AccessibilityWindowInfo.getTitle()` 또는 탭 노드의 `contentDescription`
  (크롬은 탭에 "제목 - 도메인" 형태로 넣는다) ★ 실기기 확인 필요
- **입력 중 상태를 버린다**: 주소창에 포커스가 있으면(`isFocused`) 보내지 않는다.
  URL 형태 검증(`.` 이 있고 공백이 없다)을 통과한 것만 기록한다
- **트리거**: 주소창 변경이 아니라 `TYPE_WINDOW_CONTENT_CHANGED` 후 디바운스
- **자기 상태를 남긴다**: 접근성 서비스는 꺼져도 조용하다. 08-22~08-25 사흘을
  아무도 모른 채 지나갔다 — `lt doctor` 가 "웹 버킷이 N일째 조용하다"를 보게 한다

> ★ **프라이버시 결정을 다시 확인할 것.** `plan.md §F3` 은 `WebWatcher`(접근성)를
> **"켜지 않는다"** 로 적어 뒀는데 지금 켜져 있다. 제목까지 채우면 "무엇을 읽었나"가
> 전부 남는다. 이 저장소 원칙상 데이터는 기기 밖으로 안 나가지만, **켤지 말지는
> 사용자 결정**이고 `plan.md` 와 어긋난 상태를 먼저 정리해야 한다.

## 4. 젯슨 쪽은 준비돼 있다

워처가 고쳐지면 코드 변경 없이 그대로 좋아진다.

- `rollup._title_from_media` 가 **같은 패키지의 세션에만** 제목을 얹는다
  (배경음악이 남의 세션 이름을 바꾸면 안 된다)
- 한 세션에 여러 곡이 걸리면 **겹친 시간이 가장 긴 것**을 쓴다
- 제목이 비었으면 앱 이름을 남긴다
- 미디어 이벤트 자체는 **활동으로 세지 않는다** (`test_rollup_device.py` 가 고정)

## 5. 하지 말 것

- **앱 이름을 제목으로 쓰지 마라.** `"YouTube"` 가 144칸에 백 번 찍히면 그 칸들은
  아무것도 말하지 않는다. 차라리 비워 두는 편이 정직하다
- **재생 중인 것으로 활동 시간을 늘리지 마라.** 틀어둔 미디어가 다른 기기를 밀어내던
  사고가 2026-08-25 에 등급제로 해결됐다 (`known-issues §5`). 제목은 **라벨일 뿐**이고
  소유권 판정에 들어가면 안 된다

## 6. 다시 재는 법

```bash
cd life-trainer
.venv/bin/python - <<'PY'
import sqlite3
c = sqlite3.connect('data/lifetrainer.db'); q = lambda s: list(c.execute(s))
print("칸 제목:", q("""SELECT day, COUNT(*),
        SUM(CASE WHEN COALESCE(top_title,'') NOT IN ('','YouTube') THEN 1 ELSE 0 END)
      FROM slot WHERE top_app='com.google.android.youtube' GROUP BY 1"""))
print("웹 제목:", q("""SELECT COUNT(*), SUM(CASE WHEN COALESCE(title,'')<>'' THEN 1 ELSE 0 END)
      FROM aw_event e JOIN aw_bucket b ON b.bucket_id=e.bucket_id
      WHERE b.bucket_id LIKE '%android-web%'"""))
PY
```
