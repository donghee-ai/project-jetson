## ★ 하루의 정의 (가장 자주 묻는 것)

**논리적 하루 = KST 06:00 → 다음날 KST 06:00.** 자정이 아니다.

- 타임존은 `config/lifetrainer.toml` 의 `timezone = "Asia/Seoul"` 하나에서 나온다
- 경계는 `[rollup] day_boundary_hour = 6`
- **`slot 0 = 06:00~06:10`, `slot 143 = 익일 05:50~06:00`**
- 새벽 1시 작업은 **전날** 하루에 속한다 (slot 114)

종이 플래너의 TIMETABLE 이 06시부터 시작하기 때문이고, 그래야 밤샘 작업이 두 날로
잘리지 않는다. 이전에는 자정 기준이라 격자와 데이터 경계가 어긋나 있었다.

### 왜 이 모양인가

- **수집과 처리를 분리했다** (설계서 §3.3). 젯슨에 워처를 두지 않는다. 노트북을 껐다 켜도
  파이프라인이 안 깨지고, 꺼져 있던 구간은 `off`로 정직하게 남는다.
- **모델 서버를 따로 띄우지 않는다.** 기존 OpenClaw용 `llama-server:8080`을 공유한다.
  8B@20480이 6.7GB를 쓰고 있어 두 번째 8B 서버는 여전히 안 들어간다.
- **웹과 Slack은 같은 DB를 본다.** 웹은 입력, Slack은 알림·기록·질의. 상태를 이중으로 두지 않는다.
- **대화의 기본은 에이전트, 슬래시는 빠른 접근.** 에이전트의 값은 속도가 아니라
  **Slack 밖으로 안 나가도 된다는 것**이다 — 웹 플래너를 열지 않고 대화로 끝난다.
  슬래시는 무엇을 할지 이미 알 때 쓴다(밀리초·GPU 미사용). 근거는 §4-3.

### 대화 경로가 둘이다 (2026-08-24 부터)

같은 `llama-server` 위에 **툴을 고르는 주체가 다른** 경로가 둘 있다.

```
   Slack 자연어 ──> agent/            **모델이** 툴을 고른다      약 30초  ★ 기본값
   Slack 슬래시 ──> slackio/app.py    파싱 → SQL                 밀리초   빠른 접근
   (강등)      ──> llm/converse.py   규칙 게이트가 툴을 고른다   2~9초   ★ 고장 신호
```

★ **셋을 같은 층으로 보면 안 된다.** 앞의 둘은 사용자가 고르는 **경로**이고,
`converse` 는 게이트웨이가 죽었을 때만 타는 **강등**이다 — 여기로 내려갔다는 것 자체가
고장이다 ([HISTORY 08-24](../HISTORY/2026-08-24-the-delegation-was-silently-falling-back.md):
조용히 강등된 채 몇 시간을 돌았다).

**2026-08-24 부터 Slack 자연어 DM 이 에이전트로 간다** (`[agent] slack = true`).
`llm/converse.py` 는 **강등 경로**로 남는다 — 게이트웨이가 죽었을 때 사용자가
에러 대신 답을 받게 한다. 슬래시 명령은 Slack 에서 다른 이벤트라 안 느려진다.

|  | `llm/` | `agent/` |
|---|---|---|
| 프롬프트 조립 | 우리가 3층으로 (`context.py`) | OpenClaw 가 |
| 툴 선택 | 규칙 (`trigger.py`, 12/12, 0.154ms) | 모델 |
| 실린 툴 | 트리거가 고른 것만 271~595토큰 | 13개 상시 2,976토큰 |
| 파일 접근 | 없음 | **감옥 안에서만** (`agent/sandbox.py`) |
| 지연 (실측) | 2~9초 | 26~106초 |

**에이전트가 자연어를 맡는 이유**: 대화 경로의 툴 10개에는 **상태 변경·삭제·메모·
기록이 없다.** "1번 완료해줘" 를 물으면 8B 가 툴 없이 "완료했습니다" 라고 답한다 —
에러도 안 난다. 에이전트는 슬래시 10개를 툴로 갖고 있어서 그게 실제로 된다.
슬래시 우선 원칙은 에이전트 **안에서도** 유지된다 — `slash` 툴이 목록의 첫 번째이고,
`/lt /log /plan /del /view /done /doing /defer /memo /week` 10개를 Slack 없이 실행한다.

자세한 것은 [progress/2026-08-24](progress/2026-08-24.md) ·
[agent-gateway.md §7](../../operate/notes/agent-gateway.md).

## 2. 데이터 모델 — 30 테이블

> 관계도(ERD)와 판정 근거는 [architecture.md](architecture.md) 에 있다. 여기는 서술만 둔다.

**핵심 설계**: `slot`은 기계가 계측한 **실제**, `plan`은 사람이 선언한 **의도**,
`slot_override`는 사람이 고친 **정정**. 셋을 절대 같은 테이블에 섞지 않는다.

### 활동 계층

| 테이블 | 역할 | 주의 |
|---|---|---|
| `aw_bucket` | ActivityWatch 버킷 메타 | |
| `aw_event` | 원본 이벤트 | PK `(bucket_id, ts)` — **이중 계산 방지의 핵심** |
| `slot` | 144슬롯 승자 카테고리 | **시각화 전용**. 집계 근거로 쓰면 틀린다 |
| `slot_breakdown` | 슬롯 × 카테고리 × 앱 초 | **모든 SQL 집계의 근거** |
| `manual_entry` | `/log` 수동 입력 | 롤업에서 가중치 2배 |
| `unclassified` | 미분류 지문 + LLM 태깅 결과 | 지문당 1행 |
| `unclassified_day` | 날짜별 실적 | 멱등성을 위해 분리 |

### 계획 계층

**템플릿과 인스턴스를 분리한다.** `plan` 은 "평일 09-12 코딩" 같은 반복 규칙이고,
`plan_instance` 는 그 규칙이 특정 날짜에 만들어낸 실체다. 분리하지 않으면
"오늘은 진행 중", "오늘은 내일로 연기" 같은 하루 단위 상태를 둘 자리가 없다.

| 테이블 | 역할 |
|---|---|
| `plan` | **반복 템플릿** (`weekdays`) / 일회성 |
| `plan_instance` | **그날의 실체.** 6단계 상태 + 이월 체인 + 소프트 삭제 |
| `plan_instance_event` | 상태 변경 감사 로그 (누가·언제·무엇에서 무엇으로) |
| `plan_skip` | 특정 날짜만 건너뛰기 |
| `plan_check` | (구) 이진 체크 — `plan_instance.status` 로 이관됨 |
| `subject` | **사용자 정의 과목.** 색은 검증된 8슬롯만 |
| `day` | 하루 단위 메모·코멘트·D-Day·총시간 |
| `slot_override` | 사람이 고친 칸. **롤업이 재생성해도 살아남는다** |
| `device` | 기기 차원. **지금 3대** (`synth-pc` 합성용 · `DESKTOP-EXAMPLE` · `phone-example` 폰).<br>여러 기기가 같은 10분을 주장하면 **마지막 상호작용이 그 시간을 소유한다** |

**상태 6단계**: `todo · doing · done · partial · deferred · canceled`
종이 플래너의 체크 기호 3종(완료 `v` / 진행 중 `/` / 연기 `>`)을 흡수한 것이다.

**이월 체인**: `deferred` 로 바꾸면 다음 날 인스턴스가 자동 생성되고 `carried_from` 으로
이어진다. 체인 깊이가 2 이상이면 `v_carry_debt` 뷰가 잡는다 — **미루기 탐지**다.

### 수집·처리 계층

| 테이블 | 역할 |
|---|---|
| `source` · `url_state` · `robots_cache` | 피드 등록 · URL 프론티어 · robots 캐시 |
| `doc_embedding` | **문서 벡터 (RAG)**. Qwen3-Embedding-0.6B · 1024차원 · L2 정규화.<br>`source_hash` 로 원문이 바뀐 것만 다시 만든다 — 요약이 나중에 붙기 때문 |
| `doc` · `doc_fts`(+4) · `doc_tag` · `interest` | 문서 · BM25 인덱스 · 태그 · 관심사 |
| `job` · `llm_call` | GPU 큐 · LLM 호출 계측 |
| `report` · `alert_state` | 생성 리포트 · 알림 쿨다운 |
| `meta` · `sync_state` | 스키마 버전 · 동기화 커서 |

## 3. 파이프라인

### 3-1. 수집 (10분 주기)

```
aw_cursor:<bucket> (마지막 본 이벤트의 시작 시각)
  → [cursor - 900초, now] 겹쳐서 재조회
  → (bucket_id, ts) upsert
```

**왜 겹쳐서 다시 가져오는가.** 버킷의 마지막 이벤트는 진행 중인 하트비트라
`id`와 `timestamp`는 고정이고 `duration`만 자란다. 끝 시각 기준으로 페이징하면
진행 중이던 활동이 다음 폴링에서 **별개의 새 이벤트처럼** 잡혀 조각나고 이중 계산된다.
시작 시각 기준 + 겹침 재조회 + `(bucket_id, ts)` upsert가 이 문제를 완전히 없앤다.

### 3-2. 롤업 — 슬롯 하나(600초) 계산 순서

```
1. afk 버킷 → active_sec / afk_sec / gap_sec  (gap = PC 꺼짐)
2. window 이벤트 → 겹친 초만큼 순회, 브라우저면 web 버킷에서 url 결합
3. ★ not-afk 구간으로 클리핑 — 잘려나간 시간은 away 로
4. (카테고리, 앱)별 초 → slot_breakdown
5. manual_entry 겹치면 가중치 2배
6. 승자 = 초 최대 카테고리
7. active 비율 < 5% 이고 수동입력 없으면 → off
8. 미분류 지문 → unclassified_day (지우고 다시 쓰기)
9. ★ slot_override 적용 (source='override')
```

**3번을 빼면 "잠든 사이 8시간 코딩했다"는 리포트가 나온다.**
**9번은 slot_breakdown을 건드리지 않는다** — 격자 표시만 바꾸고 집계 숫자는 실측 그대로.

멱등성: 같은 날을 몇 번 롤업해도 결과가 같다. 실측 불변식 4종 위반 0 확인.

### 3-3. 웹 수집 (매시)

```
조건부 GET (ETag/Last-Modified) → 304면 본문 없이 종료
  ├─ 3회 연속 무변경 → 주기 ×2 (상한 7일)
  └─ 변경 감지 → 주기 ÷2 (하한 10분)
중복: SHA-256(완전) + SimHash 64비트(근사, 뉴스 신디케이션)
```

도메인별 토큰 버킷 2초, arXiv 3초, 동시 연결 1, robots.txt 준수.
**실측: 소스 20개 · 신규 2,331건 · 오류 0.**

### 3-4. 표현

```
slot_breakdown ──SQL 집계──> stats ──> 플래너 PNG / 웹 격자 / Slack 카드
                                 └──> 계획 달성률 (plan ∩ slot_breakdown)
```

**Phase 1 리포트에는 LLM이 없다.** 순수 SQL + 템플릿 문장.

## 4. 기능 전체

### 4-1. CLI — 26개 명령

```bash
# 진단·기반
lt doctor                     # 17개 항목 점검, FAIL 시 해결법까지 출력
lt init-db · lt backup

# 활동
lt sync                       # ActivityWatch 동기화 (젯슨이 당긴다)
lt import <파일>               # 폰에서 뽑은 AW export 넣기 (폰은 밀기만 된다)
lt synth --days 14            # 합성 데이터 (AW 없이 전 파이프라인 검증)
lt rollup [--today|--yesterday|--day D|--range A B]
lt stats --day D
lt log 운동 60m 헬스장         # 수동 기록

# 계획
lt plan add "딥워크" 09:00-12:00 --category coding --days 평일
lt plan add "병원" 14:00-15:00 --day 2026-08-20     # 일회성
lt plan list --day D          # 달성률 포함
lt plan rm/check/skip
lt slot set D 54-60 coding    # 칸 보정 (자동 재롤업)
lt slot clear D 54-60

# 표현
lt planner --day D [--theme dark]    # 플래너 PNG (24×6)
lt timeline --day D                  # 가로 띠 PNG
lt report daily|weekly [--post]      # --post 없으면 발송 안 함
lt digest [--post]                   # 아침 다이제스트

# 수집·LLM
lt collect · lt score · lt worker [--once] · lt queue stats
lt nightly [--dry-run|--stop]        # 야간 배치 적재 (--stop 은 남은 잡 비우기)

# 서비스
lt web [--host --port] · lt slack serve|test

# 에이전트 (OpenClaw 결합, 2026-08-24)
lt agent mcp                  MCP stdio 서버 — 게이트웨이가 띄운다. 손으로 부를 일 없음
lt agent budget               프롬프트 토큰 예산. 넘으면 종료코드 1 (테스트도 이걸 본다)
lt agent prompt [--print]     워크스페이스 AGENTS.md 생성·설치
lt agent call <툴> k=v …      툴 하나만 직접 호출 (게이트웨이·모델 없이 몸통 확인)
```

### ★ 슬래시를 남겨 두는 이유 (기본값은 에이전트다)

| 경로 | 지연 |
|---|---|
| 슬래시 → 파싱 → SQL | **밀리초** (GPU 미사용) |
| llama-server 직접 질의 | 3.9초 |
| OpenClaw 에이전트 경유 | **25~40초** |

**대화의 기본값은 에이전트다** (2026-08-28 판단, §1). 그래도 슬래시를 안 지우는 이유는
지연이 아니라 **실패 모드**다 — 소형 모델은 툴을 안 부르고 *"했습니다"* 로 끝내는 실패가
있고(`operate/notes/agent-gateway.md §4-6`) **에러가 안 난다.** 플래너에서 그게 나면 DB 는
비어 있는데 사용자는 성공한 줄 안다. 명시적 명령은 그게 **구조적으로 불가능**하다.

→ **무엇을 할지 이미 알 때는 슬래시, 대화로 풀 때는 에이전트.**
   에이전트를 쓰는 값은 Slack 밖(웹 플래너)으로 안 나가도 된다는 것이다.

```
/plan 저녁 약속가기                       한 건 추가
/plan 1. 첫째 2. 둘째                     번호 목록이면 일괄
/plan 프로젝트 보고서 #프로젝트 @90m !high     확장 문법 (#과목 @소요 !우선순위)
/del                                      체크박스 목록 → 선택 → 삭제 (15초 실행취소)
/del 3,5                                  번호 즉시 삭제 (소프트)
/view [어제|YYYY-MM-DD]                    플래너 PNG
/done N · /doing N · /defer N              상태 전환 (defer 는 내일 인스턴스 자동 생성)
/memo <텍스트> · /week
/lt today|yesterday|week|status|ping · /log 운동 60m
```

**`/del` 은 완료 항목을 기본 숨김**하고 삭제도 소프트 삭제다 — 실적이 사라지면
주간 통계가 깨진다.

PNG는 `files_upload_v2` → 반환된 file id를 Block Kit `slack_file` 이미지 블록에 삽입.
공개 URL이 필요 없다.

## 6. 하드웨어가 강제한 규칙

`measure/findings/hardware.md` · `measure/findings/performance.md`의 실측에서 나온 것들.

| 규칙 | 근거 |
|---|---|
| **JSON 스키마에 `pattern` 금지** | llama.cpp GBNF 변환기가 정규식을 못 다뤄 요청 전체를 400으로 거부. 앵커를 붙여도 안 됨 |
| **JSON 출력 시 thinking 무조건 off** | 사고 텍스트가 섞여 파싱이 깨짐 |
| **LLM 입력 3~5K로 끊기** | 깊이 3K 10.9 tok/s → 32K 3.96 tok/s (−70%). 30K 1회보다 3K 10회가 2.7배 빠름 |
| **한국어 토큰 55% 할증** | 같은 내용에 토큰 1.55배 |
| **모델 id까지 확인** | 포트만 보는 헬스체크가 다른 모델을 통과시켜 1시간 무중단 다운 낸 적 있음 |
| **GPU 잡 동시 실행 금지** | `fcntl.flock`. 두 번째 워커는 즉시 종료 |
| **파이썬 상주 300MB 이하** | 가용 4.5GB (ctx 축소 전에는 2.8GB였다) |

### 메모리 현실

```
전체 16GB → 안전 예산 13.4GB
llama-server (8B Q4_K_M @ 20480ctx)    6.7GB   ← 두 프로젝트가 공유한다
llama-embed  (0.6B Q8_0, CPU, :8081)   1.8GB   ← RAG. 08-23 신설
openclaw-gateway                       0.29GB
남는 것 (free -h 의 available)          4.5GB
```

**Life Trainer 는 전용 모델 서버를 띄우지 않는다.** OpenClaw 가 이미 띄운
`127.0.0.1:8080` 을 그대로 쓴다 — 8B 스택 하나로 예산이 거의 찬다.

**선결과제였던 ctx 회수는 2026-08-23 에 끝났다.** 40,960 → 20,480 으로 낮춰
KV 캐시 2.99GB → 1.50GB. KV(q8_0)는 토큰당 76.5 KiB 이고 **시동 시 전액 선불**이라,
대화가 짧아도 안 줄어든다. 한 턴 실측 최악이 2,980 토큰(`MAX_HISTORY_MESSAGES=6`
으로 상한이 구조적)이라 나머지 3GB 는 영구히 놀고 있던 것이다.

회수분(1.49GB)보다 실제 효과가 컸다 — 세 서버가 스왑에서 나오고 페이지 캐시가
복구되면서 **가용 200MB → 4,566MB, 스왑 3,890 → 1,474MB**. 덕분에 임베딩 서버와
OpenClaw 게이트웨이를 동시에 켜고도 4.5GB 가 남는다.

### 검증 기록

**여기에 숫자를 옮겨 적지 않는다.** 뽑는 명령이 정본이다:

불변식만 여기 적는다 — 이건 값이 아니라 **성질**이라 안 변한다:
`active+afk+gap == 600` · 슬롯합 ≤ 600 · 하루 ≤ 24h · 승자 실재.

**테스트는 네트워크를 안 탄다.** 전부 페이크/픽스처다 — 그래서 [실기기를 붙이고 5분
만에 나온 겹침 버그](../HISTORY/2026-08-17-aw-overlap-inflation.md)를 원리적으로 못 잡았다.
초록불은 동작 확인이 아니다.

## 8. 지금 무엇이 막혀 있나 — **여기 적지 않는다**

**이 문서는 구조를 설명한다. 현황은 시제가 달라 같은 파일에 두면 반드시 어긋난다.**

| 묻는 것 | 어디서 답이 나오나 |
|---|---|
| 지금 무엇이 고장나 있나 | [`docs/issues/`](issues/) — 한 건에 한 파일, **파일명 접두어가 등급이다** |
| 지금 서비스·데이터가 어떤가 | `make status` · `lt doctor` |
| 다음에 뭘 할까 | [../HANDOFF.md](../HANDOFF.md) §6·§7 |
| 무엇을 사실이라 잘못 믿었나 | [`../HISTORY/`](../HISTORY/) |

> **왜 지웠나 (2026-08-28).** 이 자리에 있던 §8(막혀 있는 것)·§9(다음 방향)가
> 헤더의 `기준일` 을 달고 **다섯 가지를 틀리게** 말하고 있었다 — 이미 넣은 검색 키를
> "없다" 고, 이미 바꾼 계획을 "테스트용" 이라고, 끝난 RAG 단계를 "남았다" 고.
> 규칙이 부족한 게 아니라 **현황을 적을 자리가 하나 더 있었던 것**이 원인이다.
> [`issues/README`](issues/README.md) 가 상태 열을 안 두는 이유와 같다.

## 9. 기록해둔 함정들

이 프로젝트가 실제로 밟은 것들. 테스트로는 안 잡혔다.

| 함정 | 어떻게 드러났나 |
|---|---|
| **AW 하트비트로 duration이 자란다** | 끝 시각 페이징 시 활동이 조각나고 이중 계산 |
| **AW를 Tailscale IP에만 바인딩하면 수집이 멈춘다** | 로컬 워처가 `localhost`로 붙기 때문 |
| **`unclassified` 누적이 멱등하지 않았다** | 10분 크론에서 무한 증식 → 테이블 분리 |
| **SimHash가 SQLite INTEGER 오버플로** | 입력 절반이 실패 → 2의 보수 정규화 |
| **arXiv가 robots.txt로 전 경로 차단** | 코드는 정상, 차단이 사실. 소스 단위 예외로 해결 |
| **눈대중으로 고른 색이 검증 3항목 FAIL** | coding↔research가 정상시야에서도 ΔE 12.0 |
| **계획 테두리가 격자선에 완전히 덮임** | 계획은 대부분 정시 시작 → 기능 전체가 죽어 있었음 |
| **합성 데이터가 오후 1시 반에 끝남** | PNG를 눈으로 보고서야 발견 |
| **데스크톱 격자가 2600px** | "하루가 한눈에"라는 존재 이유가 깨짐 |
| **tailscale serve `:443` 충돌** | OpenClaw가 이미 사용 중 → `:8443`으로 분리 |
| **`lt log --at 09:00` 이 15:00 으로 기록됨** | 경계 전환 후 `day_bounds` 가 06:00 을 반환하는데 거기에 9시간을 더하고 있었다 |
| **웹 격자가 6시간 이중 회전** | slot 0 이 06:00 이 됐는데 UI 가 여전히 벽시계 hour 로 슬롯을 찾았다 |
| **계획 오버레이가 격자와 어긋남** | `achieve.py` 의 슬롯 변환이 자정 기준으로 남아 있었다 |
| **`slack_bolt.App(...)` 이 생성 시 네트워크를 탄다** | `auth.test` 를 실제 호출한다. 테스트·점검용 `verify_token=False` 추가 |
| **마이그레이션이 타임존을 하드코딩** | `migrate(conn, cfg)` 로 설정값을 받게 수정 |
| **`dict(resp)` 가 일일 리포트를 3일간 막고 있었다** | 가짜 SDK 응답이 실물보다 착했다 |
| **계획만 주입했더니 "다 했다"고 지어냄** | 대화 E2E 첫 질문에서 |
| **플래너 PNG 가 밤 활동을 낮 칸에 그림** (6시간 밀림) | 경계 수정 때 3곳만 고치고 4번째(`planner.py`)를 놓쳤다 |
| **친절한 폴백이 무관한 결과를 결과처럼 내놓음** | 사용자 질문("이건 환각 아니야?") |
| **`required` 는 툴 호출 보장이 아니었다** | 모델이 본문을 먼저 다 쓰고 나서 툴을 부른다 |
| **요약 JSON 이 태그 목록 때문에 잘림** | 스키마는 문법만 강제하지 **길이를 모른다** |
| **규칙을 보강했는데 미분류 1위가 그대로** | 집합이 **줄어드는** 경우를 안 봤다 |
| **플래너 PNG 가 Slack 에 두 번 뜸** | `channel=` 이 업로드가 아니라 **게시 지시**였다 |
| ★ **`is_private` 로 SSRF 를 막으면 Tailscale 이 통과한다** | 100.64/10 은 private 이 아니다. 이 기기 웹 플래너가 거기 있다 |
| ★ **살아 있다 ≠ 서빙 가능하다** | 배치가 모델 로딩을 안 기다려 요약 잡 277건이 503 |

전체 색인과 각 건의 "깨진 가정"은 [../HISTORY/](../HISTORY/) 에 있다.

> **공통점**: 전부 테스트가 초록불인 상태에서 나왔다.
> 렌더링해서 보거나, 실제로 돌려보거나, 계산해봐야 나오는 것들이다.
