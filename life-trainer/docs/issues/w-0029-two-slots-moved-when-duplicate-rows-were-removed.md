# 중복 행을 지웠더니 칸 두 개가 움직였다 — 롤업이 원본 행 수에 민감하다

- **번호**: `0029`
- **발견일**: 2026-09-07 — `lt aw-compact --apply` 를 운영에 돌린 직후 27일치를 비교하다
- **상태**: 🟣 **`w` — 알려진 채로 둔다 (2026-09-07 사람이 판정: "잘 작동한다로 끝내").**

> ★ 왜 지우지 않고 남기나: 27일 중 **칸 2개**(20분)이고 화면 숫자는 멀쩡하다.
>   다만 *"같은 사건을 두 번 적어도 롤업 결과는 같다"* 가 안 지켜진다는 사실 자체는
>   남는다 — `w-0014` 와 **같은 함수가 용의선상**이라, 그쪽을 팔 때 재료로 쓴다.
>   재현 절차와 스냅숏이 아래 그대로 있다.

## 무슨 일이 있었나

`aw-compact` 는 **같은 사건을 여러 번 적은 행**을 하나로 합친다. 덮은 시간(합집합)은
정의상 안 변하고, 실제로 일곱 버킷 모두 0.001초 이내였다.

그런데 롤업을 다시 돌려 27일을 전부 비교하니 **칸 두 개**가 바뀌었다 (3,888칸 중):

```
2026-08-30 16:00   entertainment → coding
2026-08-30 21:00   coding        → away      ← 이쪽이 문제다
```

## 21:00 칸의 원본 — 사람은 PC 앞에 있었다

압축 전후로 **딱 하나만** 다르다. PC afk 버킷이 3행 → 1행이 됐고, **셋 다 `not-afk`** 였다:

```
압축 전   10:27:57→12:14:11  not-afk
          11:59:11→12:14:11  not-afk     ← 앞의 것 안에 완전히 들어간다
          12:09:59→12:14:11  not-afk     ← 〃
압축 후   10:27:57→12:14:11  not-afk
```

같은 구간의 PC 창 기록은 **압축 전후가 글자 하나까지 같다** — `Code.exe`,
`chrome.exe`, `WindowsTerminal.exe` 가 몇 초 간격으로 계속 바뀐다. 즉:

- PC afk: **자리에 있었다**(not-afk)
- PC 창: **계속 만지고 있었다**
- 폰: 영상 재생 중간부터 `afk` (시각은 익명화)

**`coding`(압축 전)이 맞고 `away`(압축 후)가 틀렸다.**

## 왜 이상한가 — 청구는 같아야 한다

`_activity_claims` 는 노트북에 대해 이렇게 만든다:

```python
not_afk = _union([...])          # ★ union 이다
return [(iv, TOUCHED) for iv in not_afk]
```

**세 행의 합집합 = 한 행**이다(뒤의 둘이 앞의 것 안에 들어간다).
그러니 중재에 들어가는 청구는 **압축 전후가 같아야 한다.** 그런데 결과가 다르다.

즉 원인은 중재 위쪽이 아니라 **그 아래 어딘가**가 원본 행 수를 보고 있다는 뜻이다.
후보는 `_dedupe_overlaps`(`w-0014` 가 이미 구멍을 지적한 곳), `absorb_short_switches`
(흡수한 구간을 `locked` 로 중재에 고정한다), `_process_slot` 의 귀속이다.
**아직 못 좁혔다.**

## 재현 — 재료가 남아 있다

```bash
# 압축 직전 스냅숏 (이 파일이 증거다)
life-trainer/data/backup/before-compact-2026-09-07.db

# ① 압축 안 한 사본을 그냥 재롤업하면 → 바뀌는 칸 0개  (재롤업 탓이 아니다)
# ② 같은 사본에 aw-compact --apply 후 재롤업하면 → 위 두 칸이 바뀐다
```

①을 실제로 돌려서 확인했다. **재롤업만으로는 아무것도 안 바뀐다** — 압축이 원인이다.

## 왜 되돌리지 않았나

- 압축 자체는 옳다. 중복 행은 같은 현실을 여러 번 적은 것이고, 안 지우면
  `sum(duration)` 을 쓰는 코드가 앞으로 생길 때 10배로 틀린다 (`0027` 의 이유)
- 되돌리면 **이 결함이 다시 가려진다.** 중복이 우연히 답을 맞히고 있었던 것이라,
  앞으로 저장 관문이 중복을 막는 이상 언젠가 같은 자리에서 드러난다
- 영향이 3,888칸 중 2칸(20분)이고, 하루 활동시간 기준 0.11시간이다

**되돌릴 수는 있다** — 위 스냅숏이 그대로 있다.

## 고칠 때 볼 것

- [ ] 중복 행 수가 결과를 바꾸는 **정확한 지점**을 찾는다 (`_dedupe_overlaps` 부터)
- [ ] 찾으면 **그 지점에 테스트를 건다** — "같은 사건을 두 번 적어도 결과가 같다"
      는 것은 롤업이 지켜야 할 성질이지 우연이면 안 된다
- [ ] `w-0014` 와 같이 볼 것. 같은 함수가 용의선상에 있다
