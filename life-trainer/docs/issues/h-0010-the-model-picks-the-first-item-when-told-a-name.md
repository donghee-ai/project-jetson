채점기는 **실사용과 다른 조건에서 돈다.** 이미 그 자체가 이슈로 열려 있다:

그리고 08-24 에 이미 관측했다 — **채점 문장이 실제보다 어려웠다.** 실패 데이터를

## 08-24 관측 (그대로 둔다)

실패 모양이 넷 다 같았다. 목록의 **첫 항목**을 고른다.

| 구성 | 모델이 부른 것 |
|---|---|
| `[id]` 실림 + id 수용 | `/done 90` (미팅은 99) |
| `[id]` 제거 | `/done 1` (지어냄) |
| 제목 우선 명령표 | `/done 예시 일정` |

형식을 세 번 바꿔도 같았다. **형식이 문제가 아니라** 모델이 "사용자가 말한 것"과
"목록의 항목"을 잇지 못하는 모양이었다. 3건짜리 목록에서도 그랬다.
그리고 **자신 있게 틀린 것을 보고했다** — "✅ … 완료 처리되었습니다 🎉".

## 영향 — 조용히 틀리지는 않는다

방어가 이미 있어서 `p` 로 둔다:

- 목록에 없는 번호·제목이면 **아무것도 안 바꾸고 거부**
- 복수 지정에서 하나라도 없으면 **전부 안 바꿈**
- 쓰기 결과가 **적용한 날짜**를 말함

조용히 틀리는 경우는 **"목록 안의 다른 계획"을 고를 때뿐**이다.
