# 채점기가 실데이터에 쓰고, 바꾼 계획 상태를 못 되돌린다

- **번호**: `0008`
- **발견일**: 2026-08-24
- **상태**: 🟡 **h — 일단 동작은 한다.** 사람이 되돌리면 되지만, 그 조건 차이가
  [`0010`](h-0010-the-model-picks-the-first-item-when-told-a-name.md) 을 못 갈리게 만든다 (2026-08-28 재판정)

## 증상

`scripts/eval_agent.py` 는 게이트웨이를 통해 도므로 **실데이터**(`data/lifetrainer.db`)에
쓴다. 만들어진 계획은 끝나고 지우지만(`--keep` 로 끄면 남는다),
**`plan-done` 케이스가 바꾼 상태(`todo` → `done`)는 못 되돌린다.**

`/done 1` 이 그날 **ordinal 1번**을 완료로 바꾸므로, 진짜 계획이 있는 날에 돌리면
그 하나는 사람이 되돌려야 한다.

## ★ 절반이 풀렸다 (2026-09-07)

`lt dev-db` 가 운영 DB 의 사본을 뜨고 `lt --dev <명령>` 이 그 사본에 대고 돈다
(`lifetrainer/devdb.py`). **채점기가 쓸 격리된 DB 를 만드는 것은 이제 한 줄이다.**

남은 것은 배선이다 — 게이트웨이에 등록된 MCP 명령줄이 고정이라, 채점기가
`--dev` 를 끼워 넣지 못한다. 채점 전용 에이전트를 하나 더 등록하는 것이 곧은 길이고,
그건 저장소 밖(`~/.openclaw/`) 작업이라 여기서 하지 않았다.

## 고칠 것

MCP 서버가 채점용 DB 를 보게 해야 한다. `lt agent mcp --config` 는 이미 받지만
**게이트웨이에 등록된 명령줄이 고정이라 채점기가 못 갈아끼운다.**
채점 전용 에이전트를 하나 더 등록하는 것이 가장 곧은 길이다.

[`0009`](h-0009-the-scorer-needs-plans-planted-by-hand.md) 와 같은 뿌리다 —
채점기가 자기 환경을 스스로 갖추지 못한다.
