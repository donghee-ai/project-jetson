# 기본값 30 은 **이 기기 한 대에서 잰 값**이다

- **번호**: `0005`
- **발견일**: 2026-08-24 (600 vs 30 불일치) · **결정 2026-09-07**
- **상태**: 🔵 **`p` — 갈라진 것은 닫았다.** 남은 것은 *"30 이 남의 기기에서도 맞나"* 다

## 닫힌 부분 (2026-09-07)

사람이 정했다 — **기본값을 30 으로 내린다.** 세 곳을 같이 바꿨다:

```
config.py  _DEFAULTS["nightly"]["summary_limit"]   600 → 30
config.py  NightlyConfig.summary_limit             600 → 30
config/lifetrainer.example.toml                    600 → 30
이 기기의 실제 운영값                                 30   (원래부터)
```

**넷이 이제 같다.** 새 기기가 이 저장소가 이미 접은 동작(600)으로 도는 일은 없다.

### 갈라지지 않게 검사를 걸었다

그전에도 검사가 있었지만 **키 이름만** 봤다 (`test_example_toml_이_코드가_읽는_키를_다_담는다`).
그래서 코드 600 · example 600 · 운영 30 인 상태가 **조용했다.**

`test_example_toml_의_값이_코드_기본값과_같다` 가 이제 **값까지** 본다.
76개 키 중 75개가 이미 값까지 같았고, 하나(`activitywatch.base_url`)만 예외 목록에
사유와 함께 넣었다 — example 은 사람에게 보여주는 문서라 테일넷 주소 예시가 낫다.

★ 검사기를 일부러 어긋내 확인했다: example 을 600 으로 되돌리자
  *"코드 30 · example 600"* 이라고 정확히 잡았다.

## 남은 것 — 왜 아직 안 닫나

**30 은 "재 봤더니 이 기기에서 3.8시간 창에 안전하더라" 는 값이다.**
다른 기기(더 빠른 GPU · 더 긴 밤 · 더 많은 문서)에서 맞는지는 **아무도 안 쟀다.**

즉 지금 기본값의 근거는 *"우리가 쓰는 값"* 이지 *"이 정도면 어디서든 안전하다"* 가 아니다.
기본값이 뜻해야 하는 것은 후자다.

- 이 기기 한 대뿐이라 **잴 방법이 지금은 없다.** 그래서 `p-` 다
- 남의 기기가 생기면 그때 잰다. 그전까지는 **보수적인 쪽(30)** 이 맞다 —
  너무 적게 요약하는 것은 다음 날 다시 하면 되지만, 밤새 GPU 를 붙들면 그날 아침이 없다

## 왜 이 파일을 남기나

기본값이 **한 대에서 잰 값**이라는 사실 자체가 다음 사람이 알아야 하는 정보다.
파일을 지우면 `30` 은 그냥 *"누가 정한 숫자"* 가 되고, 늘려야 할 때
**근거가 있었는지 없었는지**부터 다시 조사하게 된다.
