- **번호**: `0007`
- **발견일**: 2026-08-24
- **상태**: 🟣 **`w` — 알려진 채로 둔다 (2026-09-07 사람이 판정).**
  쓰고 있고 답이 온다. 느린 원인은 이미 밝혀져 있다(프롬프트 재처리) —
  **모르는 것이 아니라 감수하기로 한 것**이다.

>   기기가 8B 를 이고 도는 이상 26초는 구조에서 나오는 값이라, 고치려면
>   모델을 바꾸는 결정이 먼저다.
  다만 사람이 기다리는 시간이다

## 실측 분해

`llm/converse.py` 경로가 2~9초인데 OpenClaw 경로는 **중앙값 약 30초, 최악 106초.**

| | 초 | 근거 |
|---|---|---|
| 첫 호출 프롬프트 처리 | **17.8** | 5,247 토큰 ÷ 295 tok/s |
| `openclaw` CLI 기동 (node) | **약 8** | `operate/notes/agent-gateway.md §7-6b` |
| 생성 + 툴 왕복 | 나머지 | 왕복 하나가 프롬프트 재처리 + 생성 |

## ★ 프롬프트 캐시는 이미 걷었다 — 원인이 아니다

*"매번 주입받아서 느린 것 아니냐"* 를 재봤더니 아니었다. 같은 세션 3턴에서 새로
처리한 양이 2,953 → 802 → **265** 토큰. 새 세션의 첫 턴조차 `cacheRead 8,108`.

턴2 는 새로 처리한 것이 802 토큰(≈2.7초)뿐인데 **43초**였다 —
**나머지는 생성이다.** 8B 가 9.4 tok/s 라 255 토큰이 27초.

## 줄일 수 있는 것 둘

1. **CLI 기동 8초** — 게이트웨이 WS 에 파이썬으로 직접 붙으면 대부분 없앤다
   (WS 101 upgrade 는 08-17 에 확인). **덤으로 node 프로세스 350MB 도 사라진다**
2. **왕복 수** — `day` 를 필수로 만들자 `plan-write` 가 한 바퀴 줄어
   30.7 → 24.6초. **스키마로 왕복을 줄일 수 있다**

## 못 줄이는 것

OpenClaw 골격 약 1,400 토큰. 안 쓰는 기능(`sessions_spawn`·canvas·messaging) 설명이
대부분인데 빼는 설정을 못 찾았다. `experimental.localModelLean` 이 그 자리인데
**8B 에서는 못 쓴다** (`operate/notes/agent-gateway.md §7-3`).

미검증: `--cache-reuse N`. **`--parallel` 증설은 하면 안 된다** — 슬롯이 KV 를
배수로 잡아 ctx 가 반토막 난다.
