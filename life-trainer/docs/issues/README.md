# issues/ — 열려 있는 문제

**아직 안 고친 것을 한 건에 한 파일로 남긴다.** 고치면 [`../../HISTORY/`](../../HISTORY/) 로
옮기고 여기서 지운다.

## 왜 파일을 나누나

[`../known-issues.md`](../known-issues.md) 가 이 일을 하고 있었는데, 한 파일에 번호로
쌓이다 보니 **항목마다 상태 갱신이 인용 블록으로 겹겹이 붙었다**(§1 이 그 예다).
어느 것이 지금 사실인지 읽어서 판별해야 하는 문서는 오래 못 간다.

한 건에 한 파일이면 **파일의 존재 자체가 상태다** — `HISTORY/` 와 같은 규칙이고,
루트 README 가 말하는 "폴더가 곧 상태다"와도 같다.

## 규칙

### ★ 번호를 새로 붙일 때

**접두어 붙은 파일도 같이 본다.** 2026-09-07 에 `0028` 을 붙였다가 옮겼다 —
`w-0028` 이 이미 있었는데 `ls` 로 훑을 때 접두어 때문에 눈에 안 들어왔다.

```bash
ls docs/issues/*.md | grep -oE '[0-9]{4}' | sort -u | tail -3
```

### 파일명이 곧 상태다

**파일을 열지 않고 `ls` 만으로 무엇이 급한지 알 수 있어야 한다.** 접두어 한 글자로 표시한다.

| 접두어 | 뜻 | 언제 |
|---|---|---|
| *(없음)* | **풀어야 하는 문제** | 기본값. 아직 안 고쳤고 고쳐야 한다 |
| `h-` | **half — 일단 동작은 한다** | 우회로가 있어 당장은 안 막힌다. 근본 원인은 남아 있다 |
| `n-` | **no — 고치지 않기로 했다** | 명시된 한계. **왜 안 고치는지가 첫 줄에 있어야 한다** |
| `p-` | **pass — 덜 중요** | 실재하는 문제지만 지금 순위가 아니다 |
| `w-` | **watched — 알려진 채로 둔다** | **재 보고 지금 판정에 만족한 것.** 고칠 수 있지만 굳이 안 한다 |

```
0001-search-query-bypasses-the-gate.md   ← 풀어야 함 (맨 위로 온다)
h-0002-….md
n-0003-….md
p-0004-….md
```

숫자가 소문자보다 먼저 정렬되므로 **급한 것이 저절로 맨 위에 온다.** 그리고
**접두어를 빠뜨리면 "풀어야 하는 문제"가 된다** — 실수가 안전한 쪽으로 떨어지도록
접두어 없음을 기본값으로 뒀다. 반대로 했으면 깜빡한 파일이 조용히 묻힌다.

알파벳 순서가 급한 정도와 반대로 간다 — `h` → `n` → `p` → `w`. 손대야 하는 것이
위에, 안 손대기로 한 것이 아래에 온다.

### `w-` 와 `n-` 은 다르다

| | 왜 안 고치나 |
|---|---|
| `n-` | **못 고치거나 고치면 안 된다.** 바깥에서 온 한계다 (예: `n-0012` 못 읽는 사이트들) |
| `w-` | **고칠 수 있다. 재 보니 지금이 낫다고 판단했다** |

`w-` 에는 **그 판단의 근거가 숫자로 있어야 한다.** "별로 안 중요해 보인다" 는 `p-` 다.
근거가 있으니 나중에 조건이 바뀌면 다시 재서 올릴 수 있다 — 그게 `n-` 과의 실질적인 차이다.

### 그 외

- 파일명: `[접두어-]NNNN-짧은-슬러그.md` — **발견 순서대로 4자리 번호.** `0001` 부터
- **번호가 이 이슈의 이름이다.** 커밋 메시지·테스트 이름·다른 문서에서 이걸로 부른다:

  ```
  git commit -m "게이트와 발송 문자열을 일치시킨다 — issues/0001"
  def test_issue_0001_gate_and_sent_string_agree(): ...
  ```

  날짜 파일명으로는 이게 안 된다. **부를 수 없는 이름은 이름이 아니다.**
- 발견일은 **파일 안**에 적는다 (`- **발견일**:`). 파일명이 들고 있을 이유가 없다
- 다음 번호: **아래 색인의 마지막 번호 +1.** 고친 이슈는 파일을 지우므로 `ls` 로
  세면 닫힌 번호를 다시 쓸 수 있다.

  ```bash
  grep -oE '`0[0-9]{3}`' README.md | grep -oE '[0-9]{4}' | sort -n | tail -1
  ```
- 상태가 바뀌면 **접두어만 갈아끼운다** (`git mv`). 번호·슬러그는 절대 안 바꾼다
- **고치면 파일을 지운다.** git 이 갖고 있고, 닫는 커밋이 `issues/0001` 로 부른다.
  `HISTORY/` 로 **옮기지 않는다** — 아래를 볼 것
- **재현 가능한 것만 쓴다.** 심증은 "아직 모르는 것"에 적고 단정하지 않는다
- `n-` 은 드물어야 한다. 늘어나면 그건 이슈 목록이 아니라 변명 목록이다
- 아래 항목을 채운다:

```markdown
# 제목

- **상태**: 열림 / h·n·p 면 그 판단의 근거를 여기 쓴다
- **발견**: 어떻게 드러났나
- **증상**: 사용자가 보는 것 · 실제 관측값
- **재현**: 그대로 붙여넣어 확인할 수 있는 명령
- **원인**: 무엇을 사실이라고 잘못 믿었나
- **영향**: 무엇이 위험한가 (범위를 넓게 잡는다)
- **아직 모르는 것**: 확인 안 된 것을 명시한다
- **고칠 것**: 후보와 그 근거
```

## `HISTORY/` 와의 관계 — 생애주기가 아니라 다른 물건이다

**여기의 이슈가 자라서 `HISTORY/` 항목이 되는 게 아니다.** 두 폴더는 답하는 질문이 다르다.

| | 답하는 질문 | 값이 언제 |
|---|---|---|
| `issues/` | **지금 무엇이 고장나 있나** | 고치면 0 이 된다. 작업 큐다 |
| [`../../HISTORY/`](../../HISTORY/) | **무엇을 사실이라 잘못 믿었나** | 고쳐도 안 줄어든다. 오래 남는 교재다 |

그래서 **자동 이관 규칙을 두지 않는다.** 둘은 비대칭이다:

- **포스트모템감이 아닌 이슈가 있다.** 오타·설정값·리팩터는 고치고 지우면 끝이다.
  전부 옮기면 `HISTORY/` 의 *"가정이 깨진 것만 쓴다"* 가 무너진다
- **이슈였던 적 없는 포스트모템이 있다.** 지금 `HISTORY/` 항목 상당수가 당일 발견·당일
  수정이라 열려 있던 적이 없다. "이슈를 거쳐야 한다"는 규칙은 그 길을 막는다

**연결은 번호로 한다.** 가정이 깨진 이슈였다면 `HISTORY/` 항목 본문에 `issues/0001` 을
적는다. 폴더를 옮기는 게 아니라 **가리킨다.**

> **`0008`·`0009`·`0010` 은 2026-08-28 에 `p` → `h` 로 올렸다.**
> 셋이 **하나의 사슬**이 됐기 때문이다 — 에이전트가 대화의 기본값이 되면서
> `0010` 의 질문이 *"모델이 왜 틀리나"* 에서 *"채점기와 실사용 중 무엇이 현실인가"* 로
> 바뀌었고, 그걸 가르려면 `0008`(실데이터에 쓴다)·`0009`(손으로 심어야 한다)를
> **먼저** 닫아야 한다. 셋 다 우회로가 있어 안 막히지만(사람이 되돌리고·심고·실사용을 믿는다)
> **근본 원인이 남아 판단을 막고 있다** — 그게 `h` 다.
>
> `0016` (큐 판정이 누적 실패율이었다) 은 **2026-08-28 에 닫혔다.**
