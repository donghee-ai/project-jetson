## 추가된 기능

### 1. 야간 배치 — `lt nightly` + 02:00 타이머

`summarize_doc`·`tag_activity` 핸들러는 08-16 에 만들어졌는데 **큐에 넣는 곳이
없었다.** `enqueue()` 호출부가 온 저장소에 예약 알림 하나뿐이라 상시 워커가 설치
이후 실질적으로 놀았다 (문서 2,976건 중 요약 0건, LLM 태깅 0건).

```
lifetrainer/llm/nightly.py   적재만 한다 (LLM 을 부르지 않는다)
lt nightly [--summaries N] [--tags N] [--dry-run]
systemd/lifetrainer-nightly.{service,timer}   매일 02:00
```

- **새 프로세스를 안 띄운다.** 처리는 이미 5초마다 폴링하는 상시 워커가 한다.
- **점수 상위 20건만.** 2,976건 × 20초 = 16시간이다. 전부 요약하지 않는다.
- **`dedupe_key` 로 멱등.** 타이머가 두 번 뛰거나 사람이 한 번 더 돌려도 같은
  문서가 두 번 들어가지 않는다. 태깅 잡은 `tag_activity:<하루>` 로 하루 한 건.
- **우선순위 200** — 예약 알림(기본 100)보다 **뒤**다. 시각이 곧 약속인 알림이
  배치 뒤에 서면 안 된다.

### 2. 대화 우선권 — `data/interactive.lock`

배치를 켜면 반드시 필요한 짝이다 ([rag-plan §4](../rag-plan.md)). llama-server 가
`--parallel 1` 이라 **워커가 요약 1건을 집는 순간 Slack 질문이 그 뒤에 선다.**
평소 2초짜리가 20초 이상이 된다. `data/gpu.lock` 은 워커끼리만 막는다.

```
llm/interactive.py   대화 턴 = 공유 락(LOCK_SH) · 워커 = 배타 락 비차단 시험
llm/worker.py        claim 하기 전에 물어보고, 잡혀 있으면 GPU 잡을 뺀다
llm/converse.py      턴 전체를 락 안에서
```

- **공유 락인 이유**: 두 채널에서 동시에 대화해도 서로 막으면 안 된다.
- **`reminder` 는 안 미룬다.** LLM 을 안 쓰고 시각이 곧 약속이다. 미루는 것은
  `GPU_KINDS`(`summarize_doc`·`tag_activity`)뿐이다.
- **락을 못 잡아도 아무것도 안 막는다.** 대화는 락 없이 진행하고, 락 파일을 못
  열면 배치는 계속 돈다 — 편의 기능 때문에 본 기능이 멈추면 안 된다.

### 3. 게임 카테고리 (9번째)

실제 미분류 목록 상위에 게임 실행 파일이 반복됐다. 개인별 게임명·사용량은 공개본에서 제거했다.
규칙에 게임이 **한 항목도** 없었다 (기존 23항목 → 28항목, 게임 5항목 추가).

**열거로는 못 따라간다** — 스팀 하나만 해도 게임이 수만 개다. 그래서 순서를
모양 → 런처 → 개별 타이틀로 잡았다.

| 규칙 | 무엇을 잡나 |
|---|---|
| `-Win(32\|64)-Shipping\.exe$` | **언리얼 패키징 규약.** 타이틀을 몰라도 잡힌다 |
| 런처 16종 | steam · Riot Client · NexonPlug · Battle.net · BlueStacks … |
| 개별 타이틀 22종 | 미분류에서 실제로 나온 것 + 흔한 것 |
| `javaw.exe` + 제목 `minecraft` | 앱만으로는 개발용 JVM 과 못 가른다 |
| URL `op.gg\|lolchess.gg\|inven…` | 전적 검색은 영상 시청이 아니다 |

**게임을 만드는 것은 여전히 코딩이다** — `unity.exe`(coding/gamedev) 규칙이 §3 에
있어 게임 섹션보다 먼저 평가된다. 여가(entertainment)에서 런처를 빼냈고 영상·음악은
그대로 뒀다. Slack 이모지도 갈라졌다 (게임 🎮 / 여가 🍿).

#### ★ 9번째 색을 눈대중으로 고르지 않았다

dataviz 스킬의 검증된 팔레트는 **8슬롯이 전부**이고, "9번째 계열색은 만들지 말고
Other 로 접어라"가 스킬의 명시적 규칙이다. 그런데 활동 카테고리는 계열이 아니라
**격자 한 칸의 정체**라 접을 수가 없다 — 칸은 반드시 무언가로 칠해진다.

그래서 OKLCH 공간을 전수 탐색했다. 색상 6°, 명도 4단, 채도 5단(후보 1,800개)을
돌려 **기존 8색 전부와의 최소 ΔE** 를 계산하고 하드 게이트를 통과하는 것만 남겼다.

```
라이트 #8f2165   기존 8색 대비 최악 CVD ΔE 11.4 (vs browsing) · 정상시야 17.4
다크   #974dad   기존 8색 대비 최악 CVD ΔE  9.0 (vs coding)   · 정상시야 14.2
9색 adjacent 검증  light ALL PASS / dark ALL PASS
```

기존 8색끼리도 all-pairs 로 재면 다크에서 CVD 1.6 / 정상시야 7.1 인 쌍이 있다.
**새 색은 기존 팔레트가 자기들끼리 유지하는 것보다 멀리 떨어져 있다.**
그래도 all-pairs 실패 쌍은 그대로이므로 2차 인코딩(범례·직접 라벨) 규칙은 유지된다.

### 4. 웹 검색 — 한국어는 네이버, 그 외는 Serper

`fetch_url` 은 **URL 을 알아야** 읽는다. 그래서 모델이 도메인을 지어냈다 —
"롤체가 뭐야" 에 `valorant.com` 을 열고 뒤이은 세 턴이 전부 같은 틀린 출처를
인용했다 ([known-issues §1](../known-issues.md)). 검색이 그 구멍을 메운다.

**구글은 길이 막혀 있다.** Custom Search JSON API 는 신규 가입이 닫혔고
(기존 고객도 2027-01-01 종료), 대안인 Vertex AI Search 는 도메인 50개 이하
사이트 검색용에 GCP 과금이 전제다. 그래서 **언어로 나눈다**:

```
llm/websearch.py    한글이 있으면 네이버(하루 25,000건 무료), 없으면 Serper
llm/tools.py        web_search 툴 (게이트) — 검색과 읽기를 함께 싣는다
llm/trigger.py      "뭐야/뭔지/검색" 계열 추가 + 개인 기록 질문은 제외
config [search]     키는 gitignore 되는 lifetrainer.toml 에만
lt doctor           10번째 항목: 검색 키 상태 (없으면 WARN + 넣는 법)
```

- **질의어만 나간다.** 활동 기록·창 제목·계획은 절대 싣지 않고, 질의어도
  120자에서 자른다 — 모델이 맥락을 통째로 검색어에 넣는 것을 막는 방어다.
- **어느 엔진으로 갔는지 결과에 박는다.** 키가 하나만 있으면 다른 쪽으로 넘어가는데,
  그걸 안 밝히면 그게 곧 [지난번 폴백 사고](../../HISTORY/2026-08-18-search-fallback-noise.md)다.
- **검색은 목록만 준다.** 근거가 필요하면 `fetch_url` 로 **서로 다른 두 곳 이상**을
  열게 툴 결과에 못박았다 — known-issues 의 C안(교차 확인)을 여기서 같이 해결한다.
- 키가 없으면 나머지는 그대로 돌아간다. `lt doctor` 가 WARN 으로 알려준다.

#### ★ 실사용에서 바로 터졌다 — 그리고 08-18 의 서술이 틀렸다는 게 드러났다

키를 넣기 전에 사용자가 Slack 에서 "롤체가 뭐야?" 를 물었고, 봇이 **주입된 활동
요약을 읽고** "롤체는 사용자의 활동 분석 도구" 라고 답했다. 원인이 세 겹이었다:

1. **상주 서비스가 옛 코드로 돌고 있었다** (11:46 기동 vs 13:55 코드 변경)
2. **`tool_choice="required"` 가 보장이 아니었다** — 본문을 먼저 쓰고 나서 툴을
   부른다. 08-18 의 "실측 확인" 은 툴이 하나뿐이라 차이가 안 나는 조건이었다
3. **주입 문장으로도 안 막혔다** — "추측하지 마라" 를 넣자 지어내는 대상만 바뀌었다

→ **선주입 + 구조적 거절**로 바꿨다. 검색 키가 없고 주소도 없으면 **모델을 아예
부르지 않고** 거절 문장을 반환한다(0.0초). 전문은
[HISTORY](../../HISTORY/2026-08-19-required-tool-choice-is-not-a-guarantee.md).

```
"롤체가 뭐야?"        0.0초 · 거절 + 키 넣는 법   (기존 41초, 지어냄)
"깃허브 트렌딩 1위?"  15.9초 · fetch_url 로 실제 답 (기존대로 동작)
"오늘 뭐 했지?"       5.5초 · 내 기록으로 답       (영향 없음)
```

#### 제외 규칙을 처음에 너무 넓게 잡았다

"뭐야" 를 웹 트리거에 넣으면서 "내 오늘 일정이 뭐야" 까지 걸리는 것을 막으려고
시간 낱말(`오늘|어제|이번 주`)로 뺐더니 **"오늘자 뉴스 뭐 있어?" 가 통째로 죽었다.**
기존 테스트가 잡아냈다. 시간 낱말이 아니라 **개인 기록 낱말**(계획·일정·달성률·
플래너 + `내/제/나의`)이 함께 있을 때만 뺀다.

처음 한도가 20건(≈8분)이라 **02:10 이면 끝났다.** 남은 문서 2,929건을 그 속도로

- **예약 알림은 안 건드린다.** 사람에게 한 약속이다.
- **진행 중인 1건은 끝낸다.** 약 20초짜리를 죽일 이유가 없다.
- ★ `cancelled` 로 표시하지 않고 **삭제**한다. `dedupe_key` 가 UNIQUE 라 취소 행이
  남으면 그 문서는 **다음 밤에 다시 큐에 못 들어간다.** 테스트로 고정했다.

## 플래너 UI 개편 — 시안 3종 (조사 당시 기록, 아래 §8에서 구현)

현재 화면의 문제를 9개 항목으로 적고([docs/design/README.md §0](../design/README.md)),
같은 날 같은 데이터로 시안 3종을 그렸다. 색은 전부 `palette.yaml` 에서 뽑아 쓴다 —
시안 HTML 안에 hex 는 한 글자도 없다.

이 절은 선택 전 조사 기록이다. 최종 선택과 구현 결과는 아래 **§8**에 이어 적었다.

| 시안 | 전제 | 핵심 |
|---|---|---|
| A 종이 | 지금 구조가 틀린 게 아니라 덜 다듬어졌다 | 격자 간격 0 헤어라인 · 연속 블록 병합 · 자리비움은 사선 |
| B 계기판 | 6칸 줄바꿈은 종이의 제약이지 화면의 제약이 아니다 | 계획 레인 \| 실측 레인 · 빈 구간 접기 · 길이 비례 블록 |
| C 차분 | 폰에서 하루 열 번 여는 화면이다 | 현재 시각 + 지금 걸린 계획이 주인공 · 격자 대신 레일 |

**공통으로 고치는 것**: 날짜 중복 표기, **현재 시각이 아예 없던 문제**, 격자를 덮던
검은 `NOW` 알약, 144개로 흩어진 칸, 활동처럼 보이던 자리비움, 안 나온 카테고리까지
띄우던 범례.

### HTML → PNG 실측 (질문에 대한 답)

Slack PNG 를 matplotlib 좌표 계산 대신 헤드리스 크로미움으로 찍을 수 있는지 쟀다.

```
HTML → PNG (chromium headless, 콜드)   1.71s   PSS 최대 197 MB
matplotlib (lt planner)                1.47s   peak RSS  76 MB
```

+0.24초 / +121MB(일시). 크로미움·node 는 이미 깔려 있다. 얻는 것은 **웹과 PNG 의
이중 구현 제거** — 이 이중화는 이미 사고를 냈다
([6시간 밀림](../../HISTORY/2026-08-18-planner-row-offset.md)).

근거·미결 항목은 [docs/design/README.md §2](../design/README.md).

### 7. Slack 앱 매니페스트 적용 스크립트

명령어 예시를 대학생 기준으로 바꿨는데 **Slack 입력창에는 옛 예시가 그대로** 떠
있었다. 힌트는 Slack 쪽 앱 설정에 저장돼 있고 저장소 JSON 은 사본이기 때문이다.

`scripts/apply-slack-manifest.sh` — 설정 토큰(xoxe-)으로 `apps.manifest.update` 를
친다. **적용 전에 현재 매니페스트를 `data/backup/` 에 내려받는다.**
권한이 바뀌면 재설치가 필요하다는 것도 결과에서 알려준다.

> 오늘만 같은 부류를 두 번 밟았다 — 상주 서비스(옛 코드), Slack 앱 설정(옛 힌트).
> **파일을 고치는 것과 실물이 바뀌는 것은 다르다.**

## ★ 폰 사용 기록 수신 — 젯슨 쪽 (Phase 1~2)

조사([android/docs/research.md](../../android/docs/research.md))만 있던 항목을 실제로
붙였다. **폰·포크는 아직 없다.** 폰 없이 만들 수 있는 젯슨 쪽을 먼저 끝냈고,
계획은 [android/docs/plan.md](../../android/docs/plan.md) 에 있다.

### 조사 문서의 전제 3개가 소스 확인으로 바뀌었다

aw-android·aw-server-rust 소스를 직접 읽었다. 조사는 이슈·공식 문서만 본 것이었다.

| 조사 문서 | 소스 확인 |
|---|---|
| 버킷 타입 판별 "실물 확인 필요" | **우연히 맞고 있었다.** ID `aw-watcher-android` 엔 `window` 가 없지만 타입 `"currentwindow"` **안에** `window` 가 들어 있어 부분매칭에 걸렸다. 의도가 아니므로 명시 타입으로 바꿨다 |
| 이슈 #228 "내보내기가 조용히 실패" = 최대 위험 | **우리 경로와 무관하다.** 백엔드 REST export 는 정상(39ms 에 JSON 생성)이고, WebView 에 `DownloadListener` 가 없어 브라우저식 다운로드만 버려진다 |
| Syncthing 으로 우회 (젯슨을 안 열려고) | **데이터가 나가도 된다**고 제약이 바뀌어 직통(Cloudflare Tunnel)으로 간다 |

### 추가된 기능

- **버킷 타입 분리** — `android`/`unlock` 을 자기 이름으로 받는다(`aw_sync.bucket_type`).
  **메타 타입으로는 폰을 못 가른다** — 데스크톱 창 워처의 타입도 똑같이 `"currentwindow"`
  라서, 판별은 버킷 ID 로 한다. `aw_bucket.type` 에 CHECK 이 없어 마이그레이션은 없다
- **`POST /ingest/aw`** — 폰이 미는 경로. 이 앱에서 **공개 인터넷으로 열리는 유일한
  엔드포인트**라 검사 순서가 방어선이다: 켜져 있는가 → 크기 → 서명 → 형식.
  자체 완결형 토큰이 아니라 **본문에 묶은 HMAC 서명**이고(가로채도 내용을 못 바꾼다),
  시계 오차 창 + nonce 1회용으로 재전송을 막는다. **ingest 비밀키는 세션 비밀키와 별개**
  — 폰이 들고 있는 값이라 새더라도 플래너 세션이 열리면 안 된다
- **`lt import --from <파일|디렉터리>`** — adb 로 뽑은 표본과 장애 시 수동 복구용.
  네트워크 경로와 **같은 코드**(`collect/ingest.apply_payload`)를 쓴다
- **`device` 배선** — `upsert_bucket` 이 이제 `device` 행을 보장하고 `device_id` 를 채운다.
  예전엔 마이그레이션만 이 연결을 만들어서 그 뒤 새로 나타난 버킷은 NULL 로 남았다

### ★ 구조 변경 — 롤업에 기기 차원과 중재

**이게 본체였다.** `_fetch_day_events` 가 버킷을 기기 구분 없이 타입별 3개 리스트로
합치고 있었다. 폰을 그대로 붙이면 두 가지가 조용히 깨진다:

1. 폰 창 이벤트가 **노트북의 afk 구간**으로 클리핑돼 전부 `away` 가 된다
   (폰을 쓰는 동안 노트북은 당연히 afk 다)
2. 두 기기 활동이 한 슬롯에서 합산돼 **하루가 24시간을 넘는다**

중재 규칙은 **마지막 상호작용이 그 시간을 소유한다**:

```
폰 켜둔 채 노트북 작업  →  노트북   (노트북 활동이 더 늦게 시작했다)
노트북 작업 중 폰 만짐  →  폰       (폰 활동이 더 늦게 시작했다)
폰에서 손을 떼면        →  노트북이 도로 가져간다
```

구간으로 보면 "그 순간을 덮는 활동 구간 중 **가장 늦게 시작한 것**이 이긴다" 와 같다.
진짜 기기 전환은 언제나 나중에 시작하는 구간을 만들기 때문이다.

**순서가 중요하다: 흡수 → 중재.** `absorb_short_switches` 가 "이 3분은 앞 활동"이라고
정한 구간을 중재가 폰에게 되돌려주면 둘이 싸운다. 그래서 흡수 구간을 그 기기 소유로
**고정**한 뒤 중재한다 (반복 실패 2번의 예방).

안드로이드 → 공통 window 변환은 `_android_to_window` **한 곳**에서만 한다.
받을 때 자기 이름으로 받아둔 이유가 이것이다.

### 검증

```
테스트 858개 (826 → +32: 기기 중재 8, ingest 14, 버킷 타입 4, 기타)
lt doctor  OK 9 / WARN 1(검색 키) / FAIL 0
```

- **변이 검사로 이빨을 확인했다** — 중재를 무력화하니 하루 합이 **정확히 48시간**
  (172,800초)으로 부풀었다. 예측한 그대로다
- **실제로 돌려봤다** (임시 DB): 합성 노트북 하루 + 폰 export 25분을 겹쳐 넣고
  `lt import --rollup` → 하루 합 1.47h ≤ 24h, 슬롯 길이 초과 0개
- 그 과정에서 **버그 하나가 나왔다** — `cmd_import` 가 `rollup_day` 를 트랜잭션으로
  또 감싸 `cannot start a transaction within a transaction`. **테스트는 초록불이었고
  실행해야만 나왔다** (반복 실패 4번). 고쳤다
- 타임라인 PNG 를 열어 폰 25분이 20시 무렵에 **살아서** 찍히는 것을 눈으로 봤다

### 8. 플래너 웹 UI 리디자인 + Slack에서 웹으로 이어지는 조절 흐름

`docs/design/refs/10min_design/README.md`의 결론을 실제 화면에 반영했다. 1차 A+C

- 실시간 `HH:MM` 시계와 현재 10분 칸 안의 세로 재생헤드를 같은 타이머로 갱신
- 그날 사용한 카테고리만 범례에 표시, `10 20 30 40 50 60` 열 머리글 추가
- Apple식 컨트롤/콘텐츠 계층과 반응형, Toss식 수치 우선 요약과 단일 파란 CTA 적용

외부 코드·CDN·폰트는 추가하지 않았고 색은 계속 `palette.yaml` 단일 원본이다.

## 남은 것

- **`search_docs` 가 아직 요약을 안 싣는다** (rag-plan 2단계). `doc_fts.summary`
  컬럼은 이미 있고 요약도 이제 쌓인다 — 툴 결과 문자열에 첫 문장만 붙이면 된다.
  **툴 결과 길이가 곧 다음 턴의 입력**이라 전문을 실으면 안 된다.
- **임베딩(4단계)은 아직 시작하지 않는다.** 1~3단계 실측 없이 붙이면 "느려지기만 한
  RAG" 가 된다. FTS5 대비 이득을 재는 것이 선행이다.
- **`bambu-studio.exe` 가 새 미분류 1위** (3D 프린팅 슬라이서). 이제 야간 태깅이
  후보로 집는다 — LLM 이 제안한 카테고리를 보고 규칙으로 승격할지 판단하면 된다.
- **플래너 HTML→PNG 단일화** — UI는 반영됐지만 Slack PNG는 아직 matplotlib 폴백이다.
  `?export=1`과 GPU 잡 직렬화 후 교체한다.
- **검색 키를 넣어야 web_search 가 산다** — 네이버 developers 등록(무료) 후
  `config/lifetrainer.toml` 의 `[search]` 에. 넣으면 `lt doctor` WARN 이 사라진다.
- **키를 넣은 뒤 "롤체가 뭐야" 를 다시 물어봐야 한다** — 이 기능이 고치려는 사고가
  바로 그 질문이었다. 실호출로만 확인되는 종류다.
- **`rules.yaml` 에 안드로이드 패키지명 규칙이 하나도 없다** — 실측에서 폰 앱이 전부
  `미분류` 로 찍혔다(`com.kakao.talk`, `com.google.android.youtube`). 실물 표본을 본 뒤
  상위부터 규칙을 넣는다. 게임 카테고리 때와 같은 절차다.
- **폰 쪽은 아직 아무것도 없다** — [android/docs/plan.md](../../android/docs/plan.md)
  Phase 0(앱 설치 → 하루 대기 → adb 로 실물 표본)이 다음이다. `USER_INTERACTION`·
  `SCREEN_INTERACTIVE` 가 실제로 오는지가 포크 범위를 가른다.
- **Cloudflare Tunnel 은 아직 안 깔았다.** `[ingest] enabled` 는 기본 꺼짐이다 —
  공개 인터넷으로 열리는 유일한 경로라 켜는 것이 명시적인 행위여야 한다.
