# 밤 작업 — OpenClaw 통합 (자연어 대화 + 툴 콜링)

## 왜

슬래시 명령 10개는 만들어져 있었지만 Slack 앱에 등록이 안 돼 있었고, DM 대화는
OpenClaw 가 받고 있었다. **소켓은 워크스페이스 앱당 하나뿐이라 둘 다 가질 수 없다.**
Life Trainer 가 소켓을 가져오고, 자연어 대화를 직접 처리하기로 했다.

측정된 근거가 결정적이었다 — 같은 8B, 같은 llama-server 인데:

| | 시스템 프롬프트 | 첫 턴 |
|---|---|---|
| OpenClaw 경유 | **12,541 토큰** | **58.3 s** |
| Life Trainer 직행 | **165 토큰** | **1.9~9.5 s** |

## 아키텍처 — 3층 프롬프트 + 트리거 게이트

```
/lt /plan /del …   → 파싱 → SQL                      밀리초    (기존, 주 경로)
"오늘 뭐 했지"      → 3층 프롬프트 + 툴 4개 → SQL      1.9~9.5s  (신규)
"10분 뒤 알려줘"    → 트리거 → cron 툴 추가 주입        신규
```

프롬프트를 **변하는 주기 순으로** 3층으로 나눴다. llama.cpp 가 공통 접두사를 앞에서부터
재사용하므로, 자주 변하는 것일수록 뒤에 놓아야 캐시가 산다.

| 층 | 내용 | 변하는 주기 | 토큰 |
|---|---|---|---|
| ① 시스템 | 역할 + 오늘 계획 + 관심사 | 하루 | 165 |
| ② 툴 스키마 | 트리거가 고른 것만 | 턴마다 가능 | 271~595 |
| ③ user | 현재 시각 + **실측 활동** + 질문 | 매 턴 | ~35 |

**②가 ①을 안 깨는 것은 우리가 순서를 지켜서가 아니다.** Qwen3 채팅 템플릿의
`{%- if tools %}` 블록이 시스템 내용을 먼저 렌더링하고 `# Tools` 를 그 뒤에 붙인다
(`/props` 로 템플릿 직접 확인).

## ★ 트리거 게이트 — 툴을 필요할 때만 싣는다

프롬프트 처리는 295 tok/s 라 **스키마 토큰이 그대로 지연**이다. OpenClaw 의 `cron` 툴
하나가 3,912 토큰(툴 전체의 44%)이라 매 턴 13.3초를 더했다. 규칙으로 골라 실으면 0이 된다.

```
정확도   12/12
지연     평균 0.154 ms/건
기본     271 토큰 (조회 툴 4개)  →  최대 595 토큰 (트리거 2개 발동)
```

음성 쪽 핫패스 라우터(15/15, 0.193ms — `docs/plans/voice-agent-plan.md §2-5`)와 같은 구조다.

**재현율을 우선한다.** 비용이 비대칭이기 때문이다:

```
과잉 주입(FP)  안 쓰이는 스키마가 실려 0.5초 손해. 그걸로 끝.
누락(FN)       "내일 3시에 알려줘"에 툴이 없으면 "알겠습니다"로 끝난다. 에러도 안 난다.
```

## 자체 cron — OpenClaw 의 3,912 토큰짜리를 안 빌린다

`job` 테이블에 `not_before`·`dedupe_key`·`lease_until` 이 **이미 다 있었다**(미사용).
`claim` 이 `not_before <= now` 만 집어 오므로 **별도 스케줄러가 필요 없다.**

| | 토큰 | 매 턴 추가 지연 |
|---|---|---|
| OpenClaw `cron` | 3,912 | 13.3 s |
| 자체 예약 툴 3개 | ~213 | 0.7 s |

`patch-cron-schema.sh` 로 우회했던 GBNF `pattern` 400 함정도 처음부터 안 밟는다 —
`client._check_no_pattern` 이 이제 **툴 스키마까지** 검사한다.

# 낮 작업 — 레퍼런스 흡수 + 실기기 연결

## 추가된 기능

### 레퍼런스 흡수

`REFERENCE/` 에 들어온 자료 3개를 분석하고 개념만 가져왔다
(판단 근거: [REFERENCE/README.md](../../../refs/reference/README.md)).
**자동 계측이 실제로 도는 것은 우리뿐**이라 우리를 뼈대로 두고 갈아엎지 않았다.

| 흡수 | 출처 | 내용 |
|---|---|---|
| **논리적 하루 06:00** | slackbot2 | KST 06:00 → 다음날 06:00. `slot 0 = 06:00~06:10` |
| **계획 6단계 상태 + 이월** | slackbot2 | `todo/doing/done/partial/deferred/canceled`, `carried_from` 체인 |
| **사용자 정의 subject** | 종이 플래너 | 고정 카테고리 위에 얹는 층. 색은 검증된 8슬롯만 |
| **HMAC 원타임 링크 + 세션** | slackbot1 | 폰에서 Tailscale 없이. 1회용 토큰 → 쿠키 교환 |
| **슬래시 명령 전체 세트** | slackbot2 | `/plan` 확장문법, `/del` 체크박스+15초 실행취소 등 |
| **UI 언어** | harugyeol | 종이 표면, NOW 라인, 완료율 링, 주간 뷰, 바텀시트 |

### 새 테이블 5개 (28 → 33)

`plan_instance`(그날의 실체) · `plan_instance_event`(감사 로그) · `subject` ·
`day`(메모·D-Day) · `device`(기기 차원) + `v_carry_debt` 뷰(미루기 탐지)

**템플릿(`plan`)과 인스턴스(`plan_instance`)를 분리**한 것이 핵심이다.
분리하지 않으면 "오늘은 진행 중", "오늘은 연기" 같은 하루 단위 상태를 둘 자리가 없다.

### 슬래시 명령을 주 경로로 확정

측정된 근거가 있다 (`docs/build/openclaw-agent.md §3`):

| 경로 | 지연 |
|---|---|
| 슬래시 → 파싱 → SQL | **밀리초** (GPU 미사용) |
| OpenClaw 에이전트 경유 | 25~40초 |

속도보다 신뢰성이 결정적이다. 소형 모델은 툴을 안 부르고 "했습니다"로 끝내는 실패 모드가
있고 **에러가 안 난다.** 명시적 명령은 그게 구조적으로 불가능하다.
→ 자연어는 "나중에 할 것"이 아니라 **"주 경로가 아닌 것"** 으로 재정의했다.

### 외부 노출 대비 프라이버시 마스킹

`cfg.web.external = True` 면 응답에서 `top_title`·`top_app`·앱 이름·미분류 원문 제목을
제거하고 카테고리·시간만 내보낸다 (설계서 §10 위험표). 실측 22KB → 13KB, 누출 0.

> Cloudflare Tunnel 실제 노출은 **범위에서 뺐다.** 인증·마스킹을 먼저 검증하고,
> 터널은 사용자가 판단해서 켠다. 순서를 거꾸로 하면 위험하다.
