# 2026-08-16

## 한 줄

빈 저장소에서 시작해 **Phase 0~2 완주 + Phase 3 골격**, 그 위에 설계서에 없던 **플래너**까지.

## 추가된 기능

### 기반
- SQLite 스키마 28테이블 (WAL, `synchronous=FULL`, FTS5 트리거)
- 설정 계층 — TOML + 환경변수 + **OpenClaw 토큰 자동 폴백**
- 시간 유틸 — 144슬롯 인덱싱, RFC3339 파싱, 기간 문자열(`1h30m`, `평일`)

### Phase 1 — 활동 로깅 (설계서가 "실사용 가치의 70%" 라 한 부분)
- ActivityWatch REST 클라이언트 (`aw-client` 패키지 안 씀 — Bearer 인증을 못 보낸다)
- **이중 계산 방지 동기화** — 겹침 재조회 + `(버킷, 시작시각)` upsert
- 규칙 분류기 47개 (Windows/Linux/macOS 실 프로세스명, URL·제목 규칙)
- 144슬롯 롤업 + **AFK 클리핑** (자리비움 중 켜진 창은 활동이 아니다)
- 타임라인 PNG, Slack 일일/주간 리포트
- 합성 데이터 생성기 — AW 없이 파이프라인 전체를 검증하기 위한 것

### Phase 2 — 웹 수집
- 예의 계층: 도메인별 토큰버킷(2초, arXiv 3초), 조건부 GET, 적응형 주기, robots.txt
- RSS/arXiv 수집, SHA-256 + SimHash 중복 제거
- 키워드 스코어링, 아침 다이제스트 (**LLM 없음**)

### Phase 3 — LLM 골격
- OpenAI 호환 클라이언트 — 기존 `llama-server:8080` 공유 (전용 서버 안 띄움)
- **JSON 스키마 `pattern` 검증기** — 있으면 즉시 거부
- GPU 작업 큐 + `fcntl` 락으로 워커 1개 강제

### 플래너 (설계서에 없던 것)
사용자가 남긴 종이 플래너 레퍼런스가 **24행 × 6칸 = 144칸**이라 우리 슬롯과 정확히 같았다.
- 계획 계층 (반복/일회성), 수동 칸 보정(`slot_override`)
- 웹 플래너 — 계획 CRUD, 드래그 범위 선택, 다크/라이트
- 플래너 PNG (종이 양식)
- **검증된 팔레트** — `config/palette.yaml` 단일 원본

## 구조 변경

- **전용 모델 서버를 안 띄운다.** 8B@40960 이 이미 10.4GB. 기존 8080 공유
- **Docker 안 씀.** 미설치 + 16GB 에서 컨테이너는 낭비. venv + systemd
- **집계 원천은 `slot_breakdown`.** `slot` 의 winner-takes-all 은 시각화 전용
- **Slack 2단계** — 지금은 발송 전용(기존 토큰), 전용 앱은 준비만
