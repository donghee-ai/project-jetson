## 추가된 기능

### `fetch_url` — 공개 웹 페이지 읽기

원래 이 프로젝트는 "기기 밖으로 안 나가는 내 데이터에 답한다"가 원칙이었다
(핸드오프 §7-B). 사용자가 명시적으로 범위를 넓혀 달라고 해서 **읽기 전용**으로 붙였다.

```
llm/webfetch.py   SSRF 가드 + HTML→텍스트 + 메뉴 접기
llm/tools.py      fetch_url 툴 (게이트) + 출처 라벨
collect/http.py   PoliteSession.get(allow_redirects=) 추가
```

**허용목록(allowlist)은 두지 않았다.** 안전 경계는 도메인이 아니라 IP다. 실제로
처음 보는 사이트 6곳(위키·연합뉴스·python docs·PyPI·BBC·arXiv)에서 바로 동작했다.

### ★ `is_private` 로 막으면 뚫린다

```
ipaddress.ip_address("100.64.0.2").is_private  →  False   ← 젯슨 웹 플래너
ipaddress.ip_address("100.64.0.2").is_global   →  False
```

Tailscale 이 쓰는 100.64.0.0/10(CGNAT)은 `is_private` 에 안 잡힌다. **`is_global`
이 참인 주소만** 허용해야 사설·루프백·링크로컬·예약·CGNAT 이 한 번에 걸린다.
이 기기에는 웹 플래너(창 제목이 담긴 개인 기록)·llama-server·노트북 ActivityWatch 가
붙어 있고, **URL 은 모델이 고른다** — 외부 RSS 에서 흘러들어온 문자열이 요청 대상이
될 수 있다.

리다이렉트도 홉마다 재검증한다. 첫 URL 만 보고 자동 추적에 맡기면 302 한 번에
방어가 무의미해진다.

### HTML → 텍스트 (의존성 0)

`beautifulsoup` 을 안 썼다 — 상주 300MB 제약이 있고 필요한 건 태그 제거뿐이다.
표준 `html.parser` 로 충분했다. 대신 **"짧은 줄이 25줄 이상 연속되면 메뉴"** 라는
모양 기반 필터를 넣었다.

```

```

`<details>` 를 통째로 버리는 방법도 있었지만 다른 사이트의 접힌 **본문**까지 잃는다.

잘못은 폴백 설계에 있었다.

### 고친 방법 — 프롬프트가 아니라 구조

1. **트리거 확장**: `급상승·순위·N위·유튜브·홈페이지·공지·소식·"뭐라고 적혀"` 등
2. **`tool_choice="required"`**: 웹 트리거가 걸린 턴은 첫 바퀴에 툴 호출을 강제한다.

   > ### ⚠️ 2026-08-19 정정 — 이 서술은 틀렸다
   >
   > `required` 는 **본문 생성을 막지 않는다.** 모델이 틀린 답을 300토큰 쓰고 나서
   > 툴을 부르고(35초 낭비), `max_tokens` 가 먼저 끝나면 툴 호출은 아예 안 나온다.
   > 여기서의 "실측 확인" 은 툴이 하나뿐인 조건이라 `required` 유무에 차이가 없었다.
   > → 지금은 **검색을 선주입**하고, `required` 는 사용자가 URL 을 준 턴에만 쓴다.
   > [자세한 기록](../../HISTORY/2026-08-19-required-tool-choice-is-not-a-guarantee.md)
3. **출처 라벨**: 툴 결과에 `[웹 · 구글 검색어 급상승 (유튜브 급상승이 아님)]` 을 박았다.

   프롬프트로는 안 잡혔다. 두 줄을 더해도 안 됐고 **온도를 낮추니 오히려 악화**됐다
   (뉴스 기사 제목을 유튜브 1위라고 답함). 라벨을 박으니 3/3 "확인하지 못했다".
4. **폴백 제거**: 0건이면 없다고 하고 **다시 찾을 낱말만** 준다. 무관한 결과를
   결과인 척 끼워넣지 않는다.

## ★ 기기 전환 흡수 (오후)

폰을 잠깐 만지면 컴퓨터 입력이 끊겨 afk 워처가 `away` 로 잡고 창 이벤트도 끊긴다.
그대로 두면 "코딩 10분 / 자리비움 3분 / 코딩 10분" 세 토막이 되는데, 사람이 보기에
그건 그냥 **코딩 23분**이다. 잠깐 딴짓까지 전부 찍히면 플래너를 읽을 수 없다.

`rollup.absorb_short_switches` — 슬롯으로 쪼개기 **전에** 하루 전체 구간에서
`switch_absorb_sec`(기본 300초) 미만이고 양옆이 모두 활동인 공백을 앞 활동으로 흡수한다.
5분 이상은 손대지 않는다(실제 자리비움이므로 플래너에 남아야 한다).

### 두 번 틀리고 세 번째에 맞았다

1. "afk 이벤트가 공백에 완전히 담길 때만 뒤집기" → 실데이터는 경계가 안 맞아
   (afk 590~800 vs 공백 600~780) 거의 안 뒤집혔고, 창만 늘어나 **away 가 늘었다**
2. 겹친 부분만 잘라내게 고쳐도 여전히 늘었다. 재보니 08-17 의 공백 751개(3,634초) 중
   **afk 가 관여한 건 187초뿐**이었다 — 나머지는 afk 이벤트가 **아예 없는** 구간이라
   잘라낼 게 없어 `active_portion=0` 이 되어 통째로 away 가 됐다
3. 잘라내는 게 아니라 **덮어야** 했다. 겹치는 afk 조각을 전부 제거하고 구간마다
   not-afk 를 하나씩 넣는다 (겹침 없이 정확히 한 번만 덮여 이중 계산이 안 된다)

### ★ 덤 — 두 소스 불일치가 같이 해결됐다

조사 중 별개 문제를 하나 찾았다. 헤더의 "활동 N시간"은 **afk 워처**에서, 아래
카테고리 합은 **window 워처**에서 온다. 두 워처는 원래 다른 걸 재므로 값이 갈렸다.

```
            활동(afk)      카테고리합(window)     격차
2026-08-17   3시간 25분     3시간 25분            6초    ← 흡수 전 589초
2026-08-18   7시간 40분     7시간 40분            9초    ← 흡수 전 1,254초
2026-08-19   1시간 45분     1시간 45분            3초    ← 흡수 전 171초
```

창 공백이 바로 두 소스가 갈리던 지점이었고, 흡수가 그걸 덮으면서 4~7% 불일치가
거의 사라졌다. 무결성(슬롯 초과·범위 이탈)은 그대로 0건.

### 시간 추적 자체는 정확했다

## 남은 것

- **검색 엔진이 없다.** URL 을 알아야 읽는다. 봇에게 정직하게 열린 검색이 없었다 —
  DuckDuckGo 는 우리 UA(`…bot`)에 202, 브라우저 UA 에만 200. Mojeek 은 403
  ("automated queries"). SearXNG 공개 인스턴스는 JSON 비활성/죽음/429.
  → 네이버·Brave 등 **API 키**를 받는 것이 정공법
- **JS 렌더링 사이트는 못 읽는다** (유튜브 급상승). 헤드리스 크로미움을 쓰려면
  가용 메모리가 필요한데 지금 343MB 뿐 — llama-server ctx 를 40960 → 16384 로
  낮춰 약 2GB 회수하는 것이 선결
- **야간 배치 미착수** — `summarize_doc`/`tag_activity` 핸들러는 있는데 **큐에 넣는
  곳이 없다.** 워커가 설치 이후 아무 일도 안 하고 있었다(문서 요약 0건, 미분류 태깅 0건)
- 배치를 켜면 **대화 우선권**이 필요하다. GPU 락은 워커끼리만 막고, 대화 경로는
  llama-server 를 직접 친다 — `--parallel 1` 이라 요약 1건(약 20초) 뒤에 줄 선다
