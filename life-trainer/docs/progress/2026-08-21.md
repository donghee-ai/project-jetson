## 폰 수집 — 게이트 전부 닫힘, 결론이 "포크 필요"로 확정

문서 작업과 별개로, 이날 오전에 폰 쪽 Phase 0 을 끝냈다.

### 젯슨 USB 가 폰을 인식하지 못하던 문제 — **콜드 부팅이 답이었다**

`usb 1-2: device not accepting address, error -71` 이 반복되고 폰뿐 아니라 마우스
동글·Wi-Fi 어댑터까지 사라졌다. **온보드 VIA USB 2.0 허브**가 열거에 실패한 것이었다.

**`sudo reboot` 으로는 안 고쳐진다.** 웜 리셋은 허브 칩의 전원 레일(`VDD_AV10_HUB`)을
끊지 않아 칩이 걸린 상태 그대로 올라온다. **전원을 완전히 뽑았다 켜니 한 번에 복구됐다.**

해봤자 소용없던 것(다시 하지 말 것): `usbcore.old_scheme_first=1` 커널 파라미터 ·
`tegra-xusb` unbind/bind(오히려 USB 가 통째로 내려갔다) · `journalctl --since "$(uptime -s)"`
로 오류 세기(부팅 시 RTC 가 어긋나 0건으로 잘못 나온다).

## 수정 — 야간 배치 503 (같은 날 오후)

원인이 **분류 한 곳**이었다. 재시도 기계는 이미 다 있었다.

```
client.py   status >= 400  →  LLMError        ← 503 이 여기로 샜다
worker.py   except LLMUnavailable:  attempts 안 깎음 · not_before +60s · break   ← 안 탔다
            except Exception:       fail() → attempts 소진 · 다음 잡 계속 집음   ← 여기로 갔다
```

`break` 가 핵심이다. 일시 장애일 때는 **뒤 잡을 건드리지 않고 멈춰야** 하는데,
영구 오류로 분류돼 있어서 큐 전체를 훑으며 태웠다.

| | 무엇 | 크기 |
|---|---|---|
| a | `_RETRYABLE_STATUS = {429, 502, 503, 504}` → `LLMUnavailable` | `client.py` 3줄 |
| b | `lt doctor` 큐 항목이 **실패율로 판정** + 대표 사유 표시 | `cli.py` |
| c | 죽어 있던 278건을 큐로 되돌림 (`not_before` = 다음 02:05) | 일회성 |

**b 를 먼저 썼다** — 고쳤는지 볼 수단이 먼저 있어야 한다. 이번 건을 이틀 못 본
직접 원인이 "doctor 가 `failed=278` 을 OK 로 찍는다" 였다.

```
[WARN] 큐   … 실패율 29% (278/967) — 대표 사유: LLM 서버가 503 …  ← 고치기 전
[  OK] 큐   cancelled=2, done=689, queued=278                    ← 되돌린 뒤
```

### 키를 넣고 실제로 물어봤다 — 세 턴이 서로 다른 이유로 틀렸다

doctor 는 `OK 10 / WARN 0` 이 됐고 검색 계층도 정답을 물어왔다. **그런데 Slack 답변은
여전히 틀렸다.** "롤체는 롤이라는 게임의 캐릭터입니다" + `leagueoflegends.com` 출처.
로그를 보고서야 원인이 갈렸다:

| 턴 | 로그 | 실제로 일어난 일 |
|---|---|---|
| `롤체는 무슨게임이야?` | `툴 [], 트리거 []` | **검색이 안 돌았다.** 모델이 URL 을 지어냈고 Slack unfurl 이 진짜처럼 보이게 했다 |
| `tft는 뭐야?` | `트리거 ['web']`, 검색 3건 | 검색은 됐는데 질의어가 원문 그대로 → TFT = Task Force Team |
| `게임 tft는?` | `툴 [], 트리거 []` | 검색이 안 돌자 **직전 답을 그대로 복사** |

#### 깨진 가정 ① — "키를 넣으면 검색이 돈다"

**트리거가 안 걸리면 키는 아무 일도 안 한다.** `_WEB_PATTERNS` 에 `어떤\s*게임` 은
있는데 **`무슨` 이 없었다.** 낱말 하나 때문에 검색이 통째로 죽었고, 그 자리를 모델이
기억으로 채웠다. `_must_refuse_web` 은 이 턴을 못 막는다 — 그건 "웹 질문인데 닿을
방법이 없을 때"의 게이트라, **웹 질문으로 분류되지 않은 턴**은 애초에 통과한다.

→ `무슨\s*(게임|회사|…)` 과 `X는?` 되묻기 형태를 넣고, 개인 기록 질문은 계속 빠지는
것을 테스트로 못박았다.

#### 깨진 가정 ② — "질문을 그대로 검색하면 된다"

`tft는 뭐야?` 는 사람이 봐도 모호하다. 앞 턴이 "롤체" 였다는 맥락이 질의어에 없으면
회사 용어(Task Force Team)와 박막트랜지스터가 온다. **`게임 tft` 로 바꾸면 1위가
롤토체스 공식이다.**

→ 질문이 15자 미만일 때만 **직전 사용자 질문의 낱말 2개**를 앞에 붙인다.
`tft는 뭐야?` → `롤체 tft는 뭐야?` (나무위키 전략적 팀 전투가 1위로 왔다).
★ 붙이는 것은 **사용자가 쓴 질문뿐**이다 — 모델 답변은 안 싣는다(틀린 답이 다음
검색을 오염시킨다). 활동 기록·창 제목은 애초에 `history` 에 없다.

#### 덤 — 키를 넣자 테스트 3개가 깨졌다

`test_websearch.py` 의 `cfg` 픽스처가 `load_config()` 를 그대로 써서 **이 기기의 설정
파일에 검색 키가 없다는 것에 조용히 기대고 있었다.** "키 없음"을 전제한 거절 테스트
3개가 한꺼번에 무너졌다. 픽스처가 키를 명시적으로 비우게 고쳤다 — 테스트는 기기
상태와 무관해야 한다.
