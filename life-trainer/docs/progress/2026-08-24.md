# 2026-08-24

## 한 줄

**Life Trainer 를 OpenClaw 의 에이전트 하나로 만들었다.** 툴을 고르는 주체가
규칙(`llm/trigger.py`)에서 **모델**로 바뀐 경로가 하나 더 생겼다. 슬래시 명령 10개를
Slack 없이 실행하고, 플래너·RAG 를 그대로 쓰며, **지정된 폴더 밖으로는 못 나간다.**

## 왜 만들었나 — 기존 경로와 무엇이 다른가

이 저장소에는 이미 자연어 대화가 있다(`llm/converse.py`). 다른 것은 **루프의 주인**이다.

| | 기존 (`llm/`) | 새 것 (`agent/`) |
|---|---|---|
| 프롬프트 조립 | 우리가 3층으로 | OpenClaw 가 |
| 툴 선택 | **규칙 게이트** (12/12, 0.154ms) | **모델이 고른다** |
| 지연 (실측) | 2~9초 | 26~48초 |
| 툴 | 트리거가 고른 것만 271~595토큰 | 13개 상시 2,874토큰 |
| 셸·파일 | 없음 | **감옥 안에서만** |

**빠른 쪽을 대체하지 않는다.** Slack 은 그대로 `llm/converse.py` 를 쓴다.
에이전트는 "규칙이 못 잡는 요청을 모델이 스스로 분해해 여러 툴을 엮는" 자리를 맡는다.
슬래시가 주 경로라는 원칙은 **에이전트 안에서도 유지된다** — `slash` 툴이 첫 번째다.

## 추가된 기능

### ① 경로 감옥 (`agent/sandbox.py`)

에이전트가 움직일 수 있는 폴더를 코드가 정한다. 기본값:

```
읽기   docs/  HISTORY/  config/  data/agent/
쓰기   data/agent/
```

- **`realpath` 로 접은 뒤 판정한다.** 문자열 비교로 짜면 `/data` 허가가
  `/dataX` 를 통과시킨다. 심링크 탈출도 같은 자리에서 막힌다
- **허용 폴더 안이어도 이름으로 거부한다.** `config/` 는 읽혀야 하지만
  `config/lifetrainer.toml` 에는 Slack 봇 토큰과 Serper 키가 있다.
  백업본(`*.bak-*`)도 같은 비밀을 갖고 있어 접두로 같이 막는다
- **읽기와 쓰기를 나눈다.** 규칙 파일이 조용히 바뀌면 롤업 결과 전체가 바뀐다
- **조용히 다른 곳에 쓰지 않는다.** `docs/x.md` 에 쓰라고 하면 거부한다.
  그냥 두면 `data/agent/docs/x.md` 에 **성공적으로** 써지고, 모델은 `docs/` 에
  썼다고 믿는다
- OpenClaw 의 `tools.fs.workspaceOnly` 를 믿지 않는 이유는 두 가지다:
  경계가 우리 것이 아니고(설정 하나로 움직인다), **MCP 툴은 게이트웨이의 fs
  정책을 거치지 않는다** — 우리 프로세스가 직접 파일을 연다

### ② 슬래시 명령 10개를 Slack 없이 (`agent/slash.py`)

`/lt /log /plan /del /view /done /doing /defer /memo /week`.

`slackio/app.py` 의 `_dispatch_*` 는 처음부터 `(cfg, …, respond)` 순수 함수로
분리돼 있었다. `respond` 자리에 수집기를 넣으면 그대로 돈다 — **명령 파싱을
두 번 쓰지 않는다.**

- **발송은 프롬프트가 아니라 구조로 막았다.** `cfg.slack.bot_token` 을 비운 사본으로
  부른다. `SlackNotifier.enabled` 가 False 가 되어 발송 경로 자체가 사라지고,
  준비된 폴백(`respond`)으로 결과가 온다. "보내지 마"라고 부탁하지 않는다
- **`/view`·`/week` 은 PNG 를 안 그린다.** 에이전트가 돌려주는 것은 텍스트고,
  `report.planner` 를 import 하면 상주가 **+44MB** 다 (실측 12.4 → 56.4MB)
- **보여 주는 번호와 조작하는 번호를 맞췄다.** `/view` 는 `ordinal` 을 쓴다 —
  `/done N`·`/del N` 이 받는 것이 그 번호다

### ③ MCP 서버 (`agent/mcp_server.py`) — 의존성 0

줄 단위 JSON-RPC 2.0. 필요한 메서드가 `initialize`·`tools/list`·`tools/call`·`ping`
넷뿐이라 SDK 를 안 들였다. 툴 13개:

```
slash · read_file · list_dir · write_file          새로 만든 것
get_plans · get_activity_summary · search_docs · compare_days
schedule_reminder · list_reminders · cancel_reminder
web_search · fetch_url                              llm/tools.REGISTRY 재사용
```

- **설명문을 다시 쓰지 않는다.** 이미 이 모델에 맞춰 다듬어진 문장이고,
  여기서 새로 쓰면 두 경로의 툴이 서로 다른 말을 하게 된다. 테스트가 고정한다
- **`add_plan` 은 안 내보낸다.** `/plan` 이 같은 일을 한다 — 같은 능력을 두 경로로
  주면 스키마 토큰을 두 번 내고 소형 모델이 헷갈린다
- **실패는 툴 결과 텍스트로 돌려준다** (`isError: true`). RPC 에러로 올리면
  게이트웨이가 턴을 끊어 모델이 다시 시도할 기회가 사라진다

### ④ 워크스페이스 프롬프트를 코드가 만든다 (`agent/prompt.py`)

명령표는 `slash.COMMANDS` 에서, 움직일 수 있는 폴더는 살아 있는 `Sandbox` 에서
가져온다. 마크다운에 손으로 베끼면 **같은 값을 두 곳에서 관리하게 된다** —
이 저장소의 반복된 실패 2번이다. 명령을 하나 더하면 프롬프트가 저절로 따라온다.

### ⑤ 채점기 (`scripts/eval_agent.py`)

**툴 선택으로 채점한다.** 답변 문장을 문자열로 채점하면 맞는 답이 틀린 답이 되는 것을
음성 쪽에서 이미 겪었고("이십사도"→"24도"), 결국 슬롯 정확도로 바꿨다. 여기서
슬롯에 해당하는 것이 툴 선택이다. 케이스 9개.

### 프롬프트 예산 — 12,541 → 5,247 토큰

`openclaw-agent.md §3` 의 12,541 토큰(첫 턴 41.6초)이 출발점이었다.

| | 토큰 | 근거 |
|---|---|---|
| OpenClaw 골격 | 약 1,400 | 실측 첫 호출 5,212 에서 우리 몫을 뺀 값 |
| 툴 스키마 13개 | 2,950 | `lt agent budget` (예산 3,000) |
| 워크스페이스 `AGENTS.md` | 973 | 예산 1,000 |
| **합계** | **약 5,323** | 첫 호출 프롬프트 처리 **18.0초** (295 tok/s) |

**어디서 줄였나 — 큰 것 두 개다.**

1. **`agents add` 가 깔아 두는 범용 인격 파일 6개** (`SOUL.md`·`IDENTITY.md`·
   `USER.md`·`TOOLS.md`·`HEARTBEAT.md`·`BOOTSTRAP.md`) = **6,122바이트**.
   게이트웨이가 전부 시스템 프롬프트에 넣는다.
   ★ **지우면 재기동 때 다시 만든다.** `nvpower.sh` 가 부팅마다 심링크를 되돌리고
   `daemon install` 이 유닛을 다시 만드는 것과 같은 부류다. **비워서 남긴다** —
   파일이 있으면 시드가 안 돈다
2. `AGENTS.md` 를 7,196바이트(7,199토큰) → **1,311자(973토큰)** 로

프롬프트 23,744자 → **10,455자**. 그 결과 **첫 턴 auto-compaction 이 0회**가 됐다
(전에는 1회 — `openclaw-agent.md §4-3` 의 그 실패였다).

★ **`experimental.localModelLean` 은 켜지 않는다.** 골격을 6,800자 줄여 주지만
툴 13개를 메타툴 3개(`tool_call`/`tool_search`/`tool_describe`)로 바꾸는 기능이라,
8B 가 그 간접층을 못 넘고 **`tool_call` 을 툴 이름으로 착각해 호출이 실패했다**
(실측). 툴이 20개를 넘는 에이전트를 위한 기능이지 우리 것이 아니다.

### 채점 — 실제로 답이 맞는가

`scripts/eval_agent.py` 9케이스. 툴 선택은 9/9 였는데, **답변을 읽어 보니 세 개가
틀려 있었다.** 채점표가 무른 것이었다.

- **`/done` 을 사용자에게 시켰다.** "1번을 완료로 바꿔줘" 에 `/view` 로 목록만 보고

  툴 이름만 채점하면 통과한다. → `require_slash` 를 넣어 **바꾼 흔적**을 요구한다.
  ★ 인자는 응답 JSON 에 없고 **게이트웨이 트레이스에만** 있다. 거기까지 읽는다
- **절대 경로를 조립했다.** "config 폴더 보여줘" 에 프롬프트에서 본 허용 폴더를
  이어 붙여 `…/data/agent/config` 를 불렀고, 없다고 나오자 **"config 폴더는
  존재하지 않아요"** 라고 답했다. §4-4 의 `workspace/workspace/` 와 같은 부류다.
  → 못 찾았을 때 결과에 "짧은 이름을 쓰라"는 한 줄을 붙이고 스키마 설명에도 박았다
- **숫자에 틀린 이름을 붙였다.** "어제랑 오늘 중 뭐가 더 코딩을 많이 했어?" 에

  `compare_days` 가 **증감만** 주고 카테고리별 절대값을 안 줬다. 붙일 숫자가
  결과에 없으니 눈에 보이는 숫자를 가져다 붙인 것이다.
  → 툴이 `gaming 4시간 56분→52분(-4시간 4분)` 으로 양쪽을 다 싣는다.
  프롬프트에도 "라벨을 바꾸는 것도 지어내는 것"을 넣었다

### 채점기가 스스로 무뎠던 곳 (읽으면서 고친 것)

**툴 이름만 채점하면 세 부류가 통과한다.** 실제로 통과시켰다가 답을 읽고 잡았다.

| 무엇을 놓쳤나 | 어떻게 고쳤나 |
|---|---|
| `/view` 만 하고 완료는 사용자에게 시킨 답 | `require_slash` — **바꾼 흔적**을 요구한다 |
| 날짜를 안 넘겨 계획이 오늘에 들어간 것 | `expect_day` — 어느 날짜에 갔는지 본다 |
| **툴 0건 · 본문 0자** 로 끝난 턴 | 답이 10자 미만이면 무조건 실패. **침묵이 오답보다 나쁘다** |

★ **툴 인자는 응답 JSON 에 없다.** `toolSummary.tools` 가 `["lt__slash"]` 라고만
알려 준다. 인자는 게이트웨이 트레이스에만 있어서 거기까지 읽는다.

★ `file-escape` 케이스는 반대로 **느슨하게** 고쳤다. 처음엔 `read_file` 호출을
요구했는데, 모델이 **아예 안 부르고 거절하는 것도 옳은 답**이라 그게 실패로 찍혔다.
여기서 볼 것은 "툴을 불렀나"가 아니라 **"내용이 새지 않았나"** 다 — 감옥이 막는다는
것은 단위 테스트가 이미 보증한다.

## (오전) Slack 을 에이전트로 연결했다

`[agent] slack = true`. **규칙이 무엇을 위임할지 고르지 않는다** — 자연어 DM 은
전부 에이전트가 받고 모델이 툴을 고른다.

```
/lt /plan /done …   Slack 슬래시 커맨드 API   → 밀리초        (안 바뀜)
자연어 DM            → OpenClaw 에이전트       → 약 30초        ★ 바뀐 곳
```

**슬래시가 안 느려지는 이유**: Slack 에서 슬래시 명령과 DM 텍스트는 **다른
이벤트**다. `_register_commands` 와 `_dispatch_chat` 이 갈라져 있어서 후자만 바꾸면
된다. "소켓을 OpenClaw 로 넘긴다"(안 A)가 위험했던 이유가 이것이었다 — 그러면
슬래시까지 에이전트를 경유한다.

**왜 자연어를 통째로 넘겼나**: 대화 경로의 툴 10개에 **상태 변경·삭제·메모·기록이
없다.** "1번 완료해줘" 를 물으면 8B 가 툴 없이 "완료했습니다" 라고 답하고 **에러가
안 난다.** 위임 규칙을 짜는 대신 경로를 옮겼다.

붙인 것:

- `agent/delegate.py` — 채널별 세션 키(히스토리를 게이트웨이가 관리) ·
  `interactive_turn` 락 · 타임아웃 · `MEDIA:`/`[[…]]` 지시자 제거
- `_Ticker` — 8초마다 "…N초" 로 고쳐 쓴다. 에이전트는 끝날 때 한 번에 답을 주므로
  중간 글이 없다. **총 시간은 안 줄지만 죽은 게 아니라는 것이 보인다**
- 실패하면 `converse()` 로 강등. 타임아웃은 **안 내려간다** — 이미 수십 초를 썼다
- 기본값 `false`. 설정이 없는 기기가 조용히 느려지면 안 된다

실측: "오늘 계획 뭐 있어?" 32.0초 · "스트레칭 추가해줘" 29.3초(추가 후 확인까지).

### ★ 그리고 여기서 데이터가 틀어지는 버그가 나왔다

"오늘 목록 보여주고 **'집중근무'** 완료 처리해줘" 에 8B 가 목록도 안 보고
`/done 1` 을 불렀다. **1번은 '근무' 였다** — 엉뚱한 계획이 완료로 바뀌었고 에러는
없었다. 채점기도 통과시켰다: `/done` 이 돌았으니까.

원인은 **번호밖에 못 받는 명령**이었다. 이름을 번호로 옮기는 일을 모델이 해야 했고,
그 변환이 곧 추측이다. 날짜에서 배운 것과 같은 자리다 — **모델에게 시키지 않는다.**

→ `/done`·`/doing`·`/defer` 가 **제목도 받는다.** 정확일치가 부분일치를 이기고,
애매하면 **아무것도 안 바꾸고** 후보를 보여준다. 하나를 골라 바꾸면 그게 또 추측이다.

→ 채점기에 `expect_status` 를 넣었다. **무엇을 했는지가 아니라 무엇이 바뀌었는지**를
DB 에서 확인한다. 이 저장소가 세 번째로 같은 것을 배웠다 —
행동을 채점하면 **엉뚱한 대상에 한 행동**이 통과한다.

## (오후) 실사용이 드러낸 것들 — 버그 6건과 측정 4회

Slack 에 붙이자마자 **사용자가 쓰면서 버그를 찾았다.** 전부 실사용 보고에서 나왔고,
채점기·테스트가 못 잡은 것들이다.

| # | 무엇 | 어떻게 드러났나 |
|---|---|---|
| 1 | 위임이 **조용히 강등**돼 있었다 (PATH) | 사용자: "답변 빠른데 엄청" |
| 2 | 한 시간 뒤 **Context overflow** | 사용자가 직접 겪음 |
| 3 | `/done 2 3` 이 **절반만** 처리 | 사용자가 둘을 시켰는데 하나만 |
| 4 | 웹 체크박스가 계획을 못 찾음 | 3번을 손으로 되돌리려다 막힘 |
| 5 | 패치가 **옆 함수에** 떨어짐 (수정하면 지워짐) | 고쳤다던 삭제가 여전히 안 됨 |
| 6 | `[90]` 을 모델이 **명령 번호로 씀** | 사용자: "이 번호 왜 붙어?" |

각각 [HISTORY](../../HISTORY/) 에 기록했다. **1·3·5 는 내가 만든 버그**이고,
셋 다 "조용히 다르게 동작하는 것" — 이 세션 내내 잡던 바로 그 유형이다.

### 날짜 문제 — 네 구성을 재서 원인을 찾았다

"어제 목록을 보여준 다음 턴에 완료 처리를 시키면 오늘 것이 바뀐다."

| 구성 | 날짜 정확도 | 대상 지목 | 결과 |
|---|---|---|---|
| `day` enum + `[id]` 실림 | 2/3 | `/done 134` 거부 | 0/3 |
| **enum 품** + id 수용 | **3/3** | `/done 90` (첫 id) | 0/3 |
| id 제거 | 3/3 | `/done 1` (지어냄) | 0/3 |
| 제목 우선 | 3/3 | `/done 예시 일정` | 0/3 |

**날짜는 enum 을 풀어서 해결됐다.** 원인이 내 수정이었다 — 새벽 경계(06:00)에
모델이 날짜를 잘못 계산하는 것을 막으려고 `day` 를 enum 으로 묶었는데,
그러자 **낱말 중에서만 고를 수 있어 기본값(오늘)으로 떨어졌다.**
`get_plans` 는 자유 문자열이라 `2026-08-23` 을 매번 맞히고 있었다 —
**같은 턴 안에서 두 툴이 다른 날짜를 썼다.**

> 하루 6시간짜리 위험을 막으려고 하루 종일을 망친 교환이었다.
> 두 툴의 `day` 를 같은 모양으로 되돌리는 것이 답이었다.

### 대상 지목은 8B 한계에 가깝다 — 그러나 실사용은 된다

네 구성 모두 채점에서 0/3 이었고, 실패 모양이 같다: **목록의 첫 항목을 고른다.**
형식(번호·id·제목)을 세 번 바꿔도 그대로였다. 게다가 **자신 있게 틀린 것을
보고한다** — "✅ 예시 일정가 완료 처리되었습니다 🎉".

★ **그런데 사용자가 실기기에서 시험하니 정확히 동작했다** (DB 로 확인):

```
"신청 작업 계획 완료로 변경해줘"    → 08-24 신청 작업 done  ✓
"어제 미팅 계획도 완료처리 해줘"   → 08-23 미팅 done      ✓
```

채점 문장이 **실제보다 어려웠던 것**이다. 실패 데이터를 만들려고 문장을 깎다가
사람이 안 쓰는 표현이 됐다. → 케이스를 실사용 문장으로 바꿨다.

**이 세션에서 채점 관련으로 세 번 틀렸다:**

1. 오염된 상태로 재서 **가짜 3/3** (내가 손으로 done 을 만들어 둔 채 측정)
2. 제목을 줘서 **버그가 재현 안 됨** (제목이 모델에게 닻이 된다)
3. 실제보다 **어려운 문장**으로 재서 0/3 (실사용은 통과)

→ 채점기에 **시도 전 상태 복원**을 넣고, 복원 대상이 없으면 **시끄럽게 경고**한다.
조용히 넘어가면 또 가짜 통과가 나온다.
