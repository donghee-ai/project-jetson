# phone — 폰(LT Phone) 쪽 작업의 인수인계 문서

폰 워처를 만들고 고치는 일은 **윈도우 PC 앞에서** 한다 (안드로이드 빌드·`adb`·실기기).
그쪽 세션이 쌓아 온 문서를 여기 둔다.

## 왜 저장소에 넣었나 (2026-09-05)

**사본이 그 PC 한 곳뿐이었다.** 코드는 [`donghee-ai/LT-Phone`](https://github.com/donghee-ai/LT-Phone)과 이 저장소에 다 있지만,
*왜 그렇게 했나*는 그 폴더에만 있었다 — 08-21부터 쌓은 것이 전부 백업 없이 있었다.

두 번째 이유는 **채널이 한쪽으로만 열려 있었다**는 것이다. [`../for_window/`](../for_window/)
는 젯슨 → 윈도우 방향인데 반대가 없었다. 09-04 에 그게 실제로 비쌌다: 프라이빗 거르기가
길이 0 이벤트를 지우던 버그는 **PC 창 워처도 같이 새게 하고 있었는데**, 젯슨 쪽 세션은
폰 쪽 세션이 무엇을 보고 있는지 읽을 방법이 없었다
([HISTORY](../life-trainer/HISTORY/2026-09-04-the-clip-erased-what-it-could-not-cut.md)).

★ [`../for_window/`](../for_window/) 와 헷갈리지 않게: 저기는 **"윈도우 앞에서만 할 수
있는 일" 목록**이고 한 파일에 한 작업이다. 여기는 **문서**다. 새 일감은 저기로 간다.

## ★ 정본은 아직 윈도우 PC 다

작업은 그 PC 의 `c:\jetsonapk\` 에서 하고, 여기 있는 것은 **세션 끝에 올린 사본**이다.
같은 문서가 두 곳에 있으면 어긋난다 — 이 저장소가 네 번 겪은 실패가 정확히 그것이다.
그래서 규칙을 하나만 둔다:

> **고치는 곳은 항상 `c:\jetsonapk\`. 여기는 세션 끝에 통째로 덮어쓴다.**
> 여기서 직접 고치지 않는다. 고쳐야 하면 PC 로 내려서 고치고 다시 올린다.

마지막 갱신은 각 파일 맨 위의 날짜를 본다.

## 여기 **안** 들어간 것

- `keys/` — 서명 키·ingest 시크릿. **저장소에 안 올린다** (`.gitignore` 가 `*` 로 막는다).
  잃으면 앱을 영원히 업데이트 못 한다. 오프라인 사본은 사람이 따로 들고 있다
- `LT-Phone.apk` (180MB) · `aw-bucket-export.json` · 타임라인 PNG — 산출물이라 다시 만든다
- `platform-tools/` — 안드로이드 SDK 배포본
