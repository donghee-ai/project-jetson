## 1. ★ 툴 콜링 — 에이전트 적합성 (가장 결정적)

측정: [`measure/tools/tool-bench.py`](../tools/tool-bench.py). 6케이스 중 2개는
**"툴을 부르지 말아야" 정답**(과잉 호출 검증).

| 케이스 | Qwen3-8B | Qwen3-30B-A3B | EXAONE 3.5 |
|---|---|---|---|
| 단일 호출 | ✅ | ❌ | ❌ |
| 병렬 2건 | ✅ | ✅ | ❌ |
| 인자 3개 | ✅ | ✅ | ❌ |
| 복합 호출 (2단계) | ✅ | ❌ | ❌ |
| ★ 툴 불필요 | ✅ | ✅ | ✅ |
| ★ 모호한 요청 | ✅ | ✅ | ✅ |
| **합계** | **6/6** | **4/6** | **미지원** ※ |

### 실패 양상

**EXAONE 3.5 7.8B — 툴을 아예 인식하지 못한다.**
```
요청: "서울 날씨 알려줘"
응답: "현재 실시간 날씨 정보를 제공하지는 못하지만, 서울의 일반적인 날씨 패턴을…"
```
**원인이 확정됐다 — 모델 능력이 아니다.** 채팅 템플릿에 `tools` 렌더링 코드가 없어
llama.cpp 가 툴 정의를 조용히 버렸다. **모델은 툴이 존재하는지도 몰랐다.**

```
EXAONE   chat_template    339자  →  tools 블록 없음
Qwen3-8B chat_template  4,100자  →  {%- if tools %} 존재
```

※ 통과한 2건은 *"툴을 부르지 말아야 정답"* 인 항목이라 **못 불러서 자동 통과**한 것이다.
실질 점수는 **0/4** 다. **에이전트 용도로는 사용 불가** — 다만 이건 스펙 미지원이지
능력 부족이 아니다.

**Qwen3-30B-A3B IQ2_M — 불규칙하다.**
```
요청: "서울 날씨 알려줘"
응답: "서울의 현재 날씨는 다음과 같습니다. 날씨를 확인해 보세요!"  ← 툴 미호출, 환각
```
가장 단순한 단일 호출에 실패하면서 병렬 2건·인자 3건은 통과했다.
복합 호출에서는 첫 단계(`get_weather`)만 부르고 두 번째(`send_email`)를 빠뜨렸다.

> **불규칙성이 일관된 실패보다 나쁘다.** 에이전트 루프는 툴 호출이 예측 가능해야
> 성립한다. 10회 중 7회만 성공하면 다단계 작업의 성공률은 급격히 무너진다.

**Qwen3-8B Q4_K_M — 전 케이스 통과.** 과잉 호출도 없었다.

| 깊이(토큰) | Qwen3-8B | Qwen3-30B-A3B | 깊이(토큰) | EXAONE 3.5 |
|---|---|---|---|---|
| 463 | 10.69 | **13.29** | 384 | 11.22 |
| 1,652 | 10.16 | **12.10** | 1,344 | 10.78 |

| **저하폭** | **−55.7%** | **−70.1%** | | **−48.7%** |

### 교차점: 약 9,600 토큰

깊이 9,603에서 8B(7.80)가 30B-A3B(7.76)를 추월한다.
**얕으면 30B, 깊으면 8B**가 빠르다. 예측했던 KV 헤드 수 역전이 실제로 확인됐다.

| | KV 헤드 | 레이어 | 토큰당 KV (q8_0) |
|---|---|---|---|
| Qwen3-8B | 8 | 36 | ~72 KB |
| Qwen3-30B-A3B | 4 | 48 | ~48 KB |

> KV 캐시는 30B가 가볍지만, **활성 가중치(3.7~4.2 GB)가 8B(4.68 GB)와 비슷한데
> MoE 라우팅 오버헤드가 더해져** 깊이가 커질수록 불리해진다.

### EXAONE이 전 구간 최고 속도

같은 깊이로 보정하면 EXAONE이 셋 중 가장 빠르다. 저하폭도 −48.7%로 가장 완만하다.

## 3. ★ 한국어 토큰 효율 — EXAONE 19% 우위

**동일한 문서 80개**를 각 모델의 토크나이저로 처리한 결과:

| 모델 | 토큰 수 | 상대 |
|---|---|---|
| Qwen3 (8B / 30B 공통) | 31,901 | 기준 |
| **EXAONE 3.5** | **25,817** | **−19%** |

한국어 특화 학습의 효과가 토크나이저에 직접 나타난다. 이는 두 가지로 복리 작용한다.

1. **같은 컨텍스트에 19% 더 많은 내용**이 들어간다
2. **같은 내용을 생성하는 데 19% 적은 토큰**이면 된다

### 한국어 실효 처리량 환산

문서 80개(동일 내용) 기준:

| 모델 | 깊이 | tok/s | **한국어 실효** |
|---|---|---|---|
| Qwen3-8B | 31,901 | 4.74 | 4.74 |
| Qwen3-30B-A3B | 31,901 | 3.97 | 3.97 |
| **EXAONE 3.5** | 25,817 | 5.76 | **≈7.1** (토큰 효율 보정) |

**한국어 장문 작업에서 EXAONE이 8B 대비 약 50%, 30B 대비 약 80% 빠르다.**

## 8. 용도별 최종 권장

### 에이전트 (Open WebUI · 툴 사용 · 다단계 작업)
**→ Qwen3-8B Q4_K_M**

툴 콜링 6/6은 대체 불가다. 30B의 불규칙한 툴 호출은 에이전트 루프를 깨뜨린다.
메모리 여유 6.7 GB로 프런트엔드를 같은 기기에 올릴 수도 있다.

### 한국어 문서 파이프라인 (grant-radar 유형)
**→ EXAONE 3.5 7.8B (개인용) / Qwen3-8B (사업화)**

EXAONE은 토큰 19% 절약 + 전 구간 최고 속도로 압도적이다. 다만 **라이선스가 `other`**
이므로 사업화하려면 Qwen3-8B로 가야 한다. 툴 콜링이 필요 없는 순수 추출 작업이면
EXAONE의 이점이 크다.

### 짧은 대화 (~9K 미만)
**→ Qwen3-30B-A3B IQ2_M**

교차점 이전 구간에서는 가장 빠르고, 30B급 지식을 갖는다.
단 메모리 여유가 2.4 GB뿐이라 다른 서비스와 공존이 어렵다.

## 9. 이전 결론의 정정 이력

| 시점 | 결론 | 정정 사유 |

| 초기 | 8B 12~18 tok/s 예상 | 사양 대역폭(102.4) 사용 → 실측 60 GB/s로 재계산 |
