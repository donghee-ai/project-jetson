## 0. 결론 먼저

1. **ASR·TTS는 만들 게 없다.** 52k~14k 스타 프로젝트가 완성형으로 널려 있다. **조립만 한다.**
2. **★ LLM 통역 지연을 실측했다 — 문장당 1.2~1.5초.** 착수 전 추정(4~5초)은 틀렸다.
   문장 하나가 12~16토큰밖에 안 되기 때문이다. **실시간 통역이 이 기기에서 성립한다.**
3. **★ 그런데 Qwen3-8B의 한국어 출력에서 한자가 튀어나왔다.** 품질이 지연보다 큰 문제다.
4. 진짜 공백은 기술이 아니라 **언어**다 — 한국어 음성 도구 생태계는 사실상 비어 있다.

## 3. ★ 실측 — LLM 통역 지연 (2026-08-15, 본 기기)

조건: Qwen3-8B Q4_K_M / llama-server (`-ngl 99 -c 40960 -fa on -ctk/-ctv q8_0`, thinking off) / MAXN
방법: 짧은 문장 5개 × 양방향, 스트리밍(TTFT)과 비스트리밍(완료) 각각 측정

| 방향 | TTFT | 완료 | 출력 토큰 | 생성 속도 |
|---|---|---|---|---|
| **한 → 영** | **0.20 s** | **1.19 s** | 12.6 | 10.6 tok/s |
| **영 → 한** | **0.20 s** | **1.51 s** | 16.2 | 10.7 tok/s |

### 3-1. 추정이 틀렸다 — 통역은 짧다

착수 전 "문장당 50토큰 ÷ 11 tok/s = 4.5초, 실시간 불가"로 계산했으나,
**실제 문장 번역 출력은 12~16토큰**이었다. 통역은 창작이 아니라 대응이므로 출력이 짧다.

```
LLM 통역 = 문장당 1.2~1.5초  →  실시간 파이프라인에 들어간다
```

### 3-2. 한국어 출력이 29% 더 길다 — 실측 재확인

영→한 16.2 토큰 vs 한→영 12.6 토큰 = **+29%**.
[llm-models.md](llm-models.md)의 한국어 토크나이저 비효율이 **번역 지연에 그대로 전가**된다.
한국어를 *만들어내는* 방향이 항상 더 느리다.

### 3-3. ⚠️ 진짜 문제는 지연이 아니라 품질이었다

| 원문 | Qwen3-8B 출력 | 문제 |
|---|---|---|
| back hurts → | 내 등이 아**所以** 의사에게 보고해야 합니다 | ★ **중국어 토큰 혼입** |
| helmet → | **모자** 없이는 작업 구역에 | 안전모 오역 (산업 현장에서 치명적) |
| The machine → | **머신**은 어제부터 | 부자연스러운 음차 |
| emergency exit → | **긴급 출구** | 비상구가 자연스러움 |

**Qwen3-8B는 한국어를 생성하는 쪽에서 무너진다.** 한자가 섞여 나오는 것은 사용 불가 수준의 결함이다.

| 대응 후보 | 근거 |
|---|---|
| **EXAONE 3.5 7.8B** | 한국어 토큰 19% 절약 + 전 구간 최고 속도. **툴콜링 불필요한 순수 번역에는 최적** |
| 전용 MT 모델 (NLLB-200 600M 등) | 훨씬 작고 빠름. 문맥은 약하나 오염 없음 |
| 용어 사전 강제 (안전모/비상구) | 현장 어휘 고정 — LLM보다 확실 |

> **다음 측정: 동일 문장으로 EXAONE 3.5 재측정.** 현재 서버가 가동 중이라 교체하지 않았다.

## 4. 전체 파이프라인 지연 예산

사람 동시통역사의 EVS(ear-voice span)는 **2~4초**다. 이 기준으로 본다.

| 단계 | 예상 | 근거 |
|---|---|---|
| VAD / KWS | ~0.05 s | CPU, 무시 가능 |
| **발화 종료 감지(endpointing)** | **0.3~0.7 s** | ★ 실제로 체감 지연의 큰 축. 스트리밍 ASR이면 단축 |
| ASR (3초 발화) | 0.2~0.5 s | **미측정** — whisper_trt RTF 확인 필요 |
| **MT (LLM)** | **1.2~1.5 s** | **★ 실측** |
| TTS (3초 음성) | 0.1~0.3 s | piper/kokoro RTF 기준 추정 |
| **합계** | **≈ 1.9~3.0 s** | **사람 통역사 대역에 들어감** |

### ⚠️ 단, 세 모델이 GPU와 60 GB/s를 나눠 쓴다

ASR·LLM·TTS는 **순차 실행**이므로 지연이 더해지고, 화자가 둘이면 큐가 생긴다.
[이 저장소의 핵심 발견](performance.md)이 여기서도 그대로 적용된다 —
**연산이 아니라 대역폭이 천장**이므로, 동시 실행 시 각 단계가 얼마나 느려지는지 측정해야 한다.
(→ [project-candidates.md](../docs/archive/project-candidates.md) 후보 G와 동일한 미지수)

| 구성요소 | 크기 |
|---|---|
| ASR (whisper-small / SenseVoice-small) | ~0.5 GB |
| MT/LLM (EXAONE 3.5 Q4 또는 Qwen3-8B Q4) | 4.7~4.9 GB |
| TTS (piper / kokoro 82M) | ~0.1 GB |
| VAD + KWS | ~0.05 GB |

| **합계** | **≈ 8 GB / 13.4 GB** ✅ |

전용 MT 모델(0.6 GB)로 가면 LLM 에이전트를 별도로 띄울 여유까지 생긴다.

## 6. 제품 후보 3개

### H1. ★ 오프라인 현장 통역기 — 가장 유력

**인터넷이 없거나 클라우드가 금지된 곳에서 쓰는 한국어 양방향 통역 상자.**

| 현장 | 왜 클라우드가 안 되나 |
|---|---|
| **제조·건설 (외국인 노동자)** | 공장 내부망 격리, 통신 음영, 안전 지시는 지연 불가 |
| **병원·보건소** | 환자 발화는 민감정보. 클라우드 전송 자체가 규제 대상 |
| 선박·도서·재난현장 | 물리적으로 인터넷이 없다 |

베트남어판(12★)의 존재가 수요를 증명하고, **한국어판은 없다.**
차별화는 기술이 아니라 **한국어 + 현장 어휘 사전 + 실측 지연 보증**이다.

### H2. 완전 로컬 한국어 음성 에이전트

```
한국어 웨이크워드 → ASR → Qwen3-8B (툴콜링 6/6 ★검증됨) → Home Assistant 제어 → TTS
```

[레퍼런스 조사 §7](reference-survey.md)에서 "난이도 낮음, 사례 적음"으로 분류된 항목.
`wyoming`·`homeassistant-core` 패키지가 젯슨에 이미 있고, **툴 콜링 6/6은 이미 우리가 측정해 확인했다.**
약점: 영어권에는 HA Assist 생태계가 이미 크다. **차별점은 한국어뿐.**

### H3. TTS로 KWS를 가르치기 — 가장 신박한 조각

한국어 웨이크워드("하이 젯슨") 학습 데이터가 없다. 그런데 **TTS가 있다.**

```
TTS(선생) ─ 수천 개 변형 음성 합성 (화자·속도·잡음·거리)
              ↓
        소형 KWS 모델(학생) 학습 → CPU/DLA에서 상시 구동
```

[Understudy](../docs/archive/project-proposal.md)의 선생-학생 구조가 **음성에서 그대로 재현된다.**
사람이 자기 목소리를 100번 녹음할 필요가 없어진다. 단독 제품은 아니고 H1·H2의 부품.

## 7. 정직한 평가 — 이 방향의 약점

| | |
|---|---|
| **젯슨 강점 노출이 약하다** | NVDEC·DLA·OFA·VIC를 하나도 안 쓴다. GPU와 CPU만 쓴다 — **미니PC로도 된다** |
| 반론 | 24시간 저전력 상시 대기(4.6 W), 오프라인 필수성, ASR+LLM+TTS **동시 상주**(16 GB 통합 메모리)는 살아 있다 |
| 기술 신규성이 낮다 | 조립이 대부분. 새로 만드는 것은 한국어 레이어와 오케스트레이션 |
| **대신 실사용 가치는 최고** | 후보 7개 중 "매일 쓸 물건"에 가장 가깝다 |

## 8. Phase 0 — 마이크 없이 오늘 확인할 것

## 9. 미확인 항목

- `whisper_trt` 컨테이너가 **L4T 36.5에서 빌드되는지** (이미지는 36.3 기준, 2024-05)
- Riva가 **JetPack 6.2에서 지원되는지** (문서는 JP5 표기)
- `piper1-tts`의 **GPL**이 사업화에 미치는 영향 — 대안 TTS 필요 여부
- 한국어 스트리밍 ASR 모델의 실재 여부 (Whisper는 비스트리밍이 기본)
- KWS 생태계 재조사 — 이번 데이터셋의 2건은 검색어 편향일 가능성이 높다
