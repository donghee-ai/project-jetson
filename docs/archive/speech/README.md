# archive/speech/ — 한국어 음성 에이전트 (접음)

> **2026-08-28: 본류에서 뺐다.** ASR 을 쓰지 않기로 했다.
> 여기 있는 것은 **접기 전에 실제로 잰 기록**이고, 결론 하나는 지금도 코드에서 돌고 있다.

## 무엇을 쟀나

같은 하드웨어에서 **완전 로컬 한국어 음성 에이전트가 성립하는지**를 마이크 없이 전 구간
측정했다. TTS 로 명령 음성을 합성해 ASR 에 먹이는 방식이라 **상한선**이다.

| 구간 | 실측 | 판정 |
|---|---|---|
| ASR (SenseVoice-Small int8, CPU 8스레드) | **RTF 0.042** — 1.3초 음성을 0.12초에 | ✅ |
| TTS (Supertonic-3 int8, CPU) | RTF 0.57~0.80 | ⚠️ 응답이 길면 부담 |
| LLM 툴콜 (Qwen3-4B Q4) | **2.45초** | ❌ **지연의 95%** |
| 핫패스 규칙 라우터 | **0.19 ms** | ✅ LLM 대비 약 **6,500배** |

**결론: 성립한다. 단 LLM 을 매번 부르면 안 된다.**
웨이크워드 → 핫패스 규칙(0.2ms) → LLM(2.5초, 폴백만) 의 3단 게이트로 갔다.

## ★ 살아남은 결론 하나

**그 3단 게이트 구조가 텍스트 쪽으로 옮겨가 지금도 돌고 있다** —
`life-trainer/lifetrainer/llm/trigger.py` 가 규칙으로 툴을 고르고 LLM 은 폴백만 한다.
그 모듈 docstring 이 [`voice-agent-plan.md`](voice-agent-plan.md) §2-5 를 인용한다.

**음성에서 먼저 재고 텍스트에서 재사용한 셈**이고, 그게 이 트랙이 남긴 값이다.

## 왜 접었나

기술이 막아서가 아니다. 위 표대로 **성립했다.**
ASR 을 쓸 계획이 없어졌을 뿐이다.

> 조사 당시 적어둔 것: *"진짜 공백은 기술이 아니라 언어다. ASR·TTS 는 52k~14k 스타
> 프로젝트가 완성형으로 널려 있어 조립만 하면 된다. **한국어 음성 도구 생태계가
> 사실상 비어 있는 것**이 문제다."*

## 지금 이 폴더의 스크립트는 실행되지 않는다

`refs/models/speech/` 가 **없다.** 6개 전부 그 경로의 가중치를 요구한다
(SenseVoice · vits-mimic3 · Supertonic-3 · silero_vad). 되살리려면 먼저 받아야 한다.

| 스크립트 | 무엇을 쟀나 |
|---|---|
| `speech-bench.py` | TTS · ASR · 엔드투엔드 (합성음) |
| `asr-source-test.py` | ASR 실패 원인 분리 — 인식기인가 합성음인가 |
| `voice-e2e-bench.py` | 음성 에이전트 E2E, **슬롯 정확도** 기준 |
| `mic-live-bench.py` | 실마이크 입력 (잡음·거리·에코 포함) |
| `hotpath-router.py` | 규칙 라우터로 LLM 을 빼면 얼마나 빨라지나 (**약 6,500배**) |
| `ha-tool-bench.py` | 구어체 스마트홈 툴 콜링 정확도 |

원본 wav 은 `measure/results/speech/` 에 있고 **git 에 안 올라간다** —
`measure/results/speech/live/` 는 **사람 목소리 실녹음**이라 개인 데이터다.

## 여기서 나온 함정 둘

- **합성음 인식률이 무너져도 ASR 탓이 아닐 수 있다** — 같은 인식기가 원어민 녹음은
  완벽히 받아썼다. 원인을 가르는 실험을 따로 설계해야 했다
- **문자열 완전일치로 음성을 채점하면 정답이 오답이 된다** — `"이십사도" → "24도"` 는
  ASR 의 숫자 정규화(ITN) 결과라 의미는 정확하다. 채점 기준을 **슬롯 정확도**로 바꿨다
