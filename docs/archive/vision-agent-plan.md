## 1. 왜 이 프로젝트인가

### 1-1. 유일하게 하드웨어를 제대로 쓰는 안

현재 젯슨의 연산 엔진 8종 중 **GPU 하나만** 돌고 있다.

| 엔진 | 클럭 | 현재 | 이 프로젝트에서 |
|---|---|---|---|
| NVDEC | 857 MHz | 유휴 | **Frigate 영상 디코딩** |
| NVENC | 793 MHz | 유휴 | 클립 인코딩 |
| NVJPG ×2 | 729 MHz | 유휴 | 스냅샷 처리 |
| VIC | 729 MHz | 유휴 | 리사이즈·색공간 변환 |
| OFA | 780 MHz | 유휴 | 모션 추적 |
| DLA ×2 | — | 유휴 | **객체 검출 (GPU와 동시)** |
| GPU | 918 MHz | LLM | **VLM 캡션** |

**DLA가 검출을 도는 동안 GPU가 VLM을 돌리는 구조**가 가능하다.
이것이 dGPU 서버나 클라우드가 구조적으로 못 하는 지점이다.

### 1-2. 대역폭 경제학

```
1080p30 카메라 1대 = 약 54 GB/일 (월 1.6 TB)
  클라우드로 전송   → 업로드 비용 + 클라우드 GPU 비용
  로컬 처리 후 이벤트만 전송 (수 KB) → 사실상 무료
```

텍스트는 클라우드가 이기고, **영상은 엣지가 이긴다.**

### 1-3. 빈틈은 "위층"에 있다

[레퍼런스 조사](../../research/reference-survey.md)에서 확인:

```
Frigate (35,105★ MIT)  →  "사람 감지됨" 바운딩 박스까지  ← 이미 완성형
                                   ↓
                        ★ 여기가 비어 있다 ★
                                   ↓
VLM 레이어             →  "택배기사가 상자를 놓고 감"
                          자연어 검색 · 오탐 필터 · 요약
```

개념 구현은 있으나(`yiliu-li/Visual-Agentic-Memory` 15★,
`mohamed-abo-taha/local-vision-agent` 0★) **아무도 제대로 만들지 않았다.**

> ⚠️ **Frigate를 다시 만들지 말 것.** 객체 검출·녹화·타임라인·웹UI·HA연동은
> 이미 성숙하다. 우리가 만들 것은 그 위 한 층뿐이다.

## 2. 확인된 전제 조건

| 항목 | 상태 | 비고 |
|---|---|---|
| **llama.cpp 멀티모달** | ✅ **빌드 완료** | `llama-mtmd-cli`, `llama-qwen2vl-cli`, `libmtmd.so`, `--mmproj` 플래그 |
| Frigate | ✅ 35,105★ MIT, 2026-08-14 | TensorRT 검출기 지원 |
| **Docker** | ❌ **미설치** | Frigate 전제조건. `sudo apt install docker.io` |
| 카메라 | ❌ **미보유** | `/dev/media0` 존재하나 미연결. USB3.1 허브 비어 있음 |
| 메모리 | ✅ 13.6 GB 여유 | 현재 llama-server 중지 상태 |

**llama.cpp에 mtmd가 이미 들어있는 것이 결정적이다.** VLM 실행에 추가 빌드가 필요 없다.

## 3. ★ 메모리 예산 — 이 프로젝트의 핵심 제약

13.4 GB 안에 Frigate와 VLM이 **동시에** 들어가야 한다.

### 3-1. 소요 추정

| 구성요소 | 예상 | 비고 |
|---|---|---|
| Frigate (ffmpeg + 검출기 + 웹) | 1.5~2.5 GB | 카메라 수에 비례 |
| 검출 모델 (YOLO TensorRT) | ~0.3 GB | DLA로 보내면 GPU 메모리 절약 |
| **VLM** | **1.5~5.5 GB** | 모델 선택이 좌우 |
| KV 캐시 + 컴퓨트 버퍼 | ~1 GB | |
| OS + 여유 | ~1.5 GB | |

### 3-2. VLM 후보 — 크기가 전부다

| 모델 | Q4 크기 | 판정 |
|---|---|---|
| **SmolVLM2 2.2B** | ~1.5 GB | ✅ **1순위** — Frigate와 여유롭게 공존 |
| moondream2 (1.8B) | ~1.5 GB | ✅ 엣지 설계 |
| Gemma 3 4B (멀티모달) | ~3 GB | ⚠️ 가능 |
| Qwen2.5-VL 7B | ~5.5 GB | ⚠️ 빠듯. Frigate와 합치면 8GB+ |

**작은 VLM으로 시작할 것.** 캡션 생성은 창작이 아니라 관찰 기술이라
2B급으로도 충분할 가능성이 높다. 부족하면 그때 키운다.

### 3-3. ⚠️ 텍스트 LLM을 따로 띄우지 말 것

```
❌ VLM 5.5GB + 텍스트 LLM 4.7GB + Frigate 2GB = 12.2GB  → 위험
✅ 멀티모달 단일 모델 (텍스트도 처리) + Frigate         → 안전
```

Qwen2.5-VL 같은 모델은 텍스트 전용 작업도 처리한다.
**하나로 통합**해서 메모리를 아낀다.

## 4. 아키텍처

```
┌─ IP 카메라 (RTSP) ─────────────────────────────────┐
│                                                     │
▼                                                     │
Frigate                                               │
├─ NVDEC 하드웨어 디코딩                               │
├─ 모션 감지 (CPU, 저비용)                             │
├─ 객체 검출 (TensorRT / DLA) → "person"               │
├─ 녹화 · 타임라인 · 웹UI                              │
└─ 이벤트 발행 (MQTT / HTTP API)                       │
     ↓ 스냅샷 + 메타데이터
┌─ VLM 워커 (신규 개발) ──────────────────────────────┐
│  ① 스냅샷 수신 (Frigate API)                        │
│  ② VLM 캡션 — llama-mtmd                            │
│     "택배기사로 보이는 사람이 상자를 놓고 떠남"        │
│  ③ 구조화 추출 (JSON)                                │
│     {who, action, objects[], risk, time}            │
│  ④ SQLite 저장 + 임베딩 색인                         │
│  ⑤ 알림 판정 — 무시 / 통지                           │
└─────────────────────────────────────────────────────┘
     ↓
┌─ 조회 레이어 ───────────────────────────────────────┐
│  "어제 저녁에 누가 왔었어?"  → 자연어 검색            │
│  일일 브리핑                → "택배 2건, 미상 1건"    │
└─────────────────────────────────────────────────────┘
```

### 핵심 설계 원칙 — 이벤트 트리거 추론

**VLM을 상시 돌리지 말 것.** 30fps 전 프레임에 VLM을 돌리는 것은 불가능하다.

```
상시 (저비용)   모션 감지 → 객체 검출 (DLA)
이벤트 시에만   VLM 캡션 (GPU)
```

측정된 생성 속도가 [11~14 tok/s](../../research/performance.md)이므로
**캡션 100토큰 = 약 8~10초**다. 이벤트가 그보다 자주 발생하면 큐가 쌓인다.

| 환경 | 일일 이벤트 | 처리 여유 |
|---|---|---|
| 가정집 현관 | 50~200건 | ✅ 충분 (시간당 360건 처리 가능) |
| 상가·주차장 | 1,000건+ | ⚠️ 필터링 선행 필요 |

## 5. 단계별 계획

### Phase 0 — 하드웨어 없이 검증 (비용 0)

**카메라를 사기 전에 파이프라인이 도는지부터 확인한다.**

- [ ] `sudo apt install docker.io docker-compose-v2` + 사용자 docker 그룹 추가
- [ ] 영상 파일로 Frigate 구동 (RTSP 대신 파일 입력)
- [ ] `tegrastats`로 **NVDEC 사용률 > 0** 확인 ← 하드웨어 디코딩 검증
- [ ] SmolVLM2 2.2B 다운로드 → `llama-mtmd-cli`로 정지 이미지 캡션 테스트
- [ ] **캡션 1건당 소요 시간 실측** ← 이벤트 처리량 상한 결정

> Phase 0에서 "VLM 캡션이 쓸 만한가"가 판가름난다. 못 쓰겠으면 여기서 중단.

### Phase 1 — 카메라 연결

- [ ] 카메라 선정 (§6)
- [ ] Frigate 단독 운영 — 검출·녹화·웹UI
- [ ] 메모리 실측 → VLM 여유 확인
- [ ] 일일 이벤트 발생량 파악 ← VLM 부하 산정 근거

### Phase 2 — VLM 캡션 레이어

- [ ] Frigate 이벤트 구독 (MQTT 또는 API 폴링)
- [ ] 스냅샷 → VLM → 캡션 생성
- [ ] 구조화 출력 (JSON) — [Qwen3 툴콜링 6/6](../../research/llm-models.md) 검증됨
- [ ] SQLite 저장
- [ ] 실패·큐 적체 모니터링

### Phase 3 — 검색 · 필터

- [ ] 캡션 임베딩 → 자연어 검색
  - 메모리 절약 위해 [PageIndex(벡터리스)](../../research/reference-survey.md) 또는 zvec 검토
- [ ] 오탐 필터 — "고양이입니다, 무시" 판정
- [ ] 일일 브리핑 생성

### Phase 4 — 알림 · 통합

- [ ] 알림 (Telegram / ntfy / Home Assistant)
- [ ] `ha-mcp` 연동 검토 — LLM이 집 기기 제어

## 6. 하드웨어 선택

| 방식 | 비용 | 장단점 |
|---|---|---|
| **기존 IP캠 RTSP** | 0 | 있으면 최선. 배선 불필요 |
| USB 웹캠 | ~2만원 | 즉시 가능. **Bus 2 USB3.1 허브 비어 있음** |
| IP캠 신규 | 3~8만원 | 야간 IR·방수. 24/7 운영에 적합 |
| CSI 카메라 | 3~5만원 | 최저 지연. 리본 케이블·마운트 필요 |

**RTSP IP캠을 권장한다.** Frigate가 RTSP 기준으로 설계됐고, 야간 IR과 방수가
24시간 운영에 필요하다. USB 웹캠은 Phase 0~1 프로토타입용으로만.

## 7. 리스크

| 리스크 | 심각도 | 대응 |
|---|---|---|
| **메모리 부족** — Frigate + VLM | **높음** | 작은 VLM(2B)부터. 텍스트 LLM 별도 구동 금지 |
| VLM 캡션 품질 미달 | 높음 | **Phase 0에서 조기 검증.** 못 쓰면 중단 |
| 이벤트 큐 적체 | 중간 | 이벤트 필터링 선행. 처리량 상한 측정 |
| Frigate 젯슨 호환성 | 중간 | TensorRT 검출기 지원 확인됨. DLA 사용 가능 여부는 미검증 |
| 발열 — 디코딩+검출+VLM 동시 | 중간 | [thermal-test.sh](../../scripts/thermal-test.sh) 미실행 상태. **선행 필요** |
| 카메라 미보유 | 낮음 | Phase 0는 영상 파일로 가능 |

### 미검증 항목

- **DLA에서 Frigate 검출기 구동 가능 여부** — 가능하면 GPU를 VLM에 온전히 쓸 수 있다
- 젯슨에서 Frigate + VLM 동시 구동 실측 메모리
- VLM 캡션 품질 (한국어 출력 포함)
- 지속 부하 발열

## 9. 착수 조건

지금 당장 시작 가능한 것은 **Phase 0**뿐이며, 그것으로 충분하다.

```bash
# 1. Docker 설치
sudo apt install -y docker.io docker-compose-v2
sudo usermod -aG docker $USER && newgrp docker

# 2. 발열 선행 측정 (미실행 상태)
bash scripts/thermal-test.sh 300

# 3. VLM 단독 테스트 — 카메라 불필요
~/llama.cpp/build/bin/llama-mtmd-cli \
  -hf ggml-org/SmolVLM2-2.2B-Instruct-GGUF \
  --image <이미지> -p "이 장면에서 무슨 일이 일어나고 있는지 한국어로 설명해줘"
```

**3번이 이 프로젝트의 성패를 가장 빨리 알려준다.** 캡션이 쓸 만하지 않으면
나머지는 의미가 없다. 카메라 구매 전에 반드시 확인할 것.
