## 0. 왜 CCTV가 먼저 나왔나 — 그리고 왜 그게 전부가 아닌가

CCTV 계열이 1순위로 나온 이유는 단 하나, **영상이 젯슨의 8개 엔진을 전부 쓰는 유일한 워크로드**이기 때문이다.
하지만 그 대가로 **카메라 구매 + Frigate라는 거대한 기성품과의 경쟁**을 떠안는다.

아래는 검토한 7개 후보 전체다.

## 2. ★ 후보 B — 음향 이상 감지: 조사 데이터상 가장 빈 곳

### 2-1. 근거 — 704개 중 0건

수집한 704개 저장소를 재질의한 결과:

```
"anomaly|fault detect|defect"        → 1건 (그마저 Home Assistant 에이전트, 무관)
"acoustic|audio anomaly|vibration|
 predictive maintenance"             → 1건 (Microsoft 생물다양성 연구)
"audio|sound|speech" 전반            → 22건, 전부 TTS·STT·음성복제
```

**오디오 생태계는 "사람의 말"에만 몰려 있다.** 46k~14k 스타가 즐비하지만
전부 말을 글로 바꾸거나 말을 만드는 것이고, **말이 아닌 소리를 이해하는 것은 아무도 안 한다.**

> ⚠️ 단서: 이 조사는 LLM·에이전트·젯슨 중심 64개 검색어로 수집됐다.
> 0건이 생태계 공백인지 **검색어 편향**인지는 착수 전 별도 확인 필요
> (DCASE·MIMII 등 학술 벤치마크 커뮤니티는 별개로 존재할 가능성이 높다).

### 2-2. 무엇을 만드나

**정상 소리를 며칠 듣고 학습한 뒤, 달라진 소리를 잡아내고 LLM이 그것을 설명하는 장치.**

```
마이크 ─→ 상시 (CPU/DLA, 초저비용)
           ├─ 로그멜 스펙트로그램
           └─ 이상 점수 (오토인코더 재구성 오차 / 임베딩 거리)
                  │ 평소와 다름
                  ▼
        선생 (GPU) ─ 오디오 이벤트 분류 + LLM 맥락 판단
                     "새벽 3시, 3층 실외기에서 평소 없던 금속성 마찰음이 12분간"
                  │
                  ▼
        일일 브리핑 · 알림 · 시계열 기록 (SQLite)
```

**라벨이 필요 없다.** "정상"만 듣고 그 분포에서 벗어난 것을 찾는 자기지도 방식이라,
[Understudy](project-proposal.md)의 자가학습 구조를 그대로 물려받으면서 **사람 라벨링도, 선생의 환각 위험도 훨씬 작다.**

### 2-3. 왜 젯슨인가

| 강점 | 이 프로젝트에서 |
|---|---|
| **24시간 4.6 W** | 소리는 놓치면 끝이다. 상시 가동이 전제 조건 |
| **프라이버시** | 마이크는 카메라보다 민감하다. **대화가 섞여 들어온다** → 클라우드 전송 불가. 로컬 처리가 선택이 아니라 필수 |
| DLA + GPU 분리 | 상시 이상 점수(작은 모델)와 이벤트 시 LLM(큰 모델)이 서로를 방해하지 않음 |
| 다채널 | USB 마이크 여러 개 = 위치 추정. CPU 8코어로 감당 |
| **11 tok/s가 문제 없음** | 이상은 하루 몇 건이다. 실시간 생성 압박이 없다 |

카메라가 못 보는 것을 듣는다 — **벽 뒤, 어둠 속, 사각지대, 그리고 "고장 나기 전"의 소리.**

### 2-4. 적용처

| 대상 | 잡아내는 것 |
|---|---|
| 기계실·보일러·실외기·펌프 | 베어링 마모, 이상 진동, 캐비테이션 — **고장 전 며칠 전조** |
| 서버랙·공조 | 팬 이상, 알람음 |
| 집 | 유리 파손, 물 새는 소리, 알람, 아기 울음 |
| 축사·농장 | 가축 이상 발성 |

### 2-5. 하드웨어 · 비용

```
USB 마이크         1~2만원  (USB3.1 허브 비어 있음 — 오늘 꽂으면 됨)
접촉식 마이크/진동  선택     (기계 표면 직접 접촉 시 SNR 급상승)
카메라             불필요
```

### 2-6. 재사용할 오픈소스

`k2-fsa/sherpa-onnx`(14k, Apache-2.0 — VAD·오디오 처리) · YAMNet/PANNs/BEATs(오디오 이벤트 분류) ·
`jetson-containers/speech`(whisper_trt 등 aarch64 빌드 완비) · Frigate `audio-labelmap.txt`(이벤트 분류 라벨 참고) ·
이상탐지는 학술 표준(DCASE Task 2, MIMII 데이터셋)이 있어 **공개 데이터로 사전 검증 가능**

### 2-7. 리스크

| 리스크 | 대응 |
|---|---|
| **소리만으로 원인 규명이 되는가** | MIMII 등 공개 데이터로 **마이크 사기 전에** 검증 |
| 오탐 폭주 (환경 소음) | 시간대별 정상 분포를 따로 학습. 며칠 적응 기간 |
| 젯슨이 과잉 (Pi로도 됨) | **정당화 조건**: 다채널 + LLM 맥락 판단 + 야간 재학습을 한 대에서. 단채널 단순 감지라면 젯슨은 낭비다 |
| 프라이버시 (대화 녹음) | 원본 오디오 미저장, 스펙트로그램·점수만 보관하는 설계를 기본값으로 |

## 3. ★ 후보 C — 영상 아카이브 시맨틱 인덱서 (카메라 0원)

**이미 가지고 있는 영상 파일**(강의·회의 녹화·홈비디오·행사)을 로컬에서 전부 보고 검색 가능하게 만든다.

```
영상 파일 ─→ NVDEC 대량 디코딩 ─→ 장면 분할 ─→ 키프레임 VLM 캡션
                                              + STT(음성) ─→ 색인 ─→ 자연어 검색
```

| 왜 좋은가 | 설명 |
|---|---|
| **오늘 0원 착수** | 카메라도 마이크도 필요 없다. 파일만 있으면 됨 |
| **실측 제약과 완벽히 맞음** | 배치 작업이라 11 tok/s가 아무 문제 없다. 밤새 돌리면 됨 |
| 엔진 활용 | NVDEC·NVJPG·VIC 대량 사용 (CCTV와 같은 이유) |
| 비용 논리 | 100시간 영상 클라우드 VLM 처리 = 수십만원 / 젯슨 = 전기료 몇 천원 |
| 공백 | `NVIDIA-AI-Blueprints/video-search-and-summarization`(1.8k★)가 있으나 **데이터센터 GPU 전제.** 젯슨판은 없음 |

**약점**: 재미는 있으나 "매일 쓰는 물건"이 되기 어렵다(⑤ 3점). 개인 아카이브가 많은 사람에게만 가치가 있다.

## 4. 나머지 후보 — 왜 밀렸나

### D. 한국어 온프레미스 회의·상담 기록기

시장은 가장 확실하다(병원·법률·공공기관은 클라우드 전송 금지). EXAONE 한국어 토큰 19% 절약도 정확히 여기서 복리로 작동한다.
**그러나 젯슨의 비전 엔진을 하나도 쓰지 않는다.** 오디오+텍스트뿐이라 미니PC로도 된다.
경쟁도 심하다 — `meetily` 29k, `whisperX` 23k, `faster-whisper` 24k.
→ **"젯슨의 강점"이라는 기준에서 탈락.** 단, 후보 B의 부산물로 STT는 어차피 붙는다.

### E. 로봇 팔 + 로컬 VLA

젯슨의 정체성 그 자체다. 폐루프 제어는 지연 때문에 클라우드가 **구조적으로 불가능**하고,
`jetson-containers/physicalAI`에 `lerobot`·`openpi`·`vla`가 이미 패키징돼 있다.
**그러나** 팔 하드웨어 30~50만원, 조립·캘리브레이션 리스크, 그리고 이 프로젝트가 축적한 자산
(LLM 벤치마크·툴콜링·한국어)이 **거의 쓰이지 않는다.**
→ 하드웨어를 살 의향이 있고 "제조·물류 로봇"으로 갈 거라면 1순위가 바뀐다.

### F. WiFi/RF 무카메라 실내 감지

가장 신박하다. 카메라 없이 벽 너머 사람의 존재·움직임·호흡을 감지한다.
**이 저장소에 MT7601U 드라이버를 직접 손본 이력이 있다는 점이 특이 자산이다**(현재 USB에 연결돼 있음).
`ruvnet/RuView`(90k★, MIT)가 이 분야를 크게 키워놓은 상태.
**그러나** CSI 추출은 칩셋 의존성이 심하다(Intel 5300 / Atheros / ESP32-CSI / Nexmon).
MT7601U에서 CSI가 나오는지 **미확인** — 안 되면 ESP32(5천원)로 우회해야 하고, 그 순간 젯슨은 그냥 서버가 된다.
→ **선행 조사 필요**. 되면 판이 커지고, 안 되면 즉시 폐기.

### G. 인프라 — 대역폭 스케줄러 / 모델 라우터

이 저장소의 최대 발견("60 GB/s가 유일한 공유 자원", "모델은 용도별로 갈린다")을 그대로 도구화.
13.4 GB에서 3개 모델을 핫스왑하는 라우터 + 엔진 조합별 경합 매트릭스.
카메라 불필요, 오늘 착수 가능, 공개 가치 높음.
→ **제품이 아니라 도구.** 단독 프로젝트로는 약하고, **A/B/C 어느 것을 골라도 그 안에 필요하다.**

## 5. 권고

```
카메라를 살 의향 있음 + 가장 큰 그림      → A (Understudy)
하드웨어 2만원 + 생태계 공백 + 낮은 위험   → ★ B (음향 이상 감지)
오늘 0원으로 시작 + 실패해도 손실 없음     → C (영상 아카이브 인덱서)
```

**B가 가장 균형이 좋다.** 공백이 가장 크고(704개 중 0건), 2만원짜리 마이크면 되고,
"11 tok/s가 느리다"는 이 기기의 유일한 약점이 **아무 문제가 되지 않는** 워크로드다.
게다가 A의 선생-학생 자가학습 구조를 그대로 계승하므로, **B를 먼저 하고 나중에 A로 확장**하는 경로가 성립한다.

### 착수 전 30분짜리 검증 (마이크 구매 전)

MIMII / DCASE Task 2 공개 데이터를 받아 **정상 소리만으로 이상 탐지가 되는지** 먼저 확인한다.
여기서 안 되면 마이크를 사도 안 된다.
