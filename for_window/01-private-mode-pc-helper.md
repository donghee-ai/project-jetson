# 01 · 프라이빗 모드 PC 헬퍼 — **안 만들기로 했다 (2026-09-04)**

> 설계는 [`docs/private-mode-pc.md`](../life-trainer/docs/private-mode-pc.md) 에 남긴다.
> 되살릴 조건이 아래에 있다.

## 결정

**PC 는 웹 토글로 끝낸다.** 워처를 죽였다 살리는 헬퍼(`lt-private-agent.ps1`)를 안 만든다.
그래서 여기 있던 실측 3가지(워처 exe 인자 · aw-qt 부활 · 재개 시 backfill)도 안 잰다.

## 왜 — 폰과 PC 는 우리가 가진 권한이 다르다

| | 폰 | 노트북 |
|---|---|---|
| 수집기 | **우리가 만든 앱** (aw-android 포크, `donghee-ai/lt-phone`) | **순정 ActivityWatch** 를 그대로 붙였다 |
| 프라이빗을 넣는 법 | 앱 안에 타일·커서 건너뛰기를 **넣으면 된다** | 바깥에서 프로세스를 죽였다 살려야 한다 |

**폰은 고칠 수 있는 물건이고 PC 는 아니다.** 순정 프로그램을 밖에서 조종하는 스크립트는
그 프로그램이 업데이트될 때마다 조용히 깨진다 — 그리고 깨진 것이 *프라이버시가 안 걸린
상태*로 나타난다. 실패 방향이 나쁜 쪽이다.

## 안 만들어도 되는 이유 — 젯슨 DB 는 이미 안 샌다

저장 관문(`upsert_events`)이 프라이빗 구간과 겹치는 부분을 잘라낸다. **웹 토글은 지금도
완전히 동작한다.** 헬퍼가 더했을 것은 *PC 로컬 AW DB 에도 안 남게* 하는 것뿐이다.

| | 젯슨 DB | PC 로컬 AW DB |
|---|---|---|
| 지금 (웹 토글만) | ✅ 안 들어간다 | ⚠️ **남는다** |
| 헬퍼를 만들었다면 | ✅ | ✅ 애초에 안 생긴다 |

## ★ 손으로 끄는 길은 이미 있다 — aw-qt 트레이 (2026-09-04 추가)

**트레이 아이콘 → Modules 에 모듈별 체크박스가 있다.** `aw-watcher-window` ·
`aw-watcher-afk` 만 풀고 **`aw-server` 는 체크된 채 둔다.**

이게 헬퍼가 하려던 일이고, **aw-qt 자신의 지원되는 UI 다.** 그래서 위에 적어 뒀던
실측 3가지 중 둘이 그냥 없어진다:

| 원래 재려던 것 | 트레이로 끄면 |
|---|---|
| ① 워처 exe 경로·기동 인자 | **필요 없다** — 다시 켜는 것도 aw-qt 라 자기 설정 그대로다 |
| ② aw-qt 가 죽은 자식을 되살리나 | **필요 없다** — 되살리는 주체가 끄는 주체다 |
| ③ 재개 시 그 구간이 딸려오나 | **원리적으로 안 딸려온다** — aw-server 를 살려 두므로 로컬 큐 flush 가 없고, PC 워처는 폰과 달리 **실시간 관측**이라 뒤에 따라잡을 로그가 없다 |

★ ③ 이 이 설계의 전제였는데, 위험의 원인이던 *"aw-server 를 같이 멈추는 것"* 을
**모듈별 체크박스가 구조적으로 피하게 해 준다.**

### 그래도 웹 토글은 같이 켠다

트레이는 *PC 에 안 남게* 하고, 웹 토글은 젯슨이 그 시간을 **프라이빗으로 표시**하게 한다.
토글 없이 워처만 끄면 젯슨 격자에 **결측**으로 뜬다 — *안 잰 것*과 *일부러 안 잰 것*이
구분이 안 된다.

### ★ 새로 생기는 실패 모드 — 다시 켜는 걸 잊는다

헬퍼 설계에 `resume_at` 데드맨 스위치가 있던 이유가 이것이다. 트레이 토글에는 만료가 없다.

**그리고 지금 젯슨은 이걸 못 잡는다** — 2026-09-04 에 넣은 워처 침묵 검사는
`d.kind = 'phone'` 으로 폰만 본다. 다만 모양은 잘 맞는다: `aw-watcher-window` 만 풀고
`afk` 를 두면 *기기는 살아 있는데 이 워처만 뒤처진* 상태가 되고, 그게 그 검사의 판정
그대로다. **`WATCHED_PHONE_BUCKETS` 를 기기 종류까지 받게 넓히면 된다.**

## 그래서 받아들인 것 — 자동은 아니다

**사람이 트레이에서 끄면 애초에 안 생긴다.** 자동이 아닐 뿐이다 —
켜고 끄는 것을 사람이 기억해야 하고, 그래서 위의 "다시 켜는 걸 잊는다" 가 남는다.

트레이를 안 끄고 웹 토글만 쓴 구간은 PC 로컬에 남는다. 지우려면 젯슨에서 따로 쳐야 한다:

```bash
lt private purge --minutes 60 --aw
```

★ **웹 경로는 이걸 안 부른다.** `purge_aw_local` 을 부르는 곳은 `cli.py` 한 곳뿐이라,
웹에서 지우면 젯슨 DB 만 지워진다. `purge_aw` 기본값도 `false` 다 — **남의 기기의
DB 를 지우는 동작**이라 일부러 꺼 뒀다.

## 되살릴 조건

- PC 로컬 AW DB 가 **실제로 문제가 됐을 때** (누가 그 기기를 보게 되는 상황이 생기면)
- 또는 ActivityWatch 가 **정지/재개를 공식 API 로** 제공하게 되면 — 그때는 밖에서
  조종하는 게 아니라 지원되는 동작을 부르는 것이다
