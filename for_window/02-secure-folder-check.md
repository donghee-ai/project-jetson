# 02 · 폰 Secure Folder 가 수집을 막는지 — **끝났다 (2026-09-04)**

> 배경: [`android/docs/private-mode.md`](../life-trainer/android/docs/private-mode.md) §0
> 결과는 그 문서 §6 에 실렸다. 이 파일은 이정표만 남긴다.

## 결과 — 안 들어온다

**Secure Folder 안에서 쓴 앱은 `aw_event` 에 하나도 안 나온다. 그 시간은 자리비움으로 찍힌다.**

| | 결과 |
|---|---|
| Secure Folder 안의 앱이 나오나 | ✅ **아니오** |
| 나온다면 앱 이름이 뭐로 찍히나 | — (해당 없음) |

예상대로였다. 별도 안드로이드 프로필의 사용 통계는 메인 프로필 워처가 원리적으로 못 본다.
공식 문서가 `UsageStats` 를 콕 집어 말하지 않아서 잰 것인데, 말하지 않은 쪽도 같았다.

## 그래서 무엇이 없어졌나

**"특정 앱을 아예 안 보이게" 하는 앱 작업이 통째로 없어졌다.** 코드가 필요 없다 —
Secure Folder 에 넣으면 된다.

**타일(§2)은 그대로 남는다.** 대체 관계가 아니다 — Secure Folder 는 *"이 앱들은 아예"*,
타일은 *"지금 이 시간대를 통째로"* 다.

## ★ 같이 드러난 것 — 예상과 다른 절반

설계 문서는 *"어느 쪽이든 폰을 쓰고 있었다는 사실은 남는다"* 고 적어 뒀다.
unlock·AFK 워처가 화면 켜짐을 계속 기록한다는 전제였다. **그 절반은 지금 안 맞는다** —
Secure Folder 를 쓴 시간이 **자리비움과 구분이 안 된다.**

그런데 이 측정 구간에 **unlock 워처가 죽어 있었다**. 개인별 중단 시각과 길이는
공개본에서 제거했다.
`lt doctor` 의 워처 침묵 검사가 잡았고, 그래서 이 검사에 unlock 을 같이 넣었다.

**즉 "unlock 이 살아 있었다면 켜짐이 남았을까"는 아직 모른다.** 워처가 살아난 뒤
같은 것을 한 번 더 재야 갈린다. 실패와 미확인은 다르다 —
[`private-mode.md`](../life-trainer/android/docs/private-mode.md) §6 에 그렇게 적어 뒀다.
